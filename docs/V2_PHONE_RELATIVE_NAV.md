# V2 手机相对定位 + 无地图导航（锁人 / 世界 两线联合）

> 写于 2026-10-19。**机主原始设想的正式化**：像朋友之间开共享定位互相找，**不给用户发 tag、不用 UWB**。
> 存给 V2，demo 期不做。本文只定义问题、分工、接口与验收，**不含实现**。
>
> 一句话：**不需要绝对定位，也不需要地图——只需要一个共同原点（分离点）和两段位移。**

---

## 0. 来源与定位

- **机主原话（2026-10-19）**："我原本想的就是类似朋友间开共享定位然后找彼此的，没有什么 UWB。"
- 此前讨论中出现的两个提法已**撤回**，不得再作为方案引用：
  - ❌ "约定地点"（把等待点讲成了人的义务）——真实意图是**车自己走去找**；
  - ❌ "人举手机屏"（让用户为机器做识别仪式）——违背"解放双手"的产品定位。
- 本文的替代原则：**负担全在机器侧**。人只做一件事——正常走路。

## 1. 先划清"人不在视野"的三类（这决定要不要 UWB）

| 类 | 人在哪 | 谁能看见 | 解法 | UWB 有用吗 |
|---|---|---|---|---|
| **(a) 不在相机视野，但物理可见** | 侧后方 0.5–2m、刚擦身过去 | **雷达 360°**（腿簇） | 转头盯住 → 相机确认 → 跟上 | ❌ 多余 |
| **(b) 被墙/家具/门挡住** | 走廊另一头、冰箱后 | 都看不见（视线被挡） | 换视角（走过去）/ 停在可被找到处等 | ⚠️ 只能给粗方向，仍需移动 |
| **(c) 超出范围 / 别的区域** | 另一个房间、楼上、出了商场 | 什么都看不见 | 需定位+地图（V3） | ⚠️ 1–2m 精度、无身份，救不了 |

**结论：UWB 唯一不可替代的是 (c)，而 (c) 明确不在 V2 范围。** 本文解决 **(a) + (b)**。

## 1.5 重逢树（2026-10-19 文献调研后定稿，取代此前无引用的草图）

> 理论工具：**rendezvous search**（Alpern 1995；Alpern & Gal 1995/2003；Gal 1999；Pelc 2012）。
> HRI 证据：见 1.5.2。**本文的"树"以下面这些数字为准，不再拍脑袋。**

### 1.5.1 理论给的三条硬结论（都改变设计）

| 结论 | 数字 / 条件 | 出处 |
|---|---|---|
| 直线上两人、已知初始距离 D 的最优确定性策略 | **1.625D**；纯"一人不动"要 2D（差 ~19%） | Alpern & Gal, SIAM J. Control Optim. 1995, doi:10.1137/S0363012993260288 |
| **"全程完全静止"永远不是最优**（两人期望会合时间） | 定理；静止只在"对方 guaranteed to return"时才理性 | Gal, Oper. Res. 1999, doi:10.1287/opre.47.6.974 |
| **离散地点模型**（几个出口/门口）最优 | **一方留在原地 + 另一方按随机排列巡游** | Alpern & Gal, *Theory of Search Games and Rendezvous*, 2003, ch.16 |
| 距离未知时的搜索 | 扩张（doubling）搜索 **9-competitive**（确定性）/ 4.591（随机） | Ozsoyeller & Tokekar, arXiv:2101.05324 |
| 相同的确定性对称策略 | **不可能保证相遇** → 双方角色必须可区分（人 vs 车天然可区分） | Pelc, Networks 2012, doi:10.1002/net.21453 |
| 保证相遇的最小信息 | ② 一方可识别且静止 + 有界区域 + 覆盖搜索 + 互相能看见 | 同上综述 |

**三处直接改写**：
1. **"原地等"不是默认**——它只在"人一定会回来"的先验成立时才最优（门口/厕所这类）；
2. **有界搜索改成"扩张 + 回锚点"**（1→2→4m，每次回锚点），有竞争比保证，且天然缓解"对向错过"；
3. **巡游的那一方应该是车**（人的路径可预测，车的自由度高）——这正是"在几个必经出口之间巡游"的理论依据。

### 1.5.2 HRI 给的参数（有 N、有数字）

| 发现 | 数字 | 对设计的约束 | 出处 |
|---|---|---|---|
| 跟丢后人的**等待中位数** | **2.4s**（SD 3.79）；老年人更久；**84.6% 的人选"每 5s 播报"而非 10s** | **每 ~5s 播一次状态**；问题不是"它不在"，是"看不懂它在干嘛" | Olatunji et al., Paladyn 2020（N=35/20），doi:10.1515/pjbr-2020-0007 |
| **静默预算** | 停顿 1–20s：信任/依赖随等待下降，可容忍 **16–20s** | 静默超过 ~20s 必须播报或行动 | Maehigashi & Yamada, HRI Companion 2024, doi:10.1145/3610978.3640611 |
| **等待点选址** | 按人流：**≤0.4× 最大人流速度** 处等待；"预判拥挤"优于"最大曝光" | "可被发现但不挡路"有了可测判据 | Sakaki, HRI 2026, doi:10.1145/3757279.3785561；Satake, IROS 2015, doi:10.1109/IROS.2015.7353616；Kidokoro, HRI 2013 |
| 重逢是**共同完成**的 | 人需要"清晰的停止点 + 结束语"；人倾向**召唤机器人**而不是走过去；儿童在压力下**主动接触**机器人 | 提供一个"叫我过来"入口 + 一个可读的停车位；重逢要有结束动作 | Reyes-Cruz, HRI 2026, doi:10.1145/3757279.3785592；Pourmehr, HRI 2016；Nozawa, THRI 2026 |
| 期待管理 | 故障前预告 + 故障后修复（道歉/补偿）显著降低损害 | 分离前先说一句"我去那边等"；重逢时确认 | Lee/Kiesler, HRI 2010（N=317） |
| 弃用是**渐进**的 | N=70、6 个月：弃用来自"功能不再相关"，不是单次分离 | 重逢做得再好也救不了没用的机器人 | De Graaf, HRI 2017 |

### 1.5.3 树（v2）

```text
分离发生
├─ 先判"返回先验"：他会不会回到这个点？
│   依据：场景类型（门口/厕所/店内/开放通道）+ 最后方向 + 手机在场
│
├─ A. 返回先验强 → 锚定等待 + 可发现性
│   （门口/厕所这类"必经点"：理论说"留一方"最优，且人 guaranteed-to-return）
│   动作：停在 ≤0.4×人流处、朝向他的来路、每 5s 播报状态、给出可读的停止点
│   └─ 边缘：他从别的门走 → 转 B'（巡游备选出口）
│
├─ B. 返回先验弱 + 手机链路可用 → 手机给 (bearing, range) → Bug2 朝目标走
│   途中每 10–20m 争取一次视觉修正（看见即重置到 0.2–0.5m）
│   进雷达 8m → 朝向腿簇转 → 相机身份门（3–5 帧）→ 恢复跟随
│   └─ 边缘：iOS 后台断流 / 热点 >30m / PDR 漂移 / Bug2 在里程计漂移下仅 40% 成功
│
├─ B'. 返回先验弱 + 多条可能路径 → 离散点巡游（理论最优：留一个，巡其余）
│   车在 2–4 个必经出口之间巡游，每个点停 5–10s 并播报
│   └─ 边缘：点太多 → 每个都错过；出口被封
│
├─ C. 返回先验弱 + 无链路 → 锚定扩张搜索
│   1→2→4m 前向扩张，每次回锚点（competitive ratio 9）；上限 N 米 / M 秒
│   超限 → 停在必经点 + 播报（不再"半路停下"）
│   └─ 边缘：方向先验错 / U 形死角 / 对向错过
│
└─ D. 跨区域/跨层 → 不做（V3：需地图 + 定位）
```

### 1.5.4 与旧版（无引用草图）的五处差异

1. 新增**"返回先验"作为第一分叉**（理论要求，不是拍脑袋）；
2. "等"从默认降级为**有条件的 A 分支**；
3. 有界搜索 → **锚定扩张（doubling）**，有竞争比；
4. 新增 **B' 必经点巡游**（离散点模型最优解）；
5. 新增**状态播报参数**（~5s）与**等待点人流判据**（≤0.4× 最大流）。

### 1.5.5 文献空白（= 本项目的 novelty）

- **没有"人-机重逢"的形式化**：RPF-Search（T-Mech 2025, arXiv:2503.02188）是"找回系统"，不是策略理论；
- **没有"谁该动"的最优分配**（人天然会走、车可自由动的非对称条件）；
- **没有公共空间里"机器人丢了之后人的第一动作/等待时长"的现场研究**（唯一相关 JOYRIDE 仅 N=2）；
- HRI 依恋研究把"分离-重逢（Strange Situation）"明确列为**未被使用/未测量**（Mitchell & Jeon 2025 综述，30 篇）；
- 没有等待机器人的朝向/显眼度参数（只有人流与个人空间模型）。

## 2. 核心：分离点 = 共同原点（相对定位，无地图）

分开那一刻，机器人与手机在同一地点；而且机器人**刚看见过**主人（知道初始相对方位与距离）。此后：

```text
p_人(t) − p_车(t) = [p_人(t0) − p_车(t0)]          ← 分离瞬间的初始相对向量（视觉给出）
                  + [Δp_人 − Δp_车]                 ← 两段位移之差（各自推算）
```

- `Δp_车`：机器人自身位移（IMU 积分；V2 加编码器后更准）。
- `Δp_人`：手机位移（PDR：计步 × 步长 + 朝向变化）。
- **两个点都是相对分离点算的 → 谁都不需要知道"自己在世界坐标系哪儿" → 不需要地图、不需要绝对定位。**

**朝向要对齐，但只用"相对变化"**：统一表达在**机器人航向系**里；手机那侧用
`(罗盘_now − 罗盘_t0)` 而不是绝对罗盘角 —— 这样能抵消磁偏置的常值误差（相对变化比绝对值稳）。

## 3. 锁人线（owner_id / 身份）交付

| 项 | 内容 | 现状 |
|---|---|---|
| **手机当"软标签"** | 一次网页授权后被动上报 `{t, 位移, 朝向}`；不要求任何后续操作 | 无（现在是 30s/60s 心跳，只记时间戳） |
| **在场提速** | 心跳从 60s 级 → 1–2 Hz（`ip neigh` + 轻量 ping） | 有代码，节拍太慢 |
| **负向身份门** | "本场曾见过 + 已 N 秒不见" → 拒绝模板重捕获（防同色路人） | 无；需 `_presence_ever` 标志，默认关 |
| **相对连续性** | 相机盲区内，用手机的位移+朝向延续"主人在哪一侧"的信念 | 无（现在靠 θ̇ 外推，2s 就失效） |
| **重捕获锚定** | 一进视野：2 帧确认 + 模板匹配 + 换人确认门 → `tracker.reset()` → 恢复跟随 | ✅ 已有（可直接复用） |
| **间歇视觉修正** | 机器人偶尔看见（雷达腿簇/相机）→ 用该次量测校正 PDR 漂移 | 无（V2c） |

**身份三层（从弱到强）**：手机在场（弱） → 相对连续性（中） → 相机模板（强，唯一可放行平移的身份证据）。
**注意**：手机只能做"弱在场"，永不当身份凭证（手环 MAC 可伪造）。

## 4. 世界线（world / 空间理解）交付

| 项 | 内容 | 现状 |
|---|---|---|
| **相对目标导航** | 输入 `(bearing, range)` 相对目标 → 输出 `MOVE/DIFF`：先转向、再前进 | 无（follow 只会追人，不会"去某点") |
| **无地图绕障** | **Bug2 沿边绕行**：朝目标开，前方被挡则沿障碍边界绕，直到目标方向重新可见；超时/超距放弃 → 停在可被找到处 | 无 |
| **弱地图更好** | 用 `grid.json`（墙/门/自由扇区，TTL 30s）跑 A*：未知格当可通行、边走边重规划 | 有 grid，无规划器 |
| **安全包络** | `lidar_guard` 的速度律/净空否决**在底下兜底**（相对导航不允许绕过它） | ✅ 已有 |
| **可被发现性（findability）** | `sector_score` 从"亲和度"扩展为 **必经 × 可见 × 不挡路**：选一个"人回来时一定经过、且看得见"的等待点 | 部分（只有亲和度） |
| **在有界范围内搜索** | 搜索不许无界乱走：限于最后已知点周围 N 米 / M 秒 | 无 |

**"可被发现性"的最小定义（可离线算）**：粗图上的**割点/必经点**（门、出口、电梯）+ 视线可达（相机/雷达可见）+ 不挡动线。这就是机主说的"等在厕所门口/店门口"的可计算版本——但**注意：等待是机器人的动作，不是对人的要求**。

## 5. 两线接口（唯一契约）

```json
// 手机 → 车（WebSocket，1–2 Hz）
{"t": 1729..., "dxy_m": [1.2, -0.4], "dth_deg": -35.0, "steps": 18, "src": "pdr"}
// 可选：室外直接给绝对位置
{"t": 1729..., "gps": [31.23, 121.47, 5.0], "dth_deg": 12.0, "src": "gps"}

// 车内部产出（喂给导航与锁定）
{"bearing_deg": 21.5, "range_m": 14.2, "sigma_m": 2.0, "age_s": 0.4,
 "quality": "pdr|gps|corrected", "since_t0_s": 38.0}
```

- **时钟**：以车为基准（phone 只发自己的单调时间 + 往返延迟估计），避免时钟漂移。
- **质量门**：`sigma_m` 超过阈值（如 5m）或 `age_s` 超时 → 导航只许"慢速靠近 / 停等"，不许全速。
- **身份**：本接口**永不**携带"我是主人"的结论，只给"几何"。

## 6. 精度包络与失效模式（诚实交底）

| 时间 / 距离 | 典型误差 | 能用吗 |
|---|---|---|
| ≤60s、≤30m | 1–2m | ✅ 够"走到附近"，最后 5–10m 交给雷达/相机 |
| 1–3min、≤50m | 2–5m（罗盘漂移为主） | ⚠️ 需途中视觉修正 |
| >5min / 跨层 | 不可用 | ❌ 需地图/定位（V3） |

| 失效 | 现象 | 对策 |
|---|---|---|
| 罗盘漂移（金属/电梯/钢筋） | 手机位移方向偏 | 只用**相对**角度变化；电梯/金属区降权 |
| 步长误差（±15%） | 距离线性偏差 | 每人标定一次（走 10m 数步数）；≤60s 内影响可接受 |
| 手机在包里/不随身 | 无步数 | 质量降级 → 只当"在场"，不参与几何 |
| 授权被拒 / 电量耗尽 | 无数据 | 退回今天的行为（心跳 + 相机 + 雷达 + 搜索） |
| 时钟漂移 | 位移对不齐 | 车侧做往返延迟估计，手机只报自己的单调时间 |
| PDR 与视觉矛盾 | 两套估计打架 | **视觉优先**（身份证据在相机侧），PDR 只做盲区桥接 |

## 7. 分阶段（全部不依赖新硬件）

| 阶段 | 做什么 | 验收（离线可测） |
|---|---|---|
| **V2a** | 相对目标估计（纯函数）+ **Bug2 绕行** + **锚定扩张搜索**（1→2→4m，每次回锚点） + **必经点巡游**（2–4 点，每点停 5–10s） | 假数据：分离 20m + 一处 L 形墙 → 到目标 ±1.5m；扩张搜索在"人往回走"场景下能与锚点相遇；巡游在"两个出口"场景覆盖正确出口；不触发雷达否决；超时必停 |
| **V2b** | 手机网页：一次授权后被动发 `{t, dxy, dth}`；车侧时钟对齐 | 走廊 30m：估计位置与真值差 ≤2m；断流 3s 内降级 |
| **V2c** | 间歇视觉修正（雷达 8m 腿簇 / 相机 ±32° → 校正 PDR） | 50m + 两次视觉修正 → 误差 ≤2m；漂移不累积 |
| **V2d**（可选） | 弱地图 A* + 重规划（用 `grid.json`） | 与 Bug2 同场景对比：路径长度/耗时/否决次数 |

**共同验收线**：到达 ±1.5m；全程无碰撞（雷达否决生效次数 >0 而无人身风险）；超时必停；**任何异常都必须退化成"停在可被找到处"**，不许无界乱走。

## 8. 不做的事（避免越界）

- ❌ 不建图、不 SLAM、不做重定位（V3 / PC 科研轨）；
- ❌ 室内不做绝对定位（没有 UWB、没有 WiFi RTT ——AP6255 在 AP 模式拿不到 station 信息）；
- ❌ 不给用户发 tag、不要求人做识别动作；
- ❌ 不用手机信号替代身份（只能当"弱在场"）；
- ❌ 不在 (c) 类（跨层/跨区域）承诺任何事。

---

## 9. 三个可写论文的开放问题

1. **无地图、无基础设施的"人机重逢"**：相对定位 + Bug 类导航 + 间歇视觉修正的组合，目前没有对应工作（多机器人 rendezvous 是经典理论，但"人-机、无 tag、无地图"几乎空白）。
2. **身份证据陈旧后的行动授权**：相对估计的 `sigma_m` 如何决定"只准转 / 准慢走 / 准全速跟"——即此前查到的"身份置信门 + 安全 shield"组合（文献空白）。
3. **零用户负担的相互可找性（findability）**：机器人要"显眼到什么程度"人才能找到它；等待点的"必经 × 可见 × 不挡路"打分与实测。
