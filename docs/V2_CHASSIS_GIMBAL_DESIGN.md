# SC V2 设计调研 — 以 RoboMaster 全向底盘 + 稳定云台为参考的低成本复刻

> 生成于 2026-09-28。回答一个问题：RoboMaster 那个"能横着走、底盘转云台不晃"的酷感，哪些本质值得抄、哪些是烧钱的部分可以绕开，落到 SC V2 的**车底座 / 载物部分 / 摄像头部分**上怎么花最少的钱实现。
>
> 定位：调研+方案稿，供 V2 立项讨论。demo（10 月底）仍由 V1 承担，V2 并行搭台。

---

## 0. 定位与研究命题（2026-10-08，统筹）

> **V2 不是十月 demo 的一部分**——demo（10 月底，硬节点）由 **V1** 承担。V2 是 **demo 之后的硬件补全 + 世界模型/HRI 探索平台**，服务于学期路线 **Phase C（11 月 → 1 月）**。

**三条动力**：
1. **硬件齐全 → 固件才可自由迭代**：C3 引脚已算死（编码器装不下），底盘层能力全被硬件卡着；S3 + 4 编码器电机 + 三路隔离电源到位后，轮速环/航向环/MEC 运动学/里程计才解锁——这是"能跑 → 能迭代"的分水岭。
2. **世界模型吃雷达**：雷达给滚动地图**扫描匹配锚定** → 地图不再"糊" → TTL 可放宽 → 从"感知快照"迈向"有记忆的度量地图"（补上 08-24 自认的 gap）。
3. **低光辅助**：相机夜景幻影（宿舍 95/98 帧含幻影）是真实失败模式；雷达不受光照影响，但**看不见玻璃/无语义** → **互补而非互替**。

**受控实验设计（研究命题）——同平台、同场景、受控光照**：

| 维度 | 相机 | 雷达 | SC 能给的证据 |
|---|---|---|---|
| 结构感知（门/墙/开阔区） | Hough 怕光照、延迟 340–1570ms | 几何缺口、免光照、5–10Hz | 同一门框两路的检出率/延迟对比 |
| **低光** | 幻影 person 95/98 帧（已有真实数据） | 不受光照影响 | **现成的夜景失败数据集** |
| 玻璃 / 语义 | 看见玻璃 + YOLO-World 给语义 | **看不见玻璃** | **互补矩阵**（谁何时失效、谁补位） |
| 地图锚定 | 无 | 扫描匹配纠偏 | 滚动地图 smear 前后对比 |

- **核心叙事**：不是"哪个更强"，而是**"何时视觉失效、雷达补位；何时雷达失效（玻璃/高物）、视觉补位"的互补矩阵** —— 一台车上量化，同时命中 **无人驾驶**（传感器融合/边缘）与 **世界模型**（语义网格的几何底座）两个方向。
- **延伸到 HRI**：麦轮 holonomic + 雷达净空 → BESIDE 并排跟随 / proxemics 社交间距 / social costmap 首次"可测量"（§12.4、§13）。

**红线（统筹）**：
- V2 上车前，**世界模型保持相机-only 可跑**；雷达 **L2/L3（SLAM 建图/重定位）明确划 Phase C**，不占工期。
- **寒招 = 产品/展示轨，单列**，不与科研轨（论文/专利）抢资源。
- **分相交付**：V2a 底盘+电源+相机（治三痛地基）→ V2b 云台 STS3215 → V2c 雷达 L1；每相独立可用。

## 0.1 结论先行

1. **RM 的"酷"不是造型，是三件事**：① 全向运动学（麦轮 + 每轮速度闭环）；② 底盘-云台解耦（云台是绝对基准，底盘跟着云台转）；③ 机械上低重心 + 轴平衡 + 减震。贵的是电机/电控（GM6020 ≈ ¥400+/个），但三件本质全都可以用 ¥500 级硬件复刻出 80% 的观感。
2. **V2 底座推荐**：4 麦轮 + 4 路编码器减速电机（GA25/GM25-370 级）+ 2×TB6612 + **运动控制器迁移 ESP32-S3**（gimbal README 里早就记了"编码器装不下 C3"这笔账，V2 正是还账的时机）。全套约 **¥250–400**。
3. **V2 云台推荐分两步**：先用 **STS3215 串行总线舵机 ×2**（¥60–80/个，7.4V 直用现有 2S 电池，单线菊花链只占 1 个 GPIO，自带速度闭环治抖动）；demo 后再玩 **无刷 DIY 云台**（2204 电机 + BGC 板 ≈ ¥150，IMU 硬件自稳，才是真"RM 级稳"）。
4. **载物部分照抄 RM 的分层思想**：载物永远在底盘层，不进云台层；上层板 + 减震垫 + 低重心居中。
5. **控制架构移植是零硬件成本的最大收益**：S3 固件 100Hz 航向环 + 轮速环，RK 10Hz 外环只发 `MEC <vx> <vy> <wz>`；同时保留 `DIFF L R` 命令的兼容语义（翻译成 vx+wz），**follow_controller 现有控制律一行不用改就能跑**。
6. 对现有三大痛点（直行走歪、偏航震荡、幻影 person）的根治路径分别落在：航向陀螺环（已立项的 MPU6050）、轮速编码器环、轮式里程计。V2 底座一次把三件硬件都备齐。

## 1. RoboMaster 参考调研

### 1.1 底盘为什么能"到处转"

| 部件 | RM 方案 | 作用 |
|---|---|---|
| 驱动 | 4× M3508 无刷减速电机 + C620 电调，CAN 总线 | 每轮独立**速度闭环**（编码器反馈），四轮速精确可控 |
| 轮子 | 4× 麦克纳姆轮（辊子 ±45°，X 对角布局） | 轮子轴向滚动 + 辊子侧向滑动叠加 → 合成任意方向速度 |
| 运动学 | `vx, vy, wz` → 4 轮速混合解算 | 平移方向与自转**完全解耦**，可边横移边转（小陀螺） |

麦轮运动学（X 布局，左前 w1 / 右前 w2 / 左后 w3 / 右后 w4）：

```text
w1 = vx - vy - wz*k
w2 = vx + vy + wz*k
w3 = vx + vy - wz*k
w4 = vx - vy + wz*k        （k = 车体几何常数；正负号随辊子手性/布局约定）
```

效果：全向平移（holonomic）+ 平移与旋转叠加。商场/宿舍的平整瓷砖正是麦轮的主场；它的弱点（地毯、地面缝隙、门槛）在 SC 的 demo 场景里基本不出现。

### 1.2 云台为什么稳

| 层 | RM 做法 | 廉价复刻的对应物 |
|---|---|---|
| 执行器 | GM6020 直驱无刷（空心轴穿线、无背隙、大扭矩） | 总线舵机（速度闭环）/ 无刷云台电机+BGC 板 |
| 传感 | 云台上装 IMU（**不在底盘上**），1kHz 串级 PID：角度环→角速度环→电流环 | MPU6050 + 100Hz 内环；或 BGC 板自带 IMU |
| 解耦 | yaw/pitch 各自独立串级 PID；底盘动≠云台动 | 分层：云台内环独立于底盘外环，RK 只发目标角 |
| 机械 | 重心过转轴、低摩擦轴承、slip ring 无限旋转 | 配平云台、滚珠轴承转轴、（可选）¥20 滑环 |
| 模式 | **底盘跟随云台**：底盘 wz = Kp ×（云台-底盘相对角），云台先指、底盘后转 | 见 §5，直接移植到 SC 的 follow 架构 |

关键洞察：**稳 = 大扭矩执行器 + 高频 IMU 闭环 + 机械平衡** 三者相乘。前两者各花几十块就能得到"够用版"，第三件是纯手艺、零成本。

### 1.3 贵的部分 vs 值的部分

| RM 的做法 | 复刻？ | 理由 |
|---|---|---|
| M3508+C620 大功率动力 | ❌ | SC 载重 <2kg，TT/GA25 级电机足够；M3508 还需要 C620 电调+CAN 调试，成本和工时都不值 |
| GM6020 云台直驱 | ❌（V2 阶段） | ¥400+/个 + FOC 开发板；STS3215/BGC 路线用 1/5 的钱拿 70% 效果 |
| 1kHz FOC 电流环 | ❌ | SC 不打弹丸，100Hz 航向环 + 轮速环已远超需求 |
| 麦轮运动学 + 轮速闭环 | ✅ 核心抄 | 这是"到处转"的全部秘密，纯数学+廉价编码器 |
| 底盘跟随云台（解耦分层） | ✅ 核心抄 | 零硬件成本，纯控制架构，直接治 SC 现有的"云台一动底盘就歪" |
| IMU 放云台/放底盘的取舍 | ✅ 抄思想 | SC：MPU6050 上底盘治航向（已立项），云台自稳交给 BGC（V2.5）或速度限幅（V2） |
| 低重心、轴配平、减震 | ✅ 白拿 | 纯机械手艺 |
| slip ring 无限旋转 | ⭕ 可选 | ¥20–30；不做就限制 pan 行程（现有救援式凝视本来就是"95% 冻结"，够用） |

## 2. V2 车底座

### 2.1 驱动方案三档对比

| 档 | 配置 | 预算 | 优点 | 缺点 |
|---|---|---|---|---|
| **A（推荐）** | 4 麦轮(65/80mm) + 4×编码器减速电机（GA25/GM25-370 或 MG310，霍尔编码器）+ 2×TB6612 + 上下双层板 | ¥250–400 | 轮速闭环→航向环/里程计地基全齐；扭矩够带载物；尺寸可控 | 要自己做 4 路编码器×2 + 电机×4 = 6 路 PWM 的固件（正是 S3 迁移的动机） |
| B | 成品麦轮底盘套装（TT 电机版，带测速码盘） | ¥120–200 | 最省事，插上就能跑 | TT 电机扭矩/一致性差，载物后明显吃力；码盘精度低；载物叙事撑不住 |
| C | 3× 万向轮（全向轮）三角形布局 | ¥100–150 | 轮子最便宜，运动学更简单 | 点接触，过缝/不平地面就卡；负载小；橡胶全向轮才好用（贵） |

**2.1b 舵轮（swerve drive）评估：为什么 V2 不上（2026-10-07）**

舵轮 = 转向轴 + 驱动轮二合一模块：一个电机让整个轮组偏航指向任意方向，另一个电机驱动轮子滚动。RM 圈主流方案是 4 模块×2 电机（转向 6020/2006+减速 + 驱动 3508），工业 AGV 则常用 1–2 个舵轮单元 + 万向脚轮。

| vs 麦轮 | 舵轮 | 说明 |
|---|---|---|
| 磨损 | ✅ 标准橡胶轮 ¥5–15/个 | 麦轮辊子磨平/侧滑损耗是真实痛点，但 RM 语境（20kg+、小陀螺滥用）远重于 SC 的 5kg 低频使用 |
| 效率/续航 | ✅ ~90% vs ~60% | 无侧滑损耗 |
| 里程计 | ✅ 无横向打滑 | 编码器可信度大增——但 SC 用扫描匹配+IMU 兜底 |
| 噪音 | ✅ 无辊子咔咔声 | |
| 电机数 | ❌ 8 个（4 转向+4 驱动）或 2 舵轮+脚轮 4 个 | 成本/固件翻倍 |
| 机械 | ❌ 转向轴承+减速+回差 | 打印件 failure point 多，寒招 deadline 前风险高 |
| 预算 | ❌ DIY ≈ ¥600–1000 vs 麦轮 ¥320 | |

**结论：V2 维持麦轮（预算/固件带宽/工期三条硬约束），买一对备用轮（¥45）对冲磨损即可；若 V3 阶段里程计精度或续航成为真瓶颈，"2 舵轮+脚轮"布局（总电机数仍 4）是比 4×舵轮更合适的学生级升级路径。**

**2.2b 底座方案定稿（2026-10-07）：¥30 成品板基座 + 自购铝板上层 ≈ ¥55–65**

现售 230×305mm 底座（¥30）几何核算通过：80mm 轮轴距 200–210mm（轮缘距板端 7–12mm，够）；轮距 = 板宽 230 + 两侧支架外扩 ≈ 260–280mm（贴近原设计 270）；电机向内伸入板内无冲突；板底离地 ~60mm 由电机支架决定（与 555 修订注的 6.1cm 一致）。

**✅ 2026-10-07 布局修订：轮子探头（wheelbase 240）**——轴距放大到 **240mm**（轮心 ±120，轮弧超出 305 板端 ~7.5mm），轮距维持 260–280：整一脚印 ≈ **295×315mm**；纵向支撑多边形 +14%，板长方向全部释放给载物（无轮弧让位）。代价与对策：①悬臂输出轴最怕侧面碰撞——板两端加防撞条（铝条/打印保险杠，高出轮弧即可，顺带当提手位）；②脚印 295×315 对寒招走廊/电梯无压力。重心校正：探头不降重心（重心由电机 40mm 高度与电池贴底位置决定），买的是支撑多边形与板面利用率；降重心的真正杠杆仍是电池居中贴底、载物压低。**载物区核算**：上层板 300×350 下，去掉桅杆前带 ~60mm，可用 ~300×290mm——30×20×15 快递盒 + 购物袋直接放，富余。验收三件事：①板厚 ≥4mm（薄了给桅杆底座加铝条加强）；②确认是纯板+铜柱结构（TT 电机座孔位用不上，自己钻 37 电机支架孔）；③上层板换 2mm 铝板 300×350（扛桅杆悬臂力，¥25–35），宽度 ≤350mm 防超出轮距过多（翻边力臂）。小拉车改造方案否决（管架软/几何错/自重吃载重），置物架金属线篮（¥15–25）作为载物篮采纳——自带提手，"篮子叙事"零成本实现。

选 A 的理由：**编码器是这个方案里最值钱的部件**——它同时是轮速环、航向环前馈、里程计三件事的硬件地基（gimbal README 已记"根治幻影 person = 位置连续性过滤 = 里程计"）。多花的 ¥100–150 买的是三个痛点一次备齐。

### 2.3 运动控制器：C3 → S3 迁移

C3 引脚账本（gimbal README 已算死）：13 个可用 GPIO 已用 11，装不下 4 电机×2 PWM + 4 编码器×1 + IMU I2C×2。S3 有 30+ 脚，固件近原样移植（LEDC、USB CDC、UART 解析框架全复用），一次迁移同时解决：4 路编码器输入、双 I2C、未来超声波 TEL 通道。RK3566 大脑与 USB CDC 链路不动。

### 2.4 结构布局（照抄 RM 的分层）

```text
┌──────────── 上层板：载物台（可拆）+ S3/RK 电子仓 + 云台立柱（前中）
│  ↑ 减震垫/铜柱
├──────────── 下层板：4 电机 + 麦轮 + 电池居中 + 驱动板
└──────────── 地面
```

- 电池放几何中心（麦轮四轮等载荷的前提）；
- 云台立柱在前中，高度以 RK 摄像头能看到人脸为准；
- 载物台与电子仓分区，泼洒物不烧板子；
- 全车重心压到下层板附近——RM 稳的第三件"白拿"的本质。

### 2.5 协议扩展（保持向后兼容）

```text
# 新增（S3 固件解算麦轮运动学）
MEC <vx> <vy> <wz>        # 速度向量命令，单位 cm/s 与 rad/s，固件内做四轮混合+轮速闭环
# 兼容语义（旧客户端零改动）
DIFF L{left} R{right}     # 固件内翻译成 vx=(L+R)/2, wz=(R-L)/K —— follow_controller 不用改
# 遥测（沿用 BT <mac> <rssi> 行风格）
ENC <w1> <w2> <w3> <w4>   # 轮速/里程，供 RK 侧里程计与幻影过滤
HDG <deg> <gz>            # 航向与角速度（MPU6050 立项里已有）
```

## 3. V2 载物部分

RM 的载物舱（弹仓）给了两条原则，SC 直接抄：

1. **载物属于底盘层，不属于云台层**——载物晃动不进相机视野，相机转动不带动货物。SC V2 的云台立柱与载物台在结构上分开，只共享上层板。
2. **重心管理优先于容量**——载物位设计在几何中心正上方，重物靠中放，轻物靠外放。

具体做法（全部低成本）：

| 项 | 做法 | 成本 |
|---|---|---|
| 防洒 | 上层板与载物托盘之间垫 TPU 打印件/硅胶垫（隔绝电机高频振动）；托盘四周 3D 打印低围栏 + 可选弹性绑带 | ¥10–20 |
| 防滑 | 托盘面贴硅胶垫/魔术贴 | ¥5 |
| 接收体验 | RECEIVE 状态时托盘朝向主人一侧（利用麦轮横移+原地转向，正好是 §5 解耦控制的展示位） | ¥0 |
| 叙事加成 | 载物台做成"包挂/挂钩"形态更贴"逛街搭子"人设（外套挂上去那句 slogan） | 视设计 |

## 4. V2 摄像头部分（云台）

### 4.1 三方案对比

| 方案 | 构成 | 预算 | 稳定性 | 与现有代码的关系 |
|---|---|---|---|---|
| **A（V2 推荐）** | STS3215 串行总线舵机 ×2 + 现成舵机云台支架 | ¥120–180 | 速度闭环+负载反馈，抖动大幅改善；但仍属"指哪打哪"，不隔底盘振动 | `PAN/TLT` 语义保留（RK 侧照发角度，S3/C3 侧翻译成总线协议）；gimbal_follow.py 零改动 |

### 4.2 方案 A 细节（为什么是它先行）

- STS3215（飞特）是机器人社区事实上的廉价总线舵机标准（SO-ARM100 等开源臂同款）：TTL 单线菊花链、位置+速度+负载回传、磁编码 360°、**7.4V 版本直接吃现有 2S 电池**（MG996R 现在还要二极管降压凑合）。
- 控制上它能做**速度限幅的平滑转角**（P 环输出→限速执行），直接治"云台一动底盘就歪"四条扰动通道里的信号混叠问题；
- 回传角度/负载走 `TEL:` 遥测行，把"指令角即真实角"的假设升级成真实反馈（gimbal README 遗留项）；
- 只占 1 个 GPIO（S3 迁移后引脚完全不紧张），C3 时代"云台吃掉 2 脚"的账也顺带清了。

### 4.3 方案 B 预研要点（给 V2.5）

- BGC 板本质就是消费级手机云台的芯：板载 IMU 以数百 Hz 闭环保持相机姿态——**这正是 RM"云台稳"的物理层，只是没有 GM6020 的暴力扭矩**；SC 相机很轻，2204 电机绰绰有余。
- yaw 轴无限旋转需要 slip ring（¥20–30）或限位（现有救援式凝视本来就是"95% 冻结"，限位可接受）。
- 移植接口：RK 侧把 follow 的期望 pan 角按 SimpleBGC 串口协议下发（ANGLE 模式）；`PAN/TLT` 兼容层写在 S3 固件里。

## 5. 控制架构移植（零硬件成本，本次调研最重要的部分）

### 5.1 RM 三层 → SC 三层

```text
RM:  云台层 1kHz IMU 串级PID（绝对基准，独立）
     底盘层 1kHz 编码器轮速环
     外层   低频遥控/AI 决策

SC V2:
     云台层  STS3215 内置位置/速度闭环（或 V2.5 BGC IMU 自稳）—— 独立，不感知底盘
     底盘层  S3 固件 100Hz：MPU6050 航向环 + 4 路编码器轮速环 —— 独立执行 vx/vy/wz
     外层   RK 10Hz：follow_controller / hri_state 只发 MEC vx vy wz 与 PAN/TLT 目标
```

现在的痛点全部是"层与层混叠"造成的（gimbal README 四条扰动通道）：新架构里底盘不再需要知道云台在动——**云台指哪，底盘的 wz 由相对角伺服跟上**，误差传导变成单向。

### 5.2 "底盘跟随云台"模式移植

RM 跟随模式的定义：底盘角速度 = Kp ×（云台 yaw − 底盘 yaw 相对角）。SC 对应：

```text
pan_error = gimbal_pan - 90°          # 云台偏离车体正前方的角度
wz_follow = Kp * pan_error            # S3 固件内实现，或 RK 外环实现
# follow_controller 现有"弧线绞合"(BASE_ENTER/BASE_EXIT) 可逐步被它替换——
# 麦轮加持下甚至可以不转头，直接 vy 横移跟人（proxemics "beside" 语义天然成立）
```

分阶段替换：demo 前不动（V1 用现有救援式凝视）；V2 上线后先并行跑 `wz_follow` 观测对比，再切换。

### 5.3 与三大痛点的对应

| 现有痛点（gimbal README） | V2 的根治路径 |
|---|---|
| 直行走歪 / 弧线不准 / 偏航震荡 | 100Hz 航向陀螺环（MPU6050 立项直接并入 V2 固件） |
| DIFF 响应不可预测、电压衰减导致速度漂 | 4 路编码器轮速闭环，PWM 指令变成速度指令 |
| 幻影 person 追杀（位置连续性过滤缺里程计） | ENC 遥测 → 轮式里程计，"位置连续性"成为最强过滤器 |
| 云台一动底盘就歪 | 分层解耦 + 底盘跟随云台（§5.2） |

### 5.4 平移-指向-航向三级解耦（V1「云台一动就翻车」的结构性根治，2026-10-11 [云台]）

> **前提（机主定调）**：云台**最终必须能自由运动**——注视、搜索、扫描、上下取景（tilt）只有相机指向能给；把云台冻死只是 demo 期的权宜。所以 V2 的设计目标不是"让云台少动"，而是**让云台动起来也不破坏底盘闭环**。
>
> V1 失败的根因不是"云台动了"，而是两件事叠加：① 两个执行器从**同一个延迟像素误差**里各自解读；② 底盘平移**必须借道自转**（差速），于是每次横向跟随都要转头，直接扰动相机指向。

#### 5.4.1 方位变化的两个来源（扰动量级）

目标在车体系的方位角变化：

```text
dθ/dt = ω_chassis  +  v_lateral / D
        ↑ 车体自转引起      ↑ 车体平移引起 (v/D 随距离衰减)
```

| | V1 差速 | V2 麦轮 |
|---|---|---|
| 横向跟人的主要手段 | **转头**（ω_chassis 大） | **横移 vy**（ω_chassis≈0） |
| 云台 pan 需跟随的速率 | 与车体自转速率同级（大、阶跃） | 只剩平移引起的漂移（∝v/D，平滑） |
| 典型量级（人走1m/s、距2m） | 30~60°/s 阶跃（≥V1 实测 RATE_LIMIT 60°/s 常饱和） | ≤15~28°/s 斜坡 |
| 对 V1 四通道的激励 | 通道1/2 的主要激励源 | 降一档，可用限速+OOSM 吃掉 |

**结论：麦轮删掉的是"平移借道自转"，不是云台的运动。**

#### 5.4.2 三级分工（每个自由度归一个执行器）

| 自由度 | 归属 | 职责 | 是否扰动相机 |
|---|---|---|---|
| **vx, vy（平移）** | 底盘（麦轮） | 跟人：前后保距、横向对齐 | ❌ 不扰动指向 |
| **wz（航向）** | 底盘（**慢速**环） | 仅服务"把目标保持在云台行程内"（§5.2 的 `wz=Kp×pan误差`） | ⚠️ 唯一扰动源，但低频 |
| **pan, tilt** | 云台 | 看住人 / 注视 / 搜索 / 扫描 / 上下取景 | —— 它自己的自由度 |

关键转变：**航向从"跟随的主执行器"降级为"慢速行程管理环"**；可以很小甚至为零（锁定航向 + 纯 vy = "并排跟随"，§12.4 的 proxemics/BESIDE 语义）。**"车头朝向"因此变成可自由支配的社交自由度**——身子移开、眼睛看着人，这在 V1 里做不到（航向被跟随环吃光）。

#### 5.4.3 三条纪律（解码与控制的接口契约，防通道1复发）

1. **全线时间戳化**：检测帧（A3.5 已完成）、舵机反馈、编码器里程都要 `ts`。
2. **用测量角，不用指令角**：STS3215 `TEL` 回传的真实 pan/tilt 才有资格进坐标变换（V1 用指令角 + `PAN_INVERT` 时险些埋雷）。
3. **控制层禁止做角度算术**：像素→角度只能在 `state/decoder` 内、且只与**同帧时刻**的云台角配对；跨时刻补偿一律交给 `state/tracker`（OOSM）。控制层只消费 `(θ, r, θ̇, ṙ)@now`。

#### 5.4.4 "原来想用云台摄像头做的事"逐条对照

| 原目标 | 三级解耦后 | 结论 |
|---|---|---|
| 跟人时把人留在视场（V1 最大丢因） | vy 横移代转头 → 云台只做微调 | ✅ 更稳 |
| 注视/目光（HRI：看向主人、等待时面向他） | 航向成为独立自由量 → **"身子移开、眼睛看着你"** | ✅ 变强 |
| 丢人后搜索 | 云台扫 + 底盘可原地转/绕圈（三自由度） | ✅ 更强 |
| HIDE / 世界扫描 | 底盘平移换视角给相机"再看一眼" | ✅ 更强 |
| 现实坐标解码 | 自转可控（IMU）+ 平移有里程计 → 世界系可解 | ✅ 从"凑合"到"可算" |

> **2026-10-16 落地注（云台冻结期先行的 V1 版）**：上表第 3 行的"底盘原地转"已在
> `scripts/follow_controller.py` 的**底盘转向通道**里实现（相 TRACK/TURN/BLIND/SEARCH，
> 命令走真实 `MOVE L/R` 语义；入口 E1 预测式 TTE + E2 贴边兜底；出口 15° 迟滞；反转看门狗）。
> 与本节设想的差别：① 没有麦轮，故"平移-指向-航向"三级里只有航向这一级（云台冻结=相机
> 与车体固连，`±32°` 水平视场就是硬边界）；② 弱线索（低置信/贴底框、下装颜色模板）只授权
> **原地转**，不授权平移（平移只由强证据放行，机主原则第 0 层不放宽）；③ V2 若实现带符号
> 差速或麦轮 `wz`，可把这里的"状态切换"升级为连续混合。仿真证据：`simulation/webots/run_passby.sh`
> （擦身 1.0m：开 0.62s 不可见 vs 关 4.03s 跟丢）。

#### 5.4.5 不能替代云台的三件事（防误读）

1. FOV 保持：若云台固定，人一旦走出画面就得靠**车体自转**去找——正是 V1 的老问题；360° 覆盖需要滑环（§7.6）。
2. **注视语义**（看向主人/路人）与 **tilt 上下取景**：只有相机指向能给，麦轮平移代替不了。
3. HIDE 的"抬头/低头"权衡（§9.3）：跟随微抬看人、HIDE 下压看地。

#### 5.4.6 防复发的三条护栏

1. **航向慢环带宽要远低于云台视觉环**（云台 10~20Hz 内环 / 航向 2~5Hz 外环），否则两环又抢同一个误差。
2. **云台限速 + 底盘 wz 持续性门**：单帧幻影不能推动整车（通道3）。
3. **保留 DIFF 一键回退**（§11.2）：MEC 出问题时一开关退回 V1 语义。

#### 5.4.7 自证实验（V2a 完成后，可写进论文/答辩）

同一段 5m 走廊、同一主人步速，两组对照：

| 组 | 控制 |
|---|---|
| A | 差速跟随（V1 式：横向误差→转头） |
| B | **锁定航向 + vy 横移跟随**（麦轮式） |

指标（各跑 3 次取中位）：**云台 pan 速率峰值 / 图像抖动（检测框中心方差 or 光流）/ 丢人率**。预期 B 组全面胜出——这就是"形态选择被数据支撑"的一页。

#### 5.4.8 对 V2 固件/接口的交付要求（源自本节）

| 交付项 | 内容 |
|---|---|
| S3 固件 | `MEC vx vy wz` + `ENC w1..w4`(带 ts) + `HDG deg gz` + `TEL` 透传 + `DIFF` 兼容 |
| STS3215 兼容层 | `PAN/TLT` 角度语义不变；下发**限速位置指令**；位置/负载/电压走 `TEL` |
| 带宽约定 | 轮速环 100Hz / 云台视觉环 10~20Hz / 航向慢环 2~5Hz / RK 外层 10Hz |
| 验收线 | 直线 5m 偏差 <0.3m；`/turn 90°` ±3°；**摇云台全幅摆动时方位读数不抖**（通道1 复现测试）；全幅摆动时底盘稳跟随（通道2/4 复现测试） |

## 7. 风险与坑（提前交底）

1. **麦轮对地面挑剔**：地毯、门槛、地面缝隙会卡/滑。demo 场景是平整瓷砖没问题，但家访演示前先踩点地面。
2. **4 编码器 ×4 电机是固件工程量**：轮速环 PID×4 + 航向环 + 运动学解算，比 C3 时代的开环 DIFF 大一档；预留 2–3 个周末，别插在 demo 冲刺期。
3. **S3 迁移的坑**：CDCOnBoot 等烧录参数、USB 枚举顺序会变，udev 别名要重做；沿用"拔板烧录成本高"的经验——第一版固件就把 `MEC/DIFF/PAN/TLT/TEL` 全做齐，一次烧好。
4. **STS3215 供电**：峰值堵转 >1.5A，必须独立分路（沿用舵机供电教训），S3 只给逻辑。
5. **无刷云台（方案 B）是独立技能树**：BGC 调参（PID/滤波）有学习成本，当加分项别当主线。
6. **slip ring 不装则云台限位**：pan 行程限制在 ±120° 量级，救援式凝视的 SCAN 逻辑要按行程钳制（现在是 ±45°，天然兼容）。

### 9.3 相机 80cm 高度的视野账（为什么是 80cm）

镜头 H=0.8m、俯仰下压 5° 时：

- **广角（垂直 FOV ≈60°）**：上缘 +25° → 1.7m 的人全身入画需距离 ≥ ~2.0m；下缘 −35° → 前方 ~1.1m 起的地面可见。**"全身+地板"同时成立** ✓
- **普通窄角（垂直 FOV ≈45°）**：上缘仅 +17.5° → 全身入画需距离 ≥ ~2.9m，或云台抬头牺牲近地。鱼和熊掌不可兼得 → **相机选型应选广角（对角 ≥100°）**，俯仰中位略下压。
- 云台 tilt 轴存在的意义就是动态调这个权衡：跟随人时微抬、HIDE/近距时下压看地。
- **文献定性（2026-10-07 补）**：无单一"最佳高度"论文，学界收敛为两条带——**腿级 10–25cm**（2D/3D 激光腿检测经典安装高度）与**躯干带 0.8–1.2m**（全身可见、ReID/遮挡最优，Koide 单目跟随等 assume 此带）；行业对高度不足的标准答案是双高度栈（高位相机看人 + 低位激光看腿/四周）——V2 的桅杆相机 + 38cm 雷达正是此架构。**80cm 的正确定性：躯干带下沿、"手部信号带"门槛**——implicit interaction 要读的伸手/肢体信号只在 0.6–1.2m 可见，10cm 高度切掉了整个信号带（这才是 V1 难受的本质）。80 vs 100cm 属调参差异（云台可补），留桅杆参数实测对比；pose_server 手部关键点置信度 vs 高度曲线可成为自证实验。

### 9.4 已知简化（后续迭代项）

1. 麦轮辊子省略（光圆柱占位）；四轮手性未镜像。
2. 无打印特征：安装孔、减重、圆角、壁厚优化——出打印件时重做。
3. 电子件全是实心占位盒；RK/相机/电池尺寸待实测后替换（§9.2 标注）。

5. 整车模型按钢密度估算无意义；真实配重估算见 §6 预算表与重心分析（重心 ~12–15cm，低于轮距半宽 13.5cm 的临界翻倾角 >42°）。

### 10.1 电机：JGB37-545B（12V，带霍尔编码器）×4

**需求核算**（5kg、80mm 麦轮、瓷砖地面）：

| 项 | 计算 | 结果 |
|---|---|---|
| 连续行驶阻力 | 5kg × 9.8 × 0.03（滚阻） | ~1.5N |
| 8° 坡道 + 0.5m/s² 加速 | 5×9.8×sin8° + 5×0.5 | ~9.3N |
| 麦轮效率折损 | ÷0.6 | 单轮 ~4.5N → **力矩 ~1.9 kg·cm** |
| 设计余量 ×2 | | **单轮额定 ≥3–4 kg·cm** |
| 车速需求 | 0.8–1.0 m/s ÷ (π×0.08m) | **190–240 RPM** |

**选型**：JGB37-545B，12V，减速比选 **~300–400 RPM 档**（该档额定力矩 3–5 kg·cm，堵转 15+），自带霍尔编码器（11PPR×4×减速比 ≈ 1300+ counts/转，100Hz 轮速环分辨率充裕）。¥45–55/个 ×4 ≈ **¥200**。

- 预算更紧的替代：GA25-370 12V + 外置编码器（~¥35/个），力矩余量小一档，载 5kg 勉强——**5kg 目标下建议直接 545**。
- **驱动板同步修正**：545 堵转 3–5A，TB6612（1.2A）不够 → **A4950 模块 ×4**（3.5A，¥8–12/个，≈¥40）或 DRV8871。固件保留 PWM 缓启（现有 ramp 逻辑复用）避免长时间堵转。
- **轮径定案 80mm**（修订 §2.2 的 65mm）：5kg 压强更分散、商场伸缩缝通过性更好、转速需求低一档。
- **PID 平台**：ESP32-S3 硬件 PCNT ×4 接编码器、MCPWM ×4 接 A4950——4 路轮速环 100Hz + MPU6050 航向环全部硬件外设直挂，无软件开销。
- 麦轮手性：80mm 麦轮也分左右手性，下单选"成对（2左2右）"。

**555 备选（2026-10-06 追加，市场货源更足）**：JGB37-555 是 545 的加长加强版（can 67 vs 62mm，低速档额定力矩可到 ~7 kg·cm），5kg 载重余量更足，编码器同为 11PPR 霍尔、PID 方案不变，档位同样选 300–400 RPM。**三个连带调整**：
1. **驱动板换 BTS7960**（单路 43A，¥10–15/个 ×4，或双路 DBH 板 ×2 ≈ ¥50–60）——555 级堵转电流按减速比可到 5–20A，A4950 的 3.5A 顶不住长时间堵转；固件现有 PWM 缓启 + 450ms 超时正好是防堵转逻辑，复用。
2. **12V 锂电组买前必问两个数：持续放电 ≥5A、过流保护阈值 ≥10A**——很多监控类成品包持续/峰值都只有 5A，四电机加速就会跳闸；持续电流按 §21.11 的真实电流预算（正常 2–4.5A、加速瞬时 6–8A）核对即可，"持续 ≥10A"是过严表述。
3. **模型占位修订**：555 本体 Ø35.7×67mm（GA25 占位是 Ø25），下层板底需从 z=5.0 抬到 ~5.5（65mm 轮）/ ~6.1（80mm 轮），否则电机顶面蹭板；两层结构整体上移 ~1cm，镜头高度在桅杆上补，总高不变。

**✅ 2026-10-07 最终定案：JGB37-520（12V，1:30 减速比，带霍尔编码器）**——两处独立数据源（Waveshare UGV02 wiki、Mikroelectron）确认该档规格：**额定扭矩 3.5 kg·cm**（需求 1.9，余量 1.84×）、空载 330rpm（80mm 轮空载 1.38m/s，负载 ~1.0m/s——比 200rpm 档速度更好）、额定电流 ≤1A、**堵转 ~2.3A（A4950 3.5A 直配，不用 BTS7960）**、输出轴 6mm D 轴（配"395/6mm"联轴器）。该型号带编码器版本（JGB37-520B 12V 333RPM 1:30）是 UGV 类底盘的量产标配，货源充足 ¥20–45/个；轮趣（WheelTec）、1688 威恒/鸿跃均有售。**555/BTS7960 降为备选**（实测爬坡吃力再换）。下单核对项：让客服在聊天里给出"1:30 档额定扭矩 + 堵转扭矩"两个数（额定 ≥2.5 达标；堵转 <5kg·cm = 25GA 假冒，直接拒）、编码器 11PPR 霍尔、左右手性成对、先拍 1 个试配再补 3。

### 10.2 电源：一包一宝、三路隔离（全部可过地铁）

**架构**：

```text
电池① 12V 6Ah 成品锂电组(带BMS外壳) ─┬─ 12V 直挂 ── A4950×4 ── 4× 545 电机   [动力轨]
                                      └─ MP1584 降压 7.4V/2A ── STS3215 云台   [云台轨]
电池② 20000mAh 3C 充电宝(PD20W+ 即可) ─┴─ 5V/3A ── KickPi + USB相机 + S3 + 雷达 [电子轨]
```

- **为什么这样分**：云台与电机共电池①但经独立降压隔离（12V→7.4V，输入即使被电机堵转拉到 10V，输出纹丝不动——buck 天然隔 sag），电机永远晃不到云台；RK/相机/雷达整条电子轨在物理上独立的电池②上，这是"落电断连"（v0.5 老毛病）的根治结构。两条轨**仅在信号交汇处单点共地**（RK↔S3 的 USB 线本身已是共地点）。
- **12V 容量核算**：电机均值 ~3A + 云台均值 ~0.5A ≈ 42W → 72Wh ≈ **1.5h**，够 demo 半天轮换。
- **安检合规要点**：
  - 电池①买**带外壳、带保护板、带输出线的成品"12V 锂电池组"**（监控/户外电源类目，JD/淘宝普通人可买，¥80–120），容量 ≤100Wh（6Ah@12V=72Wh ✓）；**不买裸极耳软包**（外观像电动车电池会被拒，多地地铁明确禁电动车电池）。
  - 电池②必须是 **3C 认证品牌充电宝**（2025 年新规：无 3C 标进不了地铁/飞机），≤20000mAh，小米/安克/罗马仕 3C 款均可。
  - 动力轨加装 5A 保险丝 + 船型开关（¥10），充电器随包配。
- 比"两节电池+充电宝"少一个充电器、少一种电芯规格，叙事上更干净。

### 10.3 云台升级：STS3215 ×2（7.4V 版）

- 飞特 STS3215（SO-ARM100 同款，¥60–75/个）：TTL 单线菊花链，**S3 只占 1 个 GPIO**；自带位置+速度+负载回传。
- 平滑原理：下发**限速位置指令**（速度参数写死上限），从根上替代现在 P 环直接跳角度造成的抖动；`PAN/TLT` 命令语义不变，兼容层放 S3 固件。
- 反馈升级：位置/负载/电压走 `TEL:` 遥测行——"指令角=真实角"的假设作废，救援式凝视的状态机拿到真实角度。
- 失效保护：串口 450ms 超时自动卸力（对应现有 STOP 超时逻辑）。
- V2.5 再上无刷 BGC（§4.3 预研要点不变）；MG996R 退役。

### 10.4 相机升级：120° 广角 + 低照度传感器 USB 模组

- **选型硬指标**（来自 §9.3 的 80cm 视野账）：垂直 FOV ≥55°（对角 ≥100°）；**低照度传感器（IMX307 / OS02A10 类）**——宿舍夜景 person 幻影率 97% 的问题是信噪比问题，换传感器比调阈值治本；UVC 协议（RK Linux 零驱动）；定焦手动调到 ~1.5m 拍超焦距。
- 推荐类目：淘宝"**120°广角 无畸变 低照度 USB摄像头模组 1080P**"，IMX307/OS02A10 方案 ¥60–90。罗技 C270/C920 类 UVC 稳但 ~60° 水平 FOV 不达标，排除。
- 带宽不焦虑：管线本来就是 640 级别下采样，1080P@30 足够；11 FPS 瓶颈在 NPU 不在相机。

### 10.5 雷达（ROS 系 SLAM 雷达）加装方案

一句话：超声波是**拐杖**（一个方向一个数），毫米波是**体感**（知道有东西在动、多快，但看不见形状），激光雷达是**画轮廓**（整个房间的几何）。三者是互补栈不是互替。LiDAR"让一切发生"的四步链：①单帧聚类/线段提取→门框方位（生产 grid.json）→②帧间扫描匹配→"世界相对我动了多少"→治麦轮打滑漂移→③扫描累积+优化→占据栅格建图→④当前帧在地图上搜索对位→重定位→全局路径规划。对应 §10.5 的 L1/L2/L3。

### 10.5.2 双目摄像头方案：不推荐（评估记录）

- **算力**：RK3566 的 NPU 跑 CNN 检测，不做立体匹配；SGBM 在 CPU 上 640×480 要 100–300ms（1–3 FPS），吃掉本就紧张的 CPU。带硬件深度芯片的 OAK-D 类 ¥700+ 超预算。
- **恰好最弱**：立体匹配在低纹理白墙、弱光下失败——而 HIDE 的目标物（门框/白墙）和宿舍夜景正是这两个最差场景。
- **覆盖不对等**：双目 FOV ~90°，雷达 360°，要 4 个才等价。
- **会不会影响原本作用**：独立双目模块 → 不碰 YOLO 链路，但 CPU/USB 带宽是真实代价；一体双目模组（RGB 从深度相机走）→ FOV/曝光为深度优化，检测画质受影响。两条路都吃亏，且解决的不是缺的那块（结构感知）。

## 12. V2 整机预测（2026-10-06，几何来自 §9 模型）

### 12.1 尺寸与重量

- **占地 30 × 34cm**（含轮），篮口高 30cm，镜头 80cm，总高 82cm——"细高"形态，比智能行李箱窄、比 RM 步兵瘦。
- **重量账**（纸面，±20%）：双层板 5mm 亚克力 ~1.0kg + 555 电机×4 ~1.3kg + 65mm 麦轮×4 ~0.45kg + 12V 6Ah 锂电 ~1.0kg + 充电宝 ~0.4kg + RK/相机/S3/线 ~0.4kg + 云台/桅杆/打印件 ~0.5kg + 篮子/紧固件 ~0.6kg ≈ **5.6kg 空车**。
- **瘦身三板斧**（把空车压回 ~4.5kg）：板降 3mm（−0.35）、电池 3Ah（−0.5）、充电宝 10000mAh（−0.2）。满载 1kg 载物后 5.5kg，**555 电机余量正好兜住**——这就是选 555 而非 545 的价值。

### 12.2 续航

| 轨 | 电池 | 负载 | 实际续航 |
|---|---|---|---|
| 动力轨 | 12V 6Ah=72Wh | 麦轮效率 60%，巡航 ~20W | **2.5–3h**（逛街场景占空比低可到半天） |
| 电子轨 | 20000mAh=74Wh | RK+YOLO+雷达 ~11W | **~5h** |

短板在动力轨 → 12V 包做成**快换结构**（魔术绑带+DC5521 一插），demo 半天零焦虑；3Ah 档续航减半（~1.5h），一场 demo 一换足够。

### 12.3 安全性分层

| 层 | 措施 |
|---|---|
| 感知 | 超声波急停（现有）+ 雷达/TOF 后补；巡航 ≤0.6m/s、上限 0.8m/s |
| 固件 | 450ms 串口超时停、PWM 缓启防堵转、STBY 拉低（全为 V1 已验证逻辑平移） |
| 电气 | 动力轨 5A 保险丝 + 双电池 BMS + 三轨隔离（§10.2） |
| 机械 | 重心 ~13–15cm < 半轮距 13.5cm（静态翻倾角 >40°）；桅杆顶软帽、桅杆用韧性铝管（碰人弯而不断）；篮子边缘 R 角；轮子全在四角外侧，脚趾夹点低于扫地机器人 |
| 场所 | 室内低速轮式不属机动车/无人机，无牌照问题；商场人流区建议陪同演示 |

### 12.4 社会接纳性（HRI 视角）

1. **借现成社会脚本**：外观锚定"购物篮/行李车"而非"机器人头"——让路、绕行、避让的礼仪人们对购物车早就有了。
2. **透明标签**：桅杆上贴一句"自动跟随购物车 · 相机只用于锁定主人"。被拍摄焦虑是 80cm 平视相机高度的最大风险，一句声明显著缓解。
3. **声音**：麦轮在瓷砖上有特征"咔咔"声。对策：BTS7960/A4950 的 PWM 提到 20kHz（超听域）+ 低转速档选型，能把可闻噪声压到"安静的电动行李箱"级。
4. **不动比动更被信任**：lost_stop 原地等待（现有逻辑）+ YIELD 横移让路，比"到处乱转找主人"的观感好一个量级——现有 HRI 状态机的保守策略本身就是接纳性资产。
5. **占道友好**：30×34 细高占地 < 智能行李箱，HIDE 状态贴边即基本消失于动线。

### 12.5 寒招任务与 20h 续航方案（2026-10-07）

> 目标场景变更：寒假前做出 V2 形态（"不像智能车也不像 RM"），带去高中母校寒招装物料/演示。硬约束：续航 ≥20h（含地铁往返）、可过安检。

**功率分级模式（固件任务，不加电池重量）**：

| 模式 | 状态 | 功率 | 占空比（活动日） |
|---|---|---|---|
| 通勤关机 | 全断电，地铁上 | 0 | 往返 ~2h |
| 柜台展示 | S3 待命 + LED 呼吸 + RK 轻怠速（systemctl stop yolo_daemon，CPU powersave，不跑 NPU） | ~3W | ~70% |
| 跟随演示 | 全管线 + 运动 | ~16W | ~30% |

**均值 ≈ 0.7×3 + 0.3×16 ≈ 7W**。20h × 7W = 140Wh：

- 电子轨维持 20000mAh 充电宝（74Wh，3C 合规上限，不买更大的——>100Wh 过检有风险）；
- 动力电池从 6Ah 升 **8Ah（96Wh，仍在 100Wh 线内）**，+¥30 +0.3kg；
- 合计 **170Wh → 理论 24h，留 20% 余量后 ≈ 20h** ✓

**三个使能技术**（按工作量排序）：①RK 分级休眠（stop YOLO daemon + governor 切换，10W→3W，一个 systemd 脚本）；②X3 Pro 电机按需起转（不扫描时停转，省 ~1.5W）；③S3 深睡 + BLE/按钮唤醒（柜台过夜用，可选）。

**兜底**：12V 包快换结构（§12.2 已设计）——固件没做完也能靠中午换电撑满全天，20h 是"不插电目标"而非硬门槛。

**形态备注**：细高桅杆 + 载物篮 + 侧面喷涂/贴膜即可与"智能车/RM 车"明确区分；柜台模式的 LED 呼吸就是"活着"的最低成本表达。时间线：10 月底 V1 demo → 11 月 V2 底盘联调 → 12 月整机 + 续航模式 → 寒假前富余。

### 12.6 寒招任务画像与优先级重排（2026-10-07）

> 定位澄清：**载物助手是主任务，展示是副产品**。核心痛点 = 一个人去寒招搬物料的窘迫（易拉宝+物料箱+背包没法一手抓）。

**载物清单驱动设计**（篮子尺寸由它定）：
- 宣传物料箱 ~30×22×15cm（篮内）；易拉宝 Ø15×120cm（**篮外：侧面卡槽/横托位，不能塞篮里**）；小礼品/水瓶/自用包（篮内分层）
- **两侧提手**：校门台阶/减速带/安检传送带都有"手提一下"的时刻，5kg 必须可单人提
- 交互极简：网页面板"跟/停"两键够用；装货=停稳而已

**优先级重排**：
1. FOLLOW 稳定性 + 人群 person 过滤 + 超声急停（真实拥挤走廊，没人给你调参的机会）
2. WAIT/BESIDE（摊位边停机守物料，owner_id 锁定同时是**防盗叙事**："它只跟我不跟别人"）
3. HIDE/世界模型/雷达 daemon → 寒招后
4. 柜台 LED 呼吸 → 降级为彩蛋

**"不动声色"的技术支持**：随手弄的底气 = 理线干净 + 贴膜 + LED 微呼吸，DIY 感藏进结构感里。另：高中生围观是必然的，那不是炫耀事故，是**最好的招生宣传现场**——准备一段 30 秒的"这是啥/咋做的"电梯稿，寒招素材里最硬的一条就是你本人。

## 13. 雷达 × HIDE 亲和度打分场（2026-10-07）

> 背景：[世界] 线计划把 HIDE 选点升级为"亲和度打分取最大"（安全/低打扰分高→连成路径→HIDE 取最近最高分），规则=贴墙边、远离门、远离路中间、远离可能交互的物品。本节回答：雷达如何逐条喂饱这个打分场。

### 13.1 规则 → 雷达原生特征对照

| 打分规则 | 相机/现状 | 雷达原生定义 |
|---|---|---|
| 贴墙边 | 无直接观测（80cm 高度看不见墙地交界） | 墙线段提取 → 距墙分带：0.25–0.5m 高分；<0.15m 剐蹭惩罚；>0.8m 离墙惩罚（=占道） |
| 远离门 | door_v3 Hough（1–2Hz，340–1570ms，怕光照） | 门=墙上缺口，5–10Hz 免光照，门心径向 1–1.5m 惩罚区（进门动线） |
| 远离路中间 | 无直接观测 | 平行双墙→走廊中心带惩罚；局部自由半径大→"开阔区"惩罚（人流高概率） |
| 远离交互物品 | YOLO-World 慢环 1Hz 给语义 | 语义锚进极坐标（精确 bearing/dist）；未识别的墙面凸出物→轻度惩罚兜底 |
| **新规则（雷达独有）** | — | ①凹墙/refuge 检测（墙线内凹=天然藏点）；②**可见性遮挡分析**（在累积地图上算候选点是否在门/owner 视线内——"不引人注意"第一次可计算）；③通道宽度（候选点最小可通行宽度） |

### 13.2 架构级提升（对 world 现有三层）

1. **几何层换心脏**：hough 门检测的三个痛点（光照敏感、延迟 340–1570ms、杂乱场景 3.5s 飙升）全部绕开——门在雷达里是几何缺口，不需要图像。YOLO-World 的 door 检出继续当语义层，雷达当几何验证（door_v3 角色平移，接口不变）。
2. **grid_polar 升原生**：8 扇区×3 距离环的相机版 → 雷达原生 360°、每圈 ~500 点，扇区数/环数可加密度不增加算力；`free_directions_deg` 从"推断"变"实测"。
3. **滚动地图获得锚定（最深的一条）**：geometry_map.py 目前靠 IMU 航向积分累积，漂移让地图"糊"；扫描匹配给每帧快照一个"世界坐标系锚"，地图不再 smear，TTL 30s 可以放宽——这是 HIDE 选点质量的天花板提升。

### 13.3 执行闭环（选点之后）

选点 → 路径 = 亲和度梯度上升 + 占据格 A*（可走性由雷达射线投射实测）→ 到达验证（"距墙 0.3m、门口方向无人"）→ HIDE 中持续监控门扇区/owner 方向的腿级聚类 → 触发再评估（re-hide）。hri_state 获得完整反馈环，而不是开环走到标定点祈祷。

### 13.4 边界与互补

- **玻璃门穿透**：雷达看不见玻璃门——恰是相机/door_v3 的主场，两层互补而非替代；
- **单线 38cm 高度**：只见腿级平面，桌面以上、台阶高差不可见；人 vs 椅腿的语义仍归 YOLO；
- **动态障碍分层**：人会污染静态地图，需快/慢环分离（现有三层频率设计正好容纳）。

### 13.5 研究点

亲和度打分 = 手工设计的 social costmap（ROS nav2 的 social layers 是先例，可引作对照）。雷达让每个打分层的输入**可测量**（距墙/距门/通道宽/可见性），研究问题从"能不能躲"升级为"哪些层重要、权重如何因文化/场景而异"——用户研究可校准权重，这是可发表的增量；也与 world/README 引用的 DIV-Nav/OpenVox/OneMap 语义网格架构同构，雷达是它们的标准几何底座。

### 13.6 集成方式（接口哲学不变）

geometry_daemon 新增第四源 `lidar`，几何类标签（free/blocked/wall/door-gap）优先级最高；grid.json v1 字段全部可由扫描表达（objects[].bearing_deg/dist_m、grid_polar、free_directions_deg、map.doors），**消费方（hri_state 亲和度打分）零改动**。落地顺序：B1 相机找门（已交付）→ 雷达 daemon 上线替换几何源 → 扫描匹配锚定滚动地图 → 可见性分析。

### 13.7 打分场增量规则与文献（2026-10-07，已入码）

## 14. 暗光降级模式与传感器分工（2026-10-11）

> 动机：相机在暗光下**不是"看不见"，而是产生幻影**——宿舍夜景实测 **95/98 帧含幻影 person**（错误目标比缺目标危险得多，会主动追错人）。
> 本节把"暗光怎么办"落成可执行的分层降级 + 传感器分工，服务 `DEMO_PLAN §3`（风险 1/3）与 Phase C 互补矩阵实验。

### 14.1 四层能力 × 传感器可胜任矩阵

| 能力层 | 超声波(HC-SR04) | 毫米波(LD2410级) | 2D 激光(X3 Pro) | 相机(低照度+IR) | BLE/UWB |
|---|---|---|---|---|---|
| 安全（别撞） | ✅ 正前 ~15°、2-4m | ⚠️ 有回波但方位粗 | ✅ **360°、5-10Hz** | 需光照 | — |
| 在场/接近（有人吗/在靠近吗） | ⚠️ 近距 | ✅ **最佳：6-8m、穿薄遮挡、免光照** | ✅ 但人须在 38cm 扫描面 | ✅ | ✅ 身份+粗距 |
| 目标粗定位（哪一侧/多远） | ❌ | ⚠️ 距离可、方位粗 | ✅ **腿级聚类**（经典腿部跟踪） | ✅ | ⚠️ UWB 可精定位 |
| 身份 / 朝向 / 手势 / 语义 | ❌ | ❌ | ❌ | ✅ **唯一来源** | ⚠️ 仅身份 |

**结论**：前三层可被非视觉传感器接管；**第四层（身份/朝向/手势/语义）只有相机 + BLE/UWB**——所以暗光不是"换个人掌管"，而是**降级到受限行为集**。

### 14.2 光照分级 → 降级阶梯（L0→L3）

| 级 | 判据 | 主传感器 | 允许行为 | 禁止行为 |
|---|---|---|---|---|
| **L0 正常** | 相机 conf 正常、无幻影 | 相机 + BLE | FOLLOW / WAIT / HIDE / RECEIVE 全功能 | — |
| **L1 临界** | 相机 conf 下降 或 幻影率升高 | 相机 + BLE **身份门控** | FOLLOW / WAIT | **禁 HIDE 语义选点**（怕幻影选错点）→ HIDE 降为原地等 |
| **L2 暗光降级** | 相机不可信（幻影率高/曝光失效） | 毫米波在场 + 激光/超声安全 + BLE/UWB 身份 | **慢速跟走**（限速）/ 原地等(wait_owner) | **禁 HIDE 语义选点、禁 RECEIVE**、禁快速接近 |
| **L3 感知失效** | 无有效传感器 / 全遮挡 | — | STOP + 原地等 + 提示（声/光） | 一切运动 |

**切换纪律**（防抖）：**退化立即生效**（安全优先），**恢复需持续 N≥3s 满足上级判据**才升回——避免明暗边界来回抖动导致行为震荡（与 [HRI] 的施密特去抖/驻留时间同一套原则）。

### 14.3 相机侧优先修（性价比序）

1. **demo 期（零成本）**：定白天 + 固定动线 + 同场地彩排（`DEMO_PLAN §3` 现场对策）
2. **低照度传感器 + 主动 IR 补光**（V2 §10.4 已选型，120° 广角模组）→ **直接把相机拉回 L0**，比加任何雷达都便宜有效
3. 雷达 / 毫米波：**冗余兜底 + L2 能力来源**，不是主方案

### 14.4 接口：让决策知道"现在是几级"（纯增量，消费方零改动）

  ```json
  "mode": "normal | dark_safe",
  "sensors": {"camera":{"ok":true,"conf":0.8,"age_s":0.1},
              "lidar":{"ok":false}, "ultrasonic":{"ok":true}, "mmwave":{"ok":false}}
  ```

### 14.5 验收与实验设计（Phase C 互补矩阵）

## 15. 桅杆顶端安装与隔震（80cm 相机/云台，2026-10-07）

### 15.1 振动分频段，各找各的解

按激励频率分三段（估算条件：顶端质量 ~350g = STS3215×2 + 相机 + 打印支架）：

| 频段 | 来源 | 对策 |
|---|---|---|
| <5Hz | 启停俯仰、行走晃动 | **刚度**：桅杆一阶弯曲频率抬到激励带之上 |
| 20–200Hz | 520 齿轮啮合（电机轴 6000+rpm）、电刷嗡声 | **隔振**：云台底座硅胶减振垫/防振球（¥5 级），舵机带宽管不了这个频段 |
| 冲激 | 麦轮辊子过瓷砖缝 | 隔振垫 + 过缝限速（固件） |

### 15.2 桅杆一阶频率实数（悬臂 + 顶端集中质量）

f₁ ≈ (1/2π)√(3EI/L³m)，L=0.68m、m=0.35kg：

| 桅杆 | 估算 f₁ | 判定 |
|---|---|---|
| Ø12×1 铝管（原占位） | **~5Hz** | ❌ 落在启停/晃动放大带（放大 1.04–1.56×） |
| Ø12×1 钢管 | ~8.5Hz | 可用但重 |
| **Ø15×1.5 铝管** | ~8.4Hz | 可用（平价推荐） |
| **15×15 铝型材(2020)** | **~17Hz** | ✅ 最优，螺栓直装，¥10/米 |
| 任意杆 + **一根斜拉撑**（桅杆 z≈60cm → 上层板后部，打印接头+M3 拉杆） | **×1.5–2** | ✅ 最便宜的刚度来源 |

### 15.3 安装结构（从上到下）

1. **相机绕 tilt 轴配平**：重心压在转轴线上——不平衡的头在急停/前倾时会因舵机有限力矩而点头，配平零成本消掉这组晃；
2. **减振垫两道**：云台底座与桅杆顶之间夹 TPU 打印件或 4 颗硅胶防振球（无人机同款），螺柱穿橡胶垫圈；相机与 tilt 支架之间同理——高频段全在这里滤掉；
3. **桅杆顶夹块**：双抱箍（≥30mm 抱合长 + M4 夹紧），材料优先 PETG（PLA 长期受载蠕变），抱箍到云台座不要留细长悬臂；
4. **桅杆底**：底座块螺栓穿透两层板（或加角码）——底部 1° 摇头到顶端放大成 6°+，底关节必须零晃动；
5. **线缆纪律**：USB/舵机线沿杆扎带固定 ≥2 点、中间留服务环（松弛圈）——绷直的线既是振动桥也是千次弯折后的断线隐患（USB 接头已属已知脆弱点）。

### 15.4 验证方法（免费）

- **敲击试验**：拨杆看衰减，手机加速度计录 FFT 找 f₁，改设计前后对比；
- **激光点试验**：相机座绑激光笔打到墙上，行驶看光点抖动——"震不震"直接可视化。

### 15.5 升级结论

- **相机：升，一次到位**——IMX307/OS02A10 类 120° 广角低照度 USB 模组（§10.4）；附加要求：M12 镜头座（留换镜升级位）、IR-CUT、1080p30（YOLO 输入仍 640，高分辨率留给录制/回放）。卷帘快门在运动下有轻微果冻效应，但平价 USB 侧基本买不到全局快门模组——靠补光 + 限速缓解，不值得为它升级。
- **云台：V2 的 STS3215×2 够用，不需要再升**。让它"更像 RM"的下一步**不是换更好的舵机，是换架构**——无刷直驱 + BGC 板（§4.3，¥150–200，V2.5）给世界系指向与硬件自稳；舵机路线上限（齿隙 0.5–1°、10Hz 级带宽）用配平 + 隔振已经吃满。寒招前不动这条。

### 15.6 篮子一体式桅杆方案（相机高度 80 → 65cm，2026-10-07 定案变更）

**结论：采纳"以篮子为基准、整体绑一体"的结构，相机降到 60–70cm（取 65cm）。** 三条收益：

1. **一提即走**（原"随手一提"叙事的完整化）：2× 2020 铝型材导轨（¥10/米）沿上层板前后铺两条，**4 点以上螺栓锁死在板上**；线篮用扎带/卡扣坐在导轨之间；桅杆是一根 2020 立柱、角码锁在导轨前端；提手做在导轨端头。**导轨是承力件（5kg 提起不靠线篮的铁丝）**，线篮只装货不承重——这样"提起来"是提整台车，相机/云台/篮子一起走，不打架。
2. **刚度暴涨**：立柱从 68cm 降到 ~50cm（板上高度），2020 截面 f₁ **~28Hz**（原 Ø12 铝管 68cm 只有 ~5Hz）；且立柱两端都锁在导轨上（底部角码 + 中部抱箍），等效双支撑，比悬臂再高一档。**§15.1 的 <5Hz 频段问题直接消失**。
3. **65cm 反而更合适当前跟随距离**（几何重算，配 120° 广角模组、中位微抬 5°）：顶缘 +35° → **全身入画 ≥1.5m**（80cm 方案要 ≥2.0m）；地面可见 ≥1.4m；**手部信号（0.6–1.2m）落在画面中心带**——对 pose/伸手意图识别的画面利用率比 80cm 更好。代价：近地 <1.4m 的脚下视野必须靠云台下压换取——LiDAR 平面（38cm）本来就管近场障碍，分工无冲突。

**云台中位策略**：跟随态微抬 5°（看全身+手）；近距交接/HIDE 下压看地；§15.3 的配平与两道减振垫不变。**外形副作用**：总高从 82 → ~70cm，更像"带小潜望镜的篮子车"而非旗杆，地铁/安检/搬运都更友好。落地：导轨+角码 ¥20–30，模型待基座到货后与 230×305 底座、探头轮距一起重排（立柱高度参数 lens_h 80 → 65）。

### 15.7 雷达安装位：为什么是"篮后短柱 38cm"（2026-10-07）

先排除法（2D 雷达需要一个**干净的水平扫描面**，只有平面上的东西遮挡它）：

| 方案 | 遮挡 | 结论 |
|---|---|---|
| 电子层（两层板之间，~6–14cm） | 铜柱、板体、电机全在平面上 → 多楔形盲区 + 近距假障碍 | ❌ 你的判断对 |
| 上层板上（14–20cm） | 线篮侧壁（16–30cm）落在平面里 → 大扇区全盲 | ❌ |
| 下层板底下（<6cm） | **四个轮子**（0–8cm 全断面）各挡 ~12°，共 ~48° | ❌ 最差 |
| 桅杆顶部 ≥65cm | 无遮挡但"头上顶个转盘"；地铁/视觉都突兀 | ❌ 你的判断对 |
| **篮后导轨端短柱，平面 z≈38cm** | **只有桅杆**（40cm 外，~4° 楔形，且朝正前方=相机的主场） | ✅ |

**为什么 38cm 这个高度神奇**：它是全车结构的一个"空层"——线篮顶 30cm ✓ 在平面下、导轨/上层板 ≤16cm ✓ 在平面下、轮子 8cm ✓ 在平面下、桅杆以上在平面外。**唯一穿过 38cm 平面的结构就是桅杆本身**，40cm 距离外只挡 4° 楔形，且方向正对相机视野。物理上已经接近零遮挡的极限。

**落地三条**：
1. **安装**：2020 导轨后端的角码 + 一根 ~22cm 短铝柱（或 2020 立段），雷达座用开槽孔留水平微调（平面必须水平，倾斜会变成"斜切环"）；位置在篮后正中，跟随场景下人回头看，那只是"篮子后面齐膝高的小传感器"——和线篮同色同高，读作篮子的零件，不是"头顶转盘"。
2. **软件遮罩**：桅杆楔形在扫描里是**固定角度区的近距回波**，daemon 里加 `angle_mask`（10 行配置）按角度屏蔽，比机械规避省事；所有固定自遮挡都走这条路。
3. **"一直在转"消解**：X3 Pro 扫描电机支持按需启停——柜台/待机模式停转（省 1.5W、多半续航账里的项），行走时才转；再视觉上等于"静止的小圆柱"。

**一句话**：不放在"层"上，也不放在"顶"上，放在**篮子后缘、齐膝高的短柱**上——那里是全车唯一的几何空层，遮挡只有 4° 且可遮罩，视觉上归入篮子的结构语汇。

**✅ 2026-10-07 决议修订（采纳用户方案，15.7 上位方案作废）：雷达藏进两层板夹层**

关键原理（此前漏说）：**支撑件只要整体位于扫描平面之下就不构成遮挡**——§15.7 的缺陷不在支撑，而在桅杆穿过了 38cm 平面。用户方案（雷达放底层板元件上方、贴近上层板）恰好满足这条，且更优：

1. **结构**：层间距从 8cm 加到 **12cm（M3×120 铜柱，零差价）**；雷达坐在下层板小基座（~4cm）上，扫描平面定在 **z≈13.5cm**（距上层板底 4cm 防边缘擦碰/回波，距下层板面 8cm）。12cm 净空同时让元件/走线更从容。
2. **遮挡清单（逐项核过）**：电机 4.5cm ✓ 在平面下；电池顶 9cm ✓ 在平面下（留 4.5cm 余量）；轮子顶 8cm ✓；上层板 17.5cm ✓ 在平面上方且不接触平面；**桅杆/篮子全在平面之上 ✓ 不遮挡**。剩余唯一遮挡物 = 4–6 根铜柱（Ø6 @ 17.5cm ≈ **每根 2°**，合计 8–12°）→ `angle_mask` 一行配置屏蔽。
3. **"一直在转"消解于建筑**：雷达罩在两层板之间，从上方/下方完全看不见，只有侧面 12cm 缝隙偶尔瞥到——比任何外置安装都隐蔽。
4. **附带收益**：上层板抬高 4cm → 桅杆板上段从 ~49cm 缩到 ~47.5cm（更刚）；柜台模式仍可停转。
5. **验收两条**：①雷达本体高度 < 夹层净空 − 基座高（12 − 4 = 8cm 给本体，X3 Pro/LD19 均满足）；②平面必须水平（基座开槽可调），否则远端会切到上层板边。

### 15.8 层间距 8→12cm 的代价核算（2026-10-07）

| 项 | 影响 | 判定 |
|---|---|---|
| 重心 | 上层组（板+篮+货+桅杆 ≈2.7kg）抬高 4cm → 整车重心 15.2 → **~17.1cm**（估） | 静态倾覆加速度 0.79g，控制限 0.3g，余量 2.6× → **无碍** |
| 载物空间 | 板面不变、篮内不变；篮口 30→33.5cm 但**总高不变**（相机仍 65cm，桅杆板上段反而缩短 4cm） | 无损 |
| 电子空间 | 夹层 8→12cm，体积 +50% | 纯增益（RK/驱动/雷达/走线更从容） |
| 结构刚度 | M3 铜柱抗侧移刚度 ∝1/L³ → **降到原来的 ~30%** | ⚠️ 需补强（下条） |

**补强（零遮挡代价）**：铜柱换 **M4/Ø8**（I 提升 ~2.4×）+ 在 **z≈9cm 加一道中层横撑**（在 13.5cm 扫描平面之下，不新增遮挡）。这样刚度回到 8cm 时代的水平，遮挡仍只有 4–6 根铜柱（8–12° 可遮罩）。

**RM 对照（据已知，规则与校队做法逐年/逐队而异，需按当年规则核）**：RM 的"雷达站"是**场外人员操作的俯视摄像头平台**（给队友在地图上标敌人位置）——不是车载激光雷达，两者别混。RM 主战机器人（步兵/英雄/工程）通常不做 SLAM；**哨兵**（无人操控、守基地的自主机器人）才需要自主定位与结构感知，也是 RM 里 2D 雷达的主要用户：常见装法是底盘层低装（20–30cm）并接受遮蔽扇区，部分队改用 **3D 雷达**（Livox Mid-360 类）装顶部——垂直 FOV ~40°，遮挡只切一层、其他层补看，此即"又要高处又要 360"的正解。关于场地是否直接下发坐标：早期赛季有定位系统，近年更多依赖队伍自研定位（视觉/里程计/雷达），**以当年规则手册为准**。**结论：单线 2D 雷达没人真保证几何 360**，工程实践就是"接受几度盲区 + 角度遮罩"；我们的夹层方案（仅铜柱 8–12°）比多数哨兵的底盘低装更干净。

## 16. 载物需求分级与 V2 能力对标（2026-10-07）

### 16.1 典型载物需求（行业常识估算，非实测数据）

| 分级 | 典型场景 | 重量 | 体积 | 频次 |
|---|---|---|---|---|
| 轻载 | 奶茶+电脑+1–2 小件快递 | 2–5kg | 10–20L | 高频 |
| **标准（甜点）** | **一次超市采购（2–3 袋）/ 驿站取 3–5 件** | **8–12kg** | **30–50L** | 主力场景 |
| 重载 | 大采购 / 大件快递 / 宿舍搬运 | 15–25kg | 60–80L | 低频 |
| 极端 | 桶装水整箱、搬家、被褥 | 25–40kg | 100L+ | 明确放弃 |

对标物：超市大购物篮 ≈40L；折叠拉杆车 ≈25–35kg 承重 / 40–60L；快递 3 号箱 43×21×27cm ≈24L；**Gita 载重 18–20kg / 容积 ~40L / 自重 23kg**（商业标杆的代价是 5 倍于 SC 的自重与占地）。

### 16.2 V2 能力测算（按 §10.1 电机 + §15 布局）

- **重量**：电机侧约 12kg 总质量可爬 8° 坡；**翻倾才是真瓶颈**——5kg 货（篮底 33.5cm）重心 ~27.8cm → 倾覆加速度 0.48g（控制限 0.3g，余量 1.6×）；10kg 货 → 0.43g 且爬坡近满载。**结论：舒适 5kg / 可用 8kg（降加速限值）/ 上限 ~10–12kg（仅平地、低加速）**。
- **体积**：篮内 30×24×18 ≈ **13L**；板上绑扎区再叠 1–2 袋/箱（3 号箱需斜放/绑在板上，塞不进篮）。实际 ≈ **15–20L 封闭 + 额外绑扎位**。

### 16.3 缺口与低成本补法

标准场景（8–12kg / 30–50L）里 SC V2 **重量边缘可达（8kg 可用）、体积差约一倍**。补法（¥0–30）：

1. **轨上加"二层货架横杆/网"**（利用 §15.6 的 2020 导轨承力，不靠铁丝篮）：体积 ×1.5–2，重物仍放底层；
2. **绑扎位纪律**：3 号箱绑板上（斜放）、软袋挂导轨端——体积弹性靠"绑"不靠"装"；
3. **明确产品分级叙事**：SC = "轻载陪伴 / 顺路捎带"档，不做"大采购替代品"——Gita 那档需要 V3（更大轮径+更宽轮距+555 级电机）才谈，别在 V2 上硬追。

## 17. 产品定位："解放双手双肩" + 轮组切换路线（2026-10-07）

### 17.1 定位表述（比"跟随购物车"更锋利）

**"解放双手双肩"** —— 命名的是*收益*不是*机制*。三个场景各自抛出一组硬需求：

| 场景 | 用户原话 | 派生需求 | V2 满足度 |
|---|---|---|---|
| 快递 | 多件不怕堆叠滑落 | 围栏/分层/绑扎位 > 平板；抗颠簸 | ✅ 篮子+绑扎（§16.3）；建议篮沿加挡边 |
| 购物 | 袋子不勒手 | 近身低速精细位姿（横移/并排）、RECEIVE 递接、手伸得到 | ✅ 麦轮正中靶心（§11） |
| 通勤 | 肩上的电脑/相机包解放 | **持续 1.2–1.4m/s 步速** + 人流 + 台阶 + 安检 | ⚠️ 速度不够（见下） |

**通勤的速度缺口（诚实发现）**：520/1:30 + 80mm 轮负载极速 ≈ **1.0–1.1m/s（慢走级）**，正常步速 1.2–1.4。补法两条：①换 **100mm 麦轮** → 1.3–1.4m/s，代价是行驶高度 +1cm、**爬坡扭矩余量从 1.84× 降到 1.46×**、轮子贵 ¥40–60；②留 80mm，通勤定位为"慢走级"，急的时候抓手柄同行。**V2 维持 80mm（寒招/商场坡道余量优先），通勤列为 V3 驱动力。**

### 17.2 "双类型轮子自动切换"：留念想，但要留对方式

| 方案 | 成本/复杂度 | 判定 |
|---|---|---|
| **手动快换轮组（推荐 MVP）** | 麦轮与普通轮共用 6mm D 轴轮毂，4 颗螺丝 ≈2 分钟；固件加一个模式位（MEC↔差速运动学） | ✅ **现在就能做**：多买一套普通轮 ¥45，写一个 mode flag。叙事上就是"给车换鞋" |
| 半自动（快拆卡扣 + 电接口） | 轮组做成卡匣，pogo pin 供电/编码器 | ⭕ V3 可选，+¥150–300，增重 |
| **自动切换（每角伺服翻转双轮/举升副轮）** | 4 套机构 + 4 个执行器 + 重标定，≈+0.5–0.8kg、+¥300–600，且吃掉载重与可靠性预算 | ❌ V2/V3 都不做；这是"变形轮"研究课题（PackBot 式可变形轮一脉），单独立项才合理 |
| 取消切换：爬坡/速度需求交给 V3 大底盘 | ¥0 | ✅ 与"SC 不做运货怪物"（§16.3）一致 |

**留接口不留机构（¥0 的正确"念想"）**：V2 把**轮/电机安装做成标准模块接口**（4 螺栓 + 统一线序），这样 V3 无论选哪条路（快换、卡匣、还是变形机构）都不用重做底盘。轮组切换的真正价值不在机构，在**同一台车能按任务改变性格**——这件事用 2 分钟的螺丝就能先实现。

### 17.3 定位与研究前提的互锁（写论文时可用的一句）

README 的核心洞察是"肢体语言即接口"——而**拎着袋子的人没有肢体语言可读**（手被占用、姿态被负载锁死）。"解放双手双肩"因此不只是产品卖点：它让 implicit interaction 的输入信号（伸手、转身、步态）重新可用。产品价值和研究前提在这里是同一件事的两面。

### 17.4 快递场景：真正的对照组是"手抱"和"拉车"（2026-10-07）

用户原话："没有 SC 的时候，一次拿多个快递只能双手抱着叠起来、还担心掉；用拉车手感又很奇怪。"——**所以要打的两个靶子不是"没有容器"，是两种"你伺候它"的方案**：

| 方案 | 手 | 注意力 | 典型崩点 |
|---|---|---|---|
| 双手抱叠 | 双手占满 | 全程担心掉落 | 没法扫码/开门/掏钥匙；码放与卸货都费劲 |
| 拉车 | 一只手常驻 | 要管方向和倾倒 | 万向轮乱飘、小轮颠/吵、台阶闸机狼狈、拖行速度受限 |
| **SC** | **两只手都空** | **零**（自动跟随/驻留） | 待验证：人群中的驻留鲁棒性 |

**价值主张一句话**：拉车解放一只手，SC 解放两只手**外加注意力**——"你伺候它" vs "它伺候你"。

**取件动线反推出的需求（按动作顺序）**：
1. 扫码/报取件码 → SC 必须**稳定驻留**且不被路人碰动（WAIT 的人群鲁棒性）；
2. 拿到 3–5 件大小不一的包裹 → 装货面在手边（并排/横移定位，麦轮的活）；
3. 码放怕滑、怕互相压 → **弹力网罩/交叉绑带**（¥10–15）比加高围栏更快装快卸、适应异形件；
4. 上下台阶、过闸机、**地铁安检** → 快拆篮 + 导轨提手：**篮可取下单独过安检机，车体走人工通道**（"随手一提"设计的第二个用途）；
5. 回程跟随 → FOLLOW 稳定性 > 一切花活。

**装货高度**（人因，待实测验证）：篮底 33.5cm 需要弯腰，与拉车平台高度相当（拉车也要弯腰）——先接受平价，实测若抱怨明显，V3 再谈更高的装载位（代价是重心）。

**这条场景重新确认了优先级**：快递取件 = 旗舰用例（§16 的"3–5 件 / 8–12kg"正中其中），购物 = 第二，通勤 = 远期（受速度限制）。小改动清单：网罩 ¥10、篮沿挡边、快拆结构、WAIT 驻留鲁棒性（HRI 侧）。

### 17.5 篮子的自由度：哪一半是科幻，哪一半是周末项目（2026-10-07）

按"加一个自由度"拆开评估（"自动升降/自动解锁/自动递上"）：

| 幻想部件 | 实现 | 成本/工期 | 判定 |
|---|---|---|---|
| **篮升降**（30cm 行程，载 5kg） | T8 丝杆（导程 2mm）+ 2 根导轨 + 520 级电机；**小导程丝杆自锁**，断电不下坠，保持不耗电 | ~¥100 / +0.5kg / 周末级 | ✅ **非科幻**，且是**装货高度人因问题的正解** |
| **自动解锁**（快拆锁扣、网罩释放） | 舵机拉销 或 电磁铁 | ¥20 / 一晚 | ✅ 非科幻 |
| **自动递上** | = 已有 RECEIVE 迎上（底盘横移）+ 升降到腰高姿态 | ¥0（复用升降） | ✅ 非科幻 |
| **自动抓取**（机械臂从篮里取出物品递到手上） | 需要操作臂 + 抓取感知/规划 | ¥300 级做不到可靠 | ❌ **这里才是科幻**：抓取是独立研究领域，不是加个舵机的事 |

**关键论证（为什么升降值得进路线图）**：§17.4 标出的"装货要弯腰"与"载物抬重心"是同一个矛盾的两头——**固定高度的篮子只能二选一，只有升降能两头都要**：行驶时降到底（重心低、稳定），装货/递接时升到 75–85cm（不弯腰、姿态得体面）。商业跟随车不做它，是因为每加一个自由度的成本（重量+失效模式+标定+固件）是非线性的——但目前这条恰好解决一个真实痛点，属于"值"的那一类。

**现在花 ¥0 留的接口**：V2 把篮子做成**导轨上的滑动小车**（两个滑套/轴承座 + 一个定位销），而不是直接锁死——今天用销钉固定；V3 要加升降时，把销钉换成丝杆螺母即可，底盘和篮子都不重做。**寒招前严格执行"只留接口不做机构"**。

### 18.1 环境级发现（比场景结果更重要）

### 18.5 幻影注入场景（phantom，2026-10-12）——逻辑层封笔前最重要的一发

复刻实机宿舍夜景失败模式（30s 采样 95/98 帧含幻影 person）：控制器新增检测层噪声注入——每拍以 `SIM_PHANTOM_RATE`（phantom 场景默认 0.35）概率在车前随机位置生成存活 3-10 拍的假 person 框（成簇、conf 0.55–0.9），进检测列表与网格快照；`SIM_PHANTOM_SEED` 固定可复现。

**结果：两个种子（7/8）一致打崩 demo 链**——HIDE 与 RECEIVE 从未触发，状态机只在 FOLLOW↔WAIT 之间弹跳（"主人恢复移动"反复出现），认主回退暴露 44/48 拍。

**机理（日志+代码定位，精确到通道）**：
1. owner.json 新鲜时，`_pick_owner` 的 IoU 匹配路径稳定选真主人 ✓（幻影不影响）；
2. 但**主人短暂不可见 → owner.json 过期 → 回退到"取 conf 最高 person"**——幻影（conf 0.55–0.9）由此被收编为"主人"（每次暴露记 `phantom_adoption_risk`，两种子合计 44/48 拍）；
3. 收编后 `sm_cx/sm_w/approach_mps` 全被幻影污染：框位置跳变 → 宽度反推速度爆表 → `static_now=False` → **静止计时器反复清零** → "主人持续静止 20s"永远攒不够 → HIDE 无法触发 → 无 HIDE 则无 RECEIVE。
4. 网格侧：幻影 person 进了 grid objects，但 §18.3 已证 person 无打分权重 → 亲和度层对幻影零反应（双重缺口互相加强）。

**这正是实机夜景病根的仿真复现**，且精确验证了 gimbal README 当时的预判："根治依赖 owner 模板质量或更稳的 ReID，长期方案=码盘/IMU 里程计让**位置连续性**成为最强过滤"。

**修复方向（框架级，决策归 HRI 线）**：
- 最小修：`_pick_owner` 的 conf 回退路径加**位置连续性闸**——候选必须与 `last_owner_cx`/上一帧框位置连续（一行的距离/ IoU 门槛），幻影随机位置天然过不了；
- 中期修：RECEIVE/YIELD 等高敏状态在 owner.json 过期时**冻结而非回退收编**（宁可不动，不可认错人）；
- 长期修：里程计/地图提供位置连续性先验（V2 的 ENC 遥测正是为此）。

## 19. V2 电源与接线全拓扑（2026-10-12）

### 19.1 总图（一图走全链路）

```text
┌─【动力域】12V 8Ah 成品锂电(带BMS, DC5521/XT60 输出)
│    └─ XT30 ── 7.5A 慢熔保险丝 ── 船型开关(≥10A) ── 12V 端子排(母线)
│         ├─→ A4950 双路模块 ×2 (VM=12V, 共 4 路) ──→ 4× JGB37-520 电机
│         ├─→ XL4015 降压 #1 → 7.4V/3A ──→ STS3215 云台 ×2 (菊花链)
│         └─→ MP1584 降压 #2 → 5V ──→ A4950 逻辑 VCC ×2 模块
│    GND ──────────────→ ★ 星形地汇流柱(下板 M4 铜柱)
│
├─【电子域】20000mAh 充电宝(3C, 双口)
│    ├─ 口1(5V/3A) → USB-C → KickPi RK3566 →(USB 口再带)相机 / S3
│    ├─ 口2(5V/2.4A) → USB → X3 Pro 雷达
│    GND(USB 负端) ─────→ ★ 同一个星形地汇流柱
│
└─【信号层】(跨域共地只走一根"地参考"= ★, 电流各回各的电池)
     RK3566 ──USB CDC── S3         (ASCII 协议; USB 负端是天然参考点)
     S3 UART1 ──→ STS3215 ×2        (串行总线菊花链, 单 GPIO)
     S3 GPIO ×8 ──→ A4950 ×2        (每路 IN1/IN2, 其中一路作 PWM; 20kHz 超听域)
     S3 I2C(GPIO10/21) ──→ MPU6050  (3.3V)
     S3 GPIO ×4 ──→ 4× 编码器 A/B   (PCNT 正交解码 ×4)
     S3 GPIO ×2 ──→ 超声波 TRIG / ECHO(*5V 需分压*, V1 老坑)
     编码器 VCC 取 S3 的 3.3V       (hall 板支持 3.3–5V, 免电平转换, 信号不过 5V)
```

### 19.2 三域设计原则

1. **分域供电、单点共地**：电机（12V 域）与电子（5V 域）各自回各自电池，**不共用电流路径**——这是"防落电"的本体；但**共地是必须的**（信号要有参考电平），且在**一点**（星形地柱）汇合，避免地环流经信号线。注意措辞：这是"分域+星地"，**不是电气隔离**（隔离要光耦/隔离电源，本车不需要）。
2. **跨域的线只有三类**：信号线、USB 地、雷达/相机数据线——它们携带的电流极小（mA 级），不会把电机波动带回电子域。
3. **动力线走线下、信号线走线上**：电机双绞、远离编码器线与 USB 线；编码器线双绞（有屏蔽更好）。

### 19.4 接线要点与坑（按重要性）

1. **保险丝值**：4×520 正常运行 ~2A、加速峰值 ~6A、四轮同时堵转理论 12A（短暂）→ 配 **7.5A 慢熔**（早期文档写的 5A 会误熔）；成品包 BMS 过流是第二道闸。
2. **A4950 逻辑 VCC 取自动力域降压 5V**（不让驱动板从充电宝取电）——保证驱动板自含于动力域，跨域只剩信号与地。
3. **降压模块出入都加电解电容**（100–470µF；云台轨 1000µF 缓冲 STS3215 堵转峰值）。
4. **STOP 语义**：A4950 双 IN 低 = 滑行（省电、平地自然），双 IN 高 = 刹车（防溜坡）。demo 平地建议**滑行**，坡道场景给固件加"刹车模式"；450ms 超时停走同一条路。
5. **超声波 ECHO 分压**（V1 老坑，别忘）；编码器 VCC 用 3.3V（S3 引脚不耐 5V）。
6. **S3 选型核对**：EP32-S3 **DevKitC-1**（引出 30+）优先；SuperMini 引出可能不够 21 根（8 驱动 + 8 编码器 + 2 I2C + 1 云台 + 2 超声 = 21）——下单前数引脚。
7. **验收三步（上车前，万用表）**：① 两电池地是否只在星地柱一点相连（防通过 USB+信号线形成环路）；② 空载各轨电压（12.0 / 7.4 / 5.0 ±5%）；③ 电机堵转测试时万用表盯云台轨电压（应纹丝不动——这就是"落电"与否的判据）。

### 19.5 充电宝双路供电的耦合问题与对策（2026-10-12）

**核心事实：便宜充电宝的"双口"常常不是"双路"** —— 很多是把同一路 boost 分到两个插口（规格写"2 口同时 5V/2.4A **总**"就是标记）。共享一路时，一个口的负载瞬变会调制另一个口的电压，这就是"颤抖"的机理来源。

**谁会抖、抖成什么样**：

| 源 | 受影响方 | 症状 |
|---|---|---|
| 雷达扫描电机纹波（唯一带电机的电子域负载） | 相机（同域） | 画面条纹/掉帧、USB 带宽报错 |
| 同上 | RK 的 USB VBUS | **S3 跟着抖**（S3 由 RK USB 供电——V1 落电模式的 V2 变体） |
| 剧烈跌落（<4.4V 持续） | 全体 | USB 重新枚举、雷达断流 |
| 另：低电流自动关机 | 全体 | 负载 <50–100mA 时充电宝自动断电——**柜台待机模式（§12.5）会静默断电**，20h 续航方案必须防这一条 |
| 另：热插拔第二口 | 已在用的口 | 部分充电宝插第二个设备瞬间会**瞬断**已用的口 → RK 重启 |

**对策（按成本排序）**：

1. **选对充电宝（¥0）**：挑"双口同时输出"且总功率 ≥18W 的 3C 型号（如 20000mAh 22.5W 档），每口独立标注 5V/2.4A+——余量大 → droop 小；确认无低电流自动关机，或有"小电流模式"（双击）。避免热插拔第二口时瞬断的型号。
2. **雷达支路加 π 滤波 + 电容（¥3，必做）**：磁珠/10–47µH 电感 + 470–1000µF 电解 + 0.1µF 瓷片，做在雷达电源入口——把唯一的电机纹波源就地摁住，不污染同域其余负载。
3. **雷达改挂 12V 域降压供 5V（¥8，彻底方案）**：让雷达回动力域（纹波只污染自己那片），电子域只剩纯静态负载。代价是多一个降压模块。
4. **相机若出条纹/掉帧**：USB 线里并 470µF 或换短粗线。
5. **验收三场景实测（¥20 USB 电压电流表）**：① 只开 RK（YOLO 跑）；② 只开雷达；③ 双开——盯 5V 是否稳在 4.8V 以上；配合 `dmesg | grep -i usb` 看有无重新枚举；雷达自带可视化看扫描环是否干净。

### 19.6 供电耦合的定量分析（2026-10-12，续 §19.5）

> 说明：充电宝内部架构无官方资料，以下为电路第一性原理估算 + 社区通行做法；最终以 §19.6.4 的实测程序为准（本 session 无联网检索条件）。

#### 19.6.1 谁在"颤抖"：先分清三笔账

5V 域负载功率预算（估算）：RK3566+YOLO 连续 7–9W、相机 0.5–1W、X3 Pro ~2W（起转瞬时 0.8–1A）、S3（经 RK USB）0.3–0.8W → **连续 2.0–2.6A，峰值 ~3.5A**。压降来自三处，按贡献排序：

| 来源 | 量级 | 说明 |
|---|---|---|
| **线材+接插件 IR 压降（主犯）** | 1m 28AWG USB 线双股 ≈0.42Ω → **2A 时压降 0.85V** | 5.0V 只剩 4.15V——低于多数 USB 器件 4.4V 门槛。**换短粗线（≤30cm，20–22AWG）比换充电宝有效得多** |
| 充电宝口径流/总限流（次犯） | "总 5V/2.4A" 的库 → 我们峰值 3.5A **超限** | 触发折返/限流 → 周期性跌落 = 真正意义的"颤抖" |
| 共享 boost 的负载瞬变耦合（第三） | 典型 50–200mV 跌落，百 µs–ms 级恢复 | 只在"两口共一路"的库上存在；雷达电机纹波由此污染相机/RK |

**结论**：你担心的"共路耦合"是真实存在的，但排第三；**先用短粗线把账算清，再判断是否需要换库或加滤波**——很多"充电宝供电抖动"案例的根因其实在线材。

#### 19.6.2 为什么不能干脆砍掉充电宝（设计约束回顾）

电子域 12W × 20h = 240Wh > 12V 包 96Wh（§12.5 的 20h 依赖两包合计 170Wh）；而单包若做大到 240Wh 就**超 100Wh 安检线**。所以双源不是图方便，是"总能量够 + 单包可过检"的唯一解——那就必须把充电宝这条链做扎实。

#### 19.6.3 三个候选方案（按代价）

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| A. 单库+电容 | 选"双口同时输出总 ≥22.5W"的库 + RK/S3 电源入口并 470–1000µF + 雷达支路 π 滤波 | ¥8 | 库的总输出 ≥4A（5V）时首选 |
| B. **PD 口诱骗独立供雷达** | 库的 PD 口(20W) → PD 诱骗器(9V/12V) → 5V/3A 降压 → 雷达 | ¥15–20 | 想让雷达彻底脱离共享路——**性价比最高的"分路"**，雷达电机纹波被自己的 buck 隔离 |
| C. 雷达回动力域 | 12V → 5V buck → 雷达 | ¥8（多一个 buck） | 电子域追求"只剩纯静态负载"时的终极形态 |

#### 19.6.4 实测程序（拿你自己的库定案，30 分钟）

1. 两只 ¥20 带记录的 USB 电压电流表，分别串在两个口上；
2. 三场景各跑 2 分钟并记录**最低电压**：① 只开 RK（YOLO 在跑）；② 只开雷达；③ 双开；
3. 判据：全程 min ≥4.75V → 通过（加电容即可）；4.5–4.75V → 换短粗线 + 加电容后复测；**<4.5V 或 `dmesg` 出现 usb 重新枚举 → 上方案 B/C**；
4. 顺带验两条充电宝行为：**低电流自动关机**（柜台待机模式让负载降到 <100mA，看库是否断电）与**热插拔第二口的瞬断**（插第二个设备时第一个口上的 RK 是否重启）——两条都影响 §12.5 的 20h 方案。

### 19.7 接线载体：面包板否决与三档替代（2026-10-12）

1. 接触电阻 0.05–0.5Ω/触点，标称载流 ~1A（廉价板 0.5A）——动力轨 2A 连续/6A 峰值 → **触点发热、压降、塑料软化**，正是 §19.5/19.6 "颤抖"的又一来源；
2. 振动下跳线松脱 = **间歇性故障**（demo 现场最难查的一类）；
3. 跳线普遍 26–28AWG → 恰好命中 §19.6.1 的 IR 压降主犯（0.4Ω+）。
   ——面包板唯一合法用途：**台面逻辑验证**（I2C 扫描、引脚点灯、编码器数脉冲），永不随车。

### 19.8 洞洞板 vs 面包板 + 焊接施工要点（2026-10-12）

**最主要的一个区别**：面包板靠**弹簧夹持**（插接、可逆、但有**隐性内部连接**——中间一排 5 孔互通、两侧电源轨整条连通）；洞洞板靠**焊锡**（永久、可靠、但**没有任何内部连接**——每个孔独立，走线全靠自己规划）。实践含义：面包板的门槛是"搞清哪些孔本来就是通的"，洞洞板的门槛是"先在纸上画连线图"。其余差异：

| 维度 | 面包板 | 洞洞板 |
|---|---|---|
| 接触/载流 | 0.05–0.5Ω/触点，~0.5–1A | mΩ 级，走粗线可过 10A+ |
| 振动 | 松脱（间歇故障） | 牢固 |
| 可逆性 | 随便改 | 解焊才能改 |
| 寄生 | 触点电阻 + 排线并排耦合 | 小且稳定 |
| 正确用法 | **台面逻辑验证**（点灯/扫 I2C/数脉冲） | **装机固化** |

**选购提示**：需做电源母线就买**条状连接板（stripboard，每 3–5 孔连通，可当现成母线）** + 一张**双面镀铜独立孔板**（灵活走线）；孔距必须 2.54mm。

**焊接要点（按容易翻车的顺序）**：

1. **耗材**：有铅 63/37 或 60/40 焊锡 0.6–0.8mm（学生项目首选有铅，183°C 好焊不易冷焊）+ 松香/免洗助焊剂；**不用酸性焊锡膏**（腐蚀）。
2. **温度**：恒温烙铁 350°C（有铅）/ 370°C（无铅）；细尖头焊信号、刀头焊端子/粗线；**焊 XT30/端子排这类大铜件要 60W 以上功率**（细烙铁焊不动，会焊成冷焊）。
3. **四步动作（2–4 秒完成）**：烙铁同时贴住焊盘+引脚预热 1–2s → 焊锡丝送到**焊点**（不是送烙铁头）→ 铺成小锥形后先撤锡丝 → 再撤烙铁。单点别超 5 秒。
4. **好焊点**：光亮小锥形、包住引脚。**坏焊点**：冷焊（灰暗粗糙球状=虚接，振动后开路，最坑）、锡桥（相邻焊盘连一起=短路，2.54mm 孔距最常见）、过热（焊盘起皮/器件变色）。
5. **线材接法**：**线头预上锡 + 焊盘预上锡 → 对焊**，这是最可靠接法；硅胶线优选（耐热不熔皮）；焊完检查有没有烫伤线皮。
6. **洞洞板专项**：① 先在纸上画连线图（无内部连接）；② 电源走**背面母线**（粗线/裸铜线横跨），信号用细线贴板走直线；③ 背面交叉处必须套热缩管绝缘；④ 12V 进出板别只靠细铜箔，加飞线加粗；⑤ 元器件面/连线面分层，别悬空跨线。
7. **上电前必查（30 秒，能救一块板）**：万用表蜂鸣档测 **12V 对 GND 是否短路**、相邻孔是否锡桥；首次上电串保险丝或限流电源，摸温度（烫手=有问题），再测各轨电压。
8. **安全**：通风（铅烟）、护目镜（剪脚会飞）、斜口钳剪引脚（别用剪刀）、烙铁用完上锡保养不乱放。
9. **练习**：先在废板上焊 20 个点再上真板——这条最省时间。

### 19.9 洞洞板装配工艺：外露电路的处理 + 元件/导线焊法（2026-10-12）

#### 19.9.1 裸板"电路外露"的三类风险与处理

| 风险 | 处理 |
|---|---|
| 背面飞线被金属底板/车体勾到或短路 | 尼龙柱/铜柱架高 ≥5mm（背面朝车体内部）；或背面盖一层亚克力/环氧绝缘片（再加一层柱）；最稳：**整板装进小塑料盒，接线端子朝外** |
| 焊接的线在振动下从焊点根部疲劳断裂（洞洞板机器人最常见故障） | **应力释放**：线必须在板边用扎带固定，机械力由扎带承担、不由焊点承担；线束套编织网管；细信号线焊点根部点一滴热熔胶（避开发热件） |
| 硬线反复弯折断裂 | 用**硅胶线**（软、耐热），避免单股硬线/劣质 PVC 线 |

#### 19.9.2 直插元件/排针怎么焊

1. **顺序铁律**：先焊**矮的**（飞线母线、电阻、跳线）→ 再焊**中等的**（IC 座/排母、小电容）→ 最后焊**高的**（电解电容、端子排、JST 座）——反了的话高元件会挡住矮焊点。
2. 元件从**元件面**插入，引脚从**焊接面**露出 1–2mm，掰弯 15–30° 固定（或蓝丁胶/胶带临时固定）。
3. 焊点做锥形，剪掉多余引脚（斜口钳）。
4. **排针/排母垂直定位技巧**：把排针插在**面包板上**（面包板在这里的合法用途）+ 洞洞板套上去焊 → 保证垂直；多脚元件先焊**对角 2 脚** → 检查贴平垂直 → 再焊其余。
5. S3 用**排母座**焊在板上（不要直接把模块焊死）——可更换、可维修。

#### 19.9.3 导线接上去的三种做法（按线径选）

| 做法 | 适用 | 步骤 |
|---|---|---|
| **穿孔焊** | 细线（26–28AWG）且能穿过孔 | 剥 4mm 上锡 → 从焊接面穿入 → 孔隙里填锡熔合 |
| **贴盘对焊** | 穿不进的粗线（20–22AWG 动力线） | 线头预上锡 + 焊盘预上锡 → 线贴焊盘烙铁压熔 1–2s 成一体 |
| **铜线母线** | 电源轨（洞洞板标准做法） | 裸铜线/粗线横跨一排焊盘，每个要连的点补一锡；12V 进出板用 20AWG 飞线 + 足锡，不靠细铜箔 |

**两条不翻车的细节**：① **先套热缩管再焊**（焊完才发现没套 = 经典翻车）；② 每根线焊完立刻在板边做扎带应力释放。

#### 19.9.4 本项目装配顺序（照抄即可）

1. 纸上画布局：12V 进 → 保险丝座 → 开关 → 端子排母线 →（A4950 ×2 / 降压 ×2）；S3 排母；编码器 JST ×4；云台 JST ×1；I2C JST ×1；
2. 焊矮件：背面 GND 铜线母线（**就地实现 §19 的星形地**，各 GND 就近点焊）+ 电阻/跳线；
3. 焊排母/端子排/JST 座（用面包板或排针辅助定位垂直）；
4. 焊高件：电解电容（注意极性）、端子排；
5. 背面走线 + 热缩 + 板边扎带应力释放 + 网管；
6. **上电前蜂鸣档查短路 → 限流/串保险丝首次上电 → 测 12/7.4/5V 三轨**（同 §19.4 验收三步）。

| **tilt 轴配平 + 两道减振垫** | ★★★★☆ 消急停点头/高频振 | ¥5 | **已定**（§14.3）✓ |

| **世界系指向（软件：底盘跟随云台）** | ★★★★ | ¥0 | 免费，随 V2 follow 改造落地（§5.2） |
| **yaw 360° 连续旋转**（滑环 ¥20–40 + 结构） | ★★★ | +滑环与走线复杂度 | ⭕ **可选**：只在采用"云台持续指向主人 + 底盘任意转向"时才必要；当前救援式凝视（±45° 扫描）与限位方案够用，且底盘跟随云台会把 pan 保持在中心附近——**等 follow-mode 落地后再评估** |
| **pitch 360°** | ✩ | — | ❌ **无用**：跟随需要的俯仰区间约 −45°(看地)~+30°(看脸)；360° 只会拍到车自己和篮子底部，且线缆会被拧断——机构换来的自由度没有用户价值 |
| **3 轴（加 roll）** | ★★ | ¥150+ | ❌ 平地轮式机器人 roll 扰动小，性价比低 |
| 更大负载/更大相机 | ✩ | — | ❌ 相机 ≤50g，STS3215 的 19kg·cm 早已过剩 |

**结论：pitch 360° 不做。** 云台的正确升级顺序是 **平滑 → 配平/隔振 → 无刷自稳（V2.5）→（可选）yaw 滑环**；真正的"稳"来自**无刷直驱 + 云台 IMU 闭环**，不是把某根轴转满 360°。

## 22. 里程计是什么 + 云台要不要第二个 IMU（2026-10-14）

### 22.1 里程计（odometry）：用传感器推算"我从哪走到哪"

- **定义**：不依赖外部地图/定位系统，用轮子编码器和 IMU 的增量**积分出位姿 (x, y, θ)**，即航位推算。俗称"码盘里程计 + 惯性里程计"，二者融合（互补滤波/EKF）后输出一条连续的轨迹。
- **V2 的硬件正好齐了**：4× JGB37-520 的霍尔编码器（11PPR×4×30 ≈ **1320 counts/转**，80mm 轮 → **0.19mm/count**）+ MPU6050 航向角速度。S3 用 4 路 PCNT 硬件计数，100Hz 积分 + 麦轮运动学 → 发 `ENC`/`ODOM` 遥测给 RK。
- **为什么它是幻影的根治**（引 gimbal README 原话"码盘/IMU 里程计让位置连续性成为最强过滤"）：如果车知道自己走了 0.5m，那么一个"凭空出现在 2m 外"的 person 框就是**物理上不可信**的 → 位置连续性成为最强的假阳性过滤器；仿真里 `_pick_owner` 回退收编幻影的问题，最小修法正是加位置连续性闸。
- **诚实的误差**：麦轮靠辊子侧滑工作 → 轮式里程计在横移/转向时**打滑误差大**；纯码盘漂移约 2–5% 里程，融陀螺航向后车头方向好很多；再上扫描匹配（雷达 L2/L3）才能长期无漂。**别指望 V2 的里程计是"绝对定位"**，它是"短时连续 + 可信度闸门"。
- **用途优先级**：① 幻影/位置连续性过滤（HRI）→ ② 世界模型滚动地图锚定（配合扫描匹配）→ ③ 前瞻跟随控制（论文方向）。

### 22.2 云台要不要第二个 IMU？——不是"上不上"，是"别混"

**两个 IMU 是两套参考系，天然不该融合到一起**：

| 传感器 | 测量对象 | 配什么参考 | 用途 |
|---|---|---|---|
| 底盘 IMU（MPU6050，车架） | 车体航向角速度 | 编码器 + 麦轮运动学 | 航向闭环、里程计融合、世界模型 |
| 云台 IMU（装在 pan 台，桅杆顶） | **相机指向**的角速度（含底盘转动+云台pan） | pan 角 + 自身积分 | 相机世界系指向（vision 方位解码）、抖动测量、V2.5 无刷自稳 |

**"打架"的真相**：传感器之间冲突通常来自三件事——① **混参考系**（把云台 IMU 当车体航向用：底盘一转它就读错）；② **混时基**（V1 的四条扰动通道，gimbal README 已记录：旧帧光学角 + 新云台角 → 假误差）；③ **乱信任**（不设门限地把两个估计平均）。**分层 + 各自参考系 + 统一时间戳 + 门限/协方差**才是解药；加第二个 IMU 本身不解决打架，只会多一个"打架源"。

**V2 建议**：
1. **底盘 IMU 必上**（航向环 + 里程计，已定）；
2. **云台 IMU 作为"测量通道"上，先不闭进控制环**（¥8–30，MPU6050 或 ICM42688）：它的第一价值是**量出相机实际抖动量**（§14 的敲击/激光点试验有了仪器版），第二价值是给"云台世界系指向"提供不依赖 pan 标定的观测，第三价值是 V2.5 接 BGC 自稳时的现成传感器。**先测量、后闭环**——这就是避免打架的纪律。
3. **电气细节**：同总线两个 MPU6050 → AD0 接 GND/VCC 得 0x68/0x69；I2C 上桅杆 60cm 用 **100kHz + 2.2k 上拉（板端）+ 双绞**，不稳就换**串口 IMU**（JY61P/HWT101 类，¥60–100，UART 抗干扰强）；IMU 用泡沫胶/TPU 减震安装（§14 的教训）。
4. **不要**：3 轴 IMU 融合替代航向环、用云台 IMU 做底盘航向、把两路角速度直接平均。

### 21.10 集成 DC-DC 模块值不值得买（2026-10-18）

**先看真实需求**（§19.10.1）：12V 直通（电机，峰值 6A）、**7.4V/2–3A**（STS3215 ×2）、5V/≤0.5A（A4950 逻辑）。**3.3V 根本不需要独立轨**——S3-DevKitC-1 自带 3.3V LDO，MPU6050/编码器/云台 IMU 全从 S3 的 3V3 取，这条很容易被"12→5/3.3 双路板"误导去买一个用不上的轨。

| 方案 | 覆盖 7.4V？ | 12V 直通能力 | 价格 | 判定 |
|---|---|---|---|---|
| **分体：XL4015(7.4) + MP1584(5) + 电容** | ✅ | 电池直连端子排，不经模块 | ¥25–35 | ✅ **推荐**（坏一个换一个） |
| 固定双路板"12→5V/3.3V" | ❌ **没有 7.4V** | 通常不达标（板载走线/端子按 2–3A） | ¥10–20 | ❌ 云台轨还得再加一个模块，等于没省 |
| **2–3 路可调降压板**（12V 入，每路可调） | ✅（调 7.4/5） | 需确认 12V 直通端子 ≥10A | ¥25–40 | ⭕ 可选的"省接线"方案 |

**价格账**：便宜板看着省，是因为它**不含**保险丝座/开关/端子排/电容，也不提供 7.4V——同口径比价其实差不多（¥25–40 vs ¥25–35），省的只是接线工夫，不是钱。

**若买集成板的验收三条**：① 7.4V 路带两个 STS3215 堵转（~3A 峰值）时电压跌落 ≤0.3V、满载 10 分钟温升可接受；② 12V 直通端子的持续电流 ≥8A；③ 输出纹波/输出电容是否够舵机瞬态（不够就自己并 1000µF）。**故障隔离**要注意：一块板挂了所有轨一起挂，分体方案则各自独立——demo 期这是加分项。

**结论**：保持分体（XL4015 调 7.4 + MP1584 调 5），或买"多路可调板"图省线；**不要买"固定 12→5/3.3"双路板**，它既不解决云台轨也没有你需要的大电流直通，3.3V 那一路更是用不上。

### 21.11 电池电流规格的真实账（修正 §21.9 的"持续 ≥10A"）（2026-10-18）

**电机电流事实**（JGB37-520 / 12V / 1:30，厂商规格）：**额定 ≤1A/台，堵转 ~2.3A/台**。

| 工况 | 每台电机 | 四台合计 | 备注 |
|---|---|---|---|
| 正常跟随/巡航 | 0.3–0.6A | **1.2–2.4A** | 主要工况 |
| 加速峰值（1–2s） | 1.5–2A | **6–8A 瞬时** | PWM 缓启会拉平 |
| 四轮同时堵转（理论极端） | 2.3A | **~9.2A** | 450ms 超时 + 声呐急停应避免 |
| 云台（经 buck 折算到 12V） | — | 平均 ~0.3A、峰值 ~2A | 短时 |
| **合计** | | **持续 2–4.5A；瞬时 6–8A；极端 ~11A** | |

**正确规格**：
- **持续放电 ≥5A**（覆盖 2–4.5A 并留余量）——**不需要 10A 持续**；
- **过流保护（BMS 跳闸阈值）≥10A**（覆盖 6–8A 加速瞬时，避免"一加速就断电重启"）；
- 容量 8Ah（能量账按 §12.5 的平均功率算，与电流峰值无关）。

**关于"几节电池串并联出来的"**：3S2P/3S3P 18650 是标准做法，本身没问题。8Ah 的 3S3P 每节只承担 ~1.7A，**1C 就够**——关键不是电芯数量，而是 **BMS 的持续/过流标称**。便宜包的坑是"持续 3A / 峰值 5A"这类（加速即跳），而不是串并联结构。

**两个坑**：① 不要买"持续 3A"的监控类小包（参数虚标常见）；② 不必买无人机高倍率包（贵且无必要，5A 持续已够）。

| 方案 | 技术 | 安全/运输 | 判定 |
|---|---|---|---|
| **航模 3S LiPo**（裸包，XT60，20–50C） | 电流随便够（5A 需求对它毫无压力）、便宜、轻 | **无 BMS**（过放/过流/短路全靠外部）、裸电芯怕穿刺、需平衡充；**地铁安检高风险**（裸包无认证标识，易被拦） | 台面/家里测试 ✅；**寒招地铁 ❌** |

### 21.13 实拍案例："3C 认证 12V 2550mAh 成品包 ¥56"——合规但动力不够（2026-10-18）

| 项 | 数值 | 判定 |
|---|---|---|
| 形态 | 成品外壳 + **3C 认证** + DC5521 输出 | ✅ 安检友好（DC5521 恰好配我们的转接线） |

| 定位 | **台面/电子测试包、备件、应急** | ✅ 可以买，但别当动力包 |

**要买动力包，认三个数**：容量 **6–8Ah**、**持续 ≥5A**、**过流保护 ≥10A**，且带 3C/外壳/DC5521。6Ah（72Wh）是 demo 日的可接受档（约 2–3h + 热换），20h 目标要 8Ah 或柜台低功耗模式（§12.5）。搜索词："12V 6Ah 锂电池组 3C 认证 带保护板" / "12V 磷酸铁锂 6Ah 成品 3C"。

### 21.14 到底怎么找电池：三个疑问 + 搜索词 + 被忽略的最优解（2026-10-18）

**疑问 1：为什么商品页写"不适合循迹小车"？**
不是电池本身差，是三个真实限制 + 一句免责：① **BMS 限流 3–5A**（电机启动/堵转超了就断电保护，要拔插恢复）；② **DC5521 接头额定只有 3–5A**（大电流会发热压降）——这两条决定了它天生不适合动力；③ 小容量包内阻大，大电流压降大；④ 商家怕退货，统一写"动力类勿用"。

**疑问 2：6 节电池的包算"大包"吗？**
**不算。** 安检看的是 **Wh 和认证**，不是节数：3S2P（6 节 18650）≈ 5Ah ≈ **60Wh**，远低于 100Wh 线。6 节包被拒的原因不会是"大"，只可能是"无标识/无 BMS/裸电芯"。

**疑问 3：电赛用什么？**
电赛小车常见就是 **3S/4S 带保护板的 18650 组** 或 **3S 航模包**；安全靠"人盯着 + 低压报警 + 专用充电器"，**不纠结 3C**（比赛不坐地铁）。所以"便宜没 3C"的路线在校园场景是常态，不是异类。

**找法的硬指标（三条，缺一不可）**：
1. **BMS 持续 ≥5A、过流保护 ≥10A**（问客服要这两个数）；
2. **输出必须是 XT60/XT30，不接受 DC5521**（接头额定 3–5A，是隐藏瓶颈）；
3. 容量 **6–8Ah**（3S = 11.1V 标称 / 12.6V 满，对口 12V 系统）。

**搜索词直接抄**：
- `12V 6Ah 锂电池组 XT60 保护板`
- `12V 6Ah 磷酸铁锂 成品 XT60`
- `12V 动力锂电池组 大电流 保护板 XT60`
- `3S 18650 电池组 6Ah 保护板 XT60`

**被忽略的最优解：电动工具电池包 + 底座**
12V 电动工具电池（3S 2–4Ah）**设计上就是 10–20A 放电**，有认证标识、可快换（底座 ¥10）、单价 ¥40–80/个。容量小（24–48Wh）但**热换 2–3 个就覆盖 demo 日**；寒招现场换电池比换整包体面。这是"高电流 + 安检友好 + 便宜"三者少有的交集。

**如果还是找不到**：自制 3S2P/3S3P + **40A 独立保护板** + XT60 + 电池盒（¥80–130，电赛标准玩法）——但自制包**不要带上地铁**，寒招用工具电池/成品 3C 包。

**别往工业级找**：工业级 12V 10Ah+ 带 3C/UL 确实贵，而我们的需求（6–8Ah/5A）消费级就能覆盖。

### 21.23 三个接线/选型快问快答（2026-10-18，未推送）

**Q1：包都送充电器？** 那"两个充电器"就不是问题了——各用各的随包充电器（12.6V/8.4V），别混用。

**Q2：MG996R 能用吗？360° 舵机能不能追 passby？**
- **MG996R（180°）**：位置控制、无回读、有死区抖动——就是 V1 现状。预算紧时**先用它顶着**完全可行（相机平滑升级可以等），但别指望"救援式凝视"之外的持续性追踪。
- **"360° 舵机"（连续旋转型）**：**只能调速、不能定角**——它没有位置反馈，无法把相机指向某个角度并保持。**做云台指向 = 不可用**（这是最容易踩的坑：买回来发现"会转但停不住"）。
- **pitch 360° 追 passby 是伪命题**：person 绕着车走是 **yaw（水平）** 问题，pitch（俯仰）360° 只会让相机翻过头顶、拍到车自己和天空，线缆还会拧断。
- 真要"水平 360° 跟人"：需要 **yaw 连续旋转 + 角度反馈**——STS3215 支持**多圈/连续模式并回读位置**，配滑环（¥20–40）走线；但你们的设计原则（95% 冻结 + 边缘救援）本来就不需要它，属于 V2.5 以后的增强。

**Q3：充电宝 GND 怎么共？**
**就通过 S3 一处**：充电宝 → USB → RK → USB → S3，这条链的 GND 本来就是通的；从 **S3 的 GND 引脚拉一根 22AWG 短线到星地柱**即可。**不要再从 RK 单独拉一根到星地柱**——那会形成地环（S3→星地→RK→USB→S3）。
星地柱上汇：12V 包 GND（20AWG）、7.4V 包 GND（20AWG）、S3 GND（22AWG）、A4950 GND ×2、MP1584 GND、电容 GND。电机大电流走"12V 包→A4950→星地→12V 包"的短粗路径，信号回流（mA 级）走 S3→星地，两者在低阻抗星点上交汇，互不吃压降。

### 21.24 MG996R / MG966R 的"没有回读"到底意味着什么（2026-10-18，未推送）

**事实**：这类 PWM 舵机的内部电位器只用于**自身闭环**，**不向外输出**——控制器只知道"发了多少"，不知道"到了多少"。MG966R 与 MG996R 同属这一类（标称扭矩不同，同样没有反馈线）；除非详情页明确写"**带反馈/三线反馈版**"（特殊型号，可问卖家）。

**具体后果**：
1. **角度误差 ±1–3°**（死区 + 齿轮回差 + 廉价电位器非线性），且随负载漂；
2. **无堵转/负载感知**——卡住了也不知道；
3. **无角度遥测** → "云台坐标解码"只能假设"**指令角 = 真实角**"；你们现有的视野方位数学正是建立在这个假设上，误差会直接进 bearing；
4. 抖动只能靠软件限速缓解，没有反馈可压。

**能用吗**：V1 级别的演示（救援式凝视、粗指向）**可以**；要"云台真实读数"（bearing/角度遥测、世界模型、V2.5 自稳）**不够**——这正是当初规划 STS3215 的原因。

**预算紧的三个折中**：
| 方案 | 成本 | 得到什么 |
|---|---|---|
| 先用 MG996R 顶着 | ¥0（已有） | 粗指向；坐标解码推迟 |
| **串行总线小舵机**（STS3032/SCS0009/LX-824 类） | ¥30–50/个 | **位置/速度/负载回读** + 单线菊花链——比 MG996R 贵一点，换来全部 V2 需要的遥测 |
| MG996R + AS5600 磁编码器自测角 | ¥5–8 + 手工改装 | 有角度读数，但安装/标定麻烦，不如直接上串行舵机 |

**结论**：钱紧就先用 MG996R 把车跑起来；一旦要做"云台真实角度/坐标解码"，最少要换到**带反馈的串行舵机**这一档，360° 连续旋转舵机不在候选内（§21.23）。

### 21.25 修正：DC5521 不能当电机包的放电口（2026-10-18，未推送）

| 接口 | 典型额定 | 我们的电流 | 判定 |
|---|---|---|---|
| **DC5521**（5.5×2.1 桶形） | **3A**（好件 5A，杂牌 2A） | 持续 1–2.5A ✓；**峰值 3–5A ✗ 边缘**；全堵转 9.2A ✗ | **只用于充电/云台/低电流**，不用作电机放电 |
| XT30 | 15–30A | 全部工况 ✓ | 可用 |
| **XT60** | 30–60A | 全部工况 ✓ | **电机包首选** |

**修正 §21.15 的表述**："DC5521 也能用"只说对了一半——**持续电流**（1–2.5A）在 3A 额定内，但**加速峰值 3–5A 会顶到/超过额定**（发热、压降、接触不良），全堵转更不用谈。

**正确做法**：
1. 电机包**走 XT60/XT30 输出**（多输出款直接用 XT60；只有 DC5521 的款，要么改接 XT30，要么只当充电口）；
2. **先确认 DC5521 是"充放电同口"还是"充电专用"**——若是充电口，严禁接电机；
3. 即便接口是 XT60，也看一眼**包的出线线径**：20AWG 约 3–7A、18AWG 约 7–10A；10A 档建议 18AWG 以上；
4. 云台包（0.3–0.5A）用 DC5521 完全没问题。

### 21.26 为什么"10A 保护板 + DC5521"不矛盾（2026-10-18，未推送）

**BMS ≠ 接口**：
- **BMS 的 10A 是"过流切断阈值"**——它保护电芯不因过放/短路烧毁，是最后一道保险；**不是"输出能力承诺"**。廉价板上"10A"常指切断点，持续能力可能只有 5A 甚至 3A。
- **接口/线径决定实际载流**：DC5521 ~3A、XT30 15–30A、XT60 30–60A。**真实可用电流 = min(BMS 持续能力, 接口额定, 线径)**。

**双口是分工，不是冗余**：这类包同时给 XT60 和 DC5521，意图就是"**大电流走 XT60，小设备/充电走 DC5521**"。BMS 的 10A 是给 XT60 这条路的保护。

**从 DC5521 抽大电流会怎样**：接口接触电阻先发热/压降、塑料软化/接触不良（"咔擦"），而 BMS 还没到 10A 阈值不动作——**接口先死，BMS 后动**。商家"不适合动力"的免责声明说的就是这件事。

**对我们**：电机走 XT60（BMS 10A 是瓶颈，峰值 6–8A 刚好）、云台走 DC5521（0.5–1.2A）——**两者各在其位**。若实测包的保护板虚标（5A 就跳），降加速限值即可。

### 21.27 DC5521 转接 vs 改接：哪些有用、哪些是自欺（2026-10-18，未推送）

| 做法 | 成本 | 载流瓶颈 | 判定 |
|---|---|---|---|
| **转接头**（DC5521 公→XT30/端子/鳄鱼夹，¥5–10） | 低 | **仍是 DC5521 插头本身（3A）** | ✅ 只用于"负载端接线方便"；❌ **不能提升电流**——插头那一段没变 |
| DC5521 一分二 | ¥6–10 | 总 3A | ✅ 仅两个小负载（云台+小设备） |
| **剪线改接**（剪掉 DC5521 头，焊 XT30/XT60，热缩） | ¥0 + 10 分钟 | 线径 + BMS | ✅ 要让这个口出大电流，只有这条路；20AWG≈3–7A、18AWG≈7–10A |
| 用转接头把 5521 口喂电机 | ¥5 | 3A | ❌ 自欺——转成 XT60 也还是 3A 的插头在瓶颈 |

**极性**：这类包标准是**内正外负**（商品页也常写"内红线正极"），**接之前万用表量一次**，别信颜色。

**我们的用法**：电机走包的 **XT60 口**（不动 5521）；云台用 DC5521（0.5–1.2A）刚好；若云台线端是裸线/端子，买一根 "DC5521 母→端子" 转接线即可，¥5。

### 21.28 剪线改接调查：DC5521 → XT30/XT60（2026-10-18，未推送）

**先说结论**：**双输出（XT60+5521）的包不用剪**——电机走 XT60、5521 留给云台/充电。剪线只在"只有 5521 但要大电流"时才考虑，而且**先过三个检查**。

#### 三个决定性检查（剪之前必做）
1. **充电口是不是同一个 5521？** 很多包是"**充放电同口**"——剪了就没法充电。→ 若同口，**不要剪**，改做"**并联加接**"（见 §21.28.3）。
2. **线径多少？** 剪完瓶颈就从插头变成线：**20AWG≈3–7A、18AWG≈7–10A、22/24AWG≈2–4A**。如果原线只有 22/24AWG，**剪了也白剪**（线才是瓶颈）。
3. **包里有 XT60 吗？** 有就根本不用剪。

#### 21.28.1 真要剪的步骤（安全顺序）
1. **电量放到 ~50%**（满电最危险），台面清空金属屑，旁边备好热缩/胶带；
2. **一次只剪一根线**——两线同时剪会短路（12V 经剪线钳短路，BMS 跳闸甚至打火）；剪完立即套热缩/胶带封头；
3. **万用表确认极性**（5521 标准内正外负，但必须实测，别信线色）；
4. 剥 3–4mm、线头预上锡、XT30/XT60 焊杯预上锡（60W+ 烙铁，XT60 焊杯大）；
5. 焊后**双层热缩**，接头处**点热熔胶做应力释放**（无人机惯例，防焊点根部疲劳）；
6. 上电前：万用表测正负极无短路 → 先接小负载（云台）测电压。

#### 21.28.2 风险
- 剪线=**失去退换**；短路可能让 BMS 锁死（部分包充电才恢复）；
- 烙铁热会烤到电芯/热缩皮——动作要快，别把线烤到烫手；
- **永远不要剥开电池包本体**，只在出线处操作。

#### 21.28.3 更优解：**并联加接，不剪**
保留 5521 做充电，**在 BMS 出线处并一根 XT30 尾线**（焊 + 热缩），放电走 XT30、充电仍走 5521。这样既拿到 20–22AWG 以上的放电通道，又不毁充电口。**这是"充放电同口"包的正解。**

**对你的情况**：两块包都有 XT60 → 直接用好 XT60/5521，**零改动**；以后若遇到只有 5521 的包，优先"并联加接"，其次才是剪。

### 21.29 两包分带：每包带 2 个轮子（电机两两分开供电）（2026-10-18，未推送）

**接法**：12V 包 A → A4950 #1 → M1+M2（左前/右前）；12V 包 B → A4950 #2 → M3+M4（左后/右后）。两包正极各自独立，**GND 同汇星地柱**。

**电流对照**：

| 工况 | 一包带四轮（单 DC5521） | **两包各带两轮（每包 DC5521）** |
|---|---|---|
| 巡航持续 | 1–2.5A | **0.5–1.25A** ✅ 舒适 |
| 加速峰值 1–2s | 6–8A ✗ 远超 3A | **3–4A ⚠️ 边缘（短暂，可接受）** |
| 双轮堵转 | — | 4.6A ✗ 应避免（PWM 缓启） |
| 判定 | DC5521 会热/压降 | ✅ 持续安全；峰值靠缓启压住 |

**三个必须知道的代价**：
1. **峰值仍在 DC5521 边缘（3–4A）**：靠固件 PWM 缓启 + 别急加速；实测接头温热正常，烫手就要降加速；
2. **不对称故障**：一侧包/BMS 跳闸 → 两轮失力、另两轮还在走 → 车会偏转/打转。低速下不危险，但 demo 时要避免单侧过载；
3. **两包必须同款同电量**：不同容量/新旧 → 左右放电快慢不同 → 持续偏航；固件 trim 只能补一点。

**接线成本**：每包需要一根 "DC5521→端子/裸线" 转接线（¥5）或剪线改接（§21.28）接到 A4950 的 VM 端子；充电仍是两包各自随包充电器。

**结论**：¥40–50 档里，**两包分带是可行且更安全的方案**——它把最要命的峰值电流砍半；代价是接线多一套、且要接受"单侧故障会偏航"和"两包匹配"的纪律。**能动就行**的目标下，这个方案成立。

### 21.30 两包分带 → "5A 以下 / 不推荐小车"的包可以用了（2026-10-18，未推送）

**为什么警告不适用了**：商家的"不推荐小车"是按**一包带四轮**（峰值 6–8A、堵转 9.2A）写的。两包各带两轮后：

| 工况 | 每包（2 电机） | 5A 以下 BMS | DC5521（3A） |
|---|---|---|---|
| 巡航持续 | 0.5–1.25A | ✅ | ✅ |
| 加速峰值 1–2s | **3–4A** | ✅（5A 阈值内） | ⚠️ 短暂压线 |
| 双轮堵转 | 4.6A | ✅（阈值内） | ⚠️ 应避免（缓启） |

**所以"5A 以下"的 BMS 够用**——它不会再因为加速跳闸。剩下的唯一边缘是 **DC5521 接头（3A）在 3–4A 峰值时的瞬时发热**，靠 PWM 缓启 + 别急加速压住。

**下单/验收四条**：
1. **BMS 必须写明 ≥5A**（标"3A"的不行；"5A 以下"若实际是 3A 就会跳——到手先小电流跑一遍看跳不跳）；
2. **两包同款、同电量**（分带最怕左右不对称）；
3. **容量按虚标预期**：标 3000mAh 实际可能 1.5–2.5Ah → 每包续航 1.5–3h；
4. **首次跑车摸接头**：温热正常，烫手立即降加速限值。

**成本**：12V 3000mAh ×2 ≈ **¥26** + 7.4V 普通包 ≈ **¥20** ≈ ¥46（充电器随包），在 50 以内 ✓。

**结论**：这套组合成立——**"能动就行"阶段的最优性价比**。它用"多一套接线 + 左右匹配纪律"换掉了"XT60 大电流包"的溢价。

### 21.31 这套 ¥46 配置的续航账（2026-10-18，未推送）

**耗电侧（两包分带）**：每包带 2 电机，**巡航 0.4–0.8A/包**，频繁加速 ~1.2A/包，demo 日均值约 0.5A/包。注意：**分带不增加续航**——每包只承担一半负载，续航仍由"单包容量 ÷ 半边电流"决定。
