## 1. 现状与为什么单独设计

现有唯一避障路径（V1，全部保留不动）：

```text
HC-SR04(正前 ±15°, 2cm 精度) → 固件 UltrasonicSensor → MotorDriver.setObstacleDetected
   → 前向 latch 停车 + 打印 "OBS <0|1> <cm>" → rk_control 读遥测
   → _gaze_drive_loop 倒车脱离（GAZE_ENABLED=False, demo 期未启用）
```

它的能力边界：**一个方向、一个数、20cm 阈值、只看正前**。V2 的雷达带来 360° + 5–10Hz + 8m，
但直接接进去会踩三个坑，这也是本设计的三个立论：

1. **时延链必须显式**（否则"多少米该停"是拍脑袋）。扫描 10Hz（100ms）+ 环 10Hz（100ms）+
   USB/串口（~10ms）+ 固件缓启（~100ms）≈ **t_react = 0.35s**。0.6m/s 时这 0.35s 就吃掉 21cm，
   加上制动 30cm 与保留间隙 8cm → **需要 0.59m 间隙才能跑满巡航速度**。这个数必须写进代码（§4.3）。
2. **禁止双控制器抢底盘**。V1 的教训（`gaze_drive_loop` 与 follow 抢底盘 → 往右拐越拐越偏）说明：
   避障若自带一套运动律，就会和 follow 打架。本设计的解法是**约束层**：不产生新运动，
   只对"别人已经发出的命令"限速或否决。
3. **噪声不得推动整车**。雷达有飞点、玻璃穿透、镜面反射、雨雾；单帧异常必须过迟滞（§4.5），
   这条与 `hri_state` 的施密特去抖、`sector_score` 的 freeze 协议是同一套工程原则。

## 2. 传感几何：装在哪、看得见什么、看不见什么

### 2.1 安装（沿用 §15.7 修订版决议）

```text
上层板 z=17.5cm ─────────────────────────────────
                  ↑ 4cm
扫描平面 z≈13.5cm  ← 雷达坐在下层板小基座上（本设计的坐标系原点）
                  ↓ 8cm
下层板 z=5.5cm ──────────────────────────────────
```

- **唯一自遮挡 = 4 根铜柱**（Ø6mm @ 距传感器 17.5cm → 每根 **~2°**）。代码不写死角度，而是
  由 `pillars_xy + sensor_x/y` **自动算遮罩**（含 2° 安装余量），改安装位置只改两行配置。
- **双保险**：铜柱本身在 17.5cm，落在 `range_min_m=0.24` 的近场滤波圈内 → 回波被丢弃；
  遮罩再挡住"柱后 2° 楔形的远端盲区"。两者独立生效，任一条误配都不会漏。
- 轮子（顶 8cm）、上层板（17.5cm）、桅杆、篮子**都不在平面内** → 不需要遮。
- 实测的默认配置里遮罩为 `[[33.9,39.9],[320.1,326.1],[140.1,146.1],[213.9,219.9]]`（±36.9°、±143.1°）。

### 2.2 看得见 / 看不见（这张表就是产品说明书的"能力边界"）

| 物体 | 13.5cm 平面看得见? | 谁兜底 |
|---|---|---|
| 人腿 / 椅子腿 / 桌腿 / 箱体 / 墙 / 门框 | ✅ | — |
| **玻璃门、镜面** | ❌ 直接穿透 | 相机 door_v3 + 超声（互补矩阵主场） |
| **矮于 13.5cm 的东西**（门槛、地漏、躺倒的瓶子、地毯边） | ❌ | 超声（正前）+ 演示时避开 |
| **桌面/台面悬挑**（腿看得见、台面看不见） | ⚠️ 只见腿 | 靠"腿级聚类"保守处理 |
| 台阶**下**（负障碍：向下的落差） | ❌（单线平面原理性看不见） | 场景约束：SC 不做下台阶 |
| 动态物体（人、推车） | ✅ + `closing_mps` 提前量 | — |

**结论**：雷达不是"全知"，它是"腿部高度的 360° 轮廓"。所有失效都必须在 §6 有对应对策与降级，
而不是假装没有。

### 2.3 装车验收 3 条（上车前 10 分钟）

1. **平面水平**：倾斜会变成"远端切到上层板"——软尺量传感器座上沿，两端读数差 ≤2mm；
   或看空场扫描：远点距离环应是一个圆，不是椭圆。
2. **空场干净**：房间中央扫描，`GET /safety` 的 `sectors_m` 应只有四面墙的四个"台阶"，无近距满圈
   （近距满圈 = 平面切到板/柱没被滤掉 → 查 `range_min_m` 与 `pillars_xy`）。
3. **满 PWM 车速实测**：直行 5m 计时 → 填 `configs/lidar_guard.json` 的 `v_at_spd_max`
   （这决定"限速×0.6"到底是多快；填错只是保守/激进，不影响安全逻辑本身）。

## 3. 架构：三段解耦 + 一个收口

```text
 ┌── 扫描生产者(V2b, 待做) ──┐   ┌── 本设计(已备好) ──────────┐   ┌── 已有链路 ────────┐
 │ YDLidar-SDK 桥(aarch64)   │   │ lidar_guard_daemon.py      │   │ rk_control.uart_send│
 │ 读 /dev/ttyUSB0           │──▶│  lidar_guard.update()      │──▶│  _safety_filter()   │
 │ 原子写 lidar_scan.json    │   │  → lidar_safety.json       │   │  → 固件(450ms/超声) │
 └───────────────────────────┘   └────────────────────────────┘   └────────────────────┘
     可独立坏/独立重启                 纯逻辑, 可离线回放              单一收口, 惰性生效
```

### 3.1 为什么收口在 RK 的 `uart_send`，而不是固件

- 雷达挂**电子域**（充电宝 5V + USB），只有 RK 有它的数据；S3 拿不到 → 固件无法直接消费。
- `uart_send` 是所有运动命令的唯一出口（follow / hri_state / 弧线绞合 / 网页面板 / 转身动作），
  在它前面过滤 = 一处生效、无人遗漏，且**各控制器不需要知道雷达存在**。
- **固件层完全不动**：450ms 超时 + 超声 latch 仍是最后一道硬件兜底（V1 已验证，不冒回归风险）。
- 代价要写明白：**雷达只能约束"命令"，不能约束"固件自己"**。若将来要固件级雷达反射弧，
  需要新增 `LIMIT` 通道（§10 待办，V3 再谈）。

### 3.2 惰性契约（demo 冻结期的安全阀）

```text
/dev/shm/lidar_safety.json 不存在  →  过滤是直通, 现有链路行为逐字节不变
文件存在且新鲜                     →  按安全包络限速/停车
文件存在但过期 (>1.0s)             →  视为 stale: 只限速到 degrade_speed_mps(0.3), 不施加停车
过滤链自身异常(文件坏/模块缺)      →  放行原命令 + 一条节流日志, 绝不阻断控制
```

**为什么 stale 是"限速"而不是"停车"**：雷达是**增强件**，基础安全由超声（正前）+ 相机（语义）承担。
若雷达一坏整车就停，等于把雷达变成单点故障——这是产品级错误。但也不能装作没事：
`mode/ok/scan_age_s` 会进 `/safety` 与 grid.json 的 `sensors.lidar`（§14.4），
行为层可以据此降级（例如暗光模式 L2 要求 `lidar.ok=true`）。**cap 还是 stop 是可配置的**
（`degrade_action` 语义在过滤层，`degrade_speed_mps=0` 即等价于停）。

## 4. 核心算法（每条都有对应断言）

### 4.1 预处理（`to_robot_frame`）

原始 `(方位, 距离)` → 去掉：遮罩角（§2.1）、量程外（<0.24 / >8m）、超近自反射、
**同角去重**（单回波雷达一个方位只有一次回波；同方位双点取更近——这同时挡住了
"腿点与墙点交叠"造成的假聚类）、**飞点**（±3° 内无邻点，或与邻点中位距离差 ≥max(0.30, 0.45×中位)
且 >1.2m → 丢；近处一律保留，因为"近处误停便宜、漏停昂贵"）。稀疏帧（<100 点）不做飞点剔除。

### 4.2 净空：矩形车体 + 走廊（`clearance_dir` / `rotation_gap`）

- 车体是 **30×34cm 的矩形**，不是圆。行进方向 θ 的支撑函数直接给"沿行进半长 / 横向半宽"
  （`|cos θ|·L + |sin θ|·W` 等）——比固定半径准确，且能区分"正着走"和"横着走"。
- **四方向间隙**：只统计落在**行进走廊**（横向 ≤ 车体横半宽 + 5cm 余量）内的点，
  间隙 = 沿行进投影 − 车体沿行进半长（**从保险杠量起，不是从车心量起**）。
- **转向净空**：最近点半径 − 外接圆半径 0.227m（原地转扫掠圈）。
- 障碍"已被甩在身后"（投影 < −0.10m）不计。

### 4.3 速度律：间隙 → 速度上限（`v_from_gap`）

制动距离模型 `v·t_react + v²/(2a) ≤ gap − 8cm`（`t_react=0.35s`、`a=0.6m/s²`）的解析解：

| 障碍间隙（从保险杠算） | 允许速度 | 判定 |
|---|---|---|
| < 5cm（硬间隙 `hard_gap_m`） | 0 | **立即否决**（不等迟滞窗） |
| 0.10 m | 0.05 | blocked（低于 `v_min=0.15`） |
| 0.20 m | 0.22 | 限速 |
| 0.40 m | 0.44 | 限速 |
| **0.59 m** | **0.60** | 刚好跑满巡航（`gap_required(0.6)`） |
| ≥ 0.60 m | 0.60 | 不干预（`v_nom`；包络只限不促） |

- 恢复（解除 blocked）需间隙 ≥ `gap_required(v_nom)+0.15 = 0.74m` → 与触发线 0.59m 形成滞回带。
- **`v_nom` 只做"限"，不做"提"**：速度的期望值归 follow/HRI，雷达只给天花板。
- 参数化好处：`a` 从 0.6（舒适）调到 2.0（室内急刹）时，整张表自动收紧，不用改任何逻辑。

### 4.4 动态目标：提前量（lead compensation）

对每个簇做极坐标最近邻跟踪（贪心关联，门 10°/0.6m），EMA 求径向速度：
- 等效间隙 `gap_eff = gap − max(0, closing)·t_react`——"正在靠近的东西"提前吃掉反应距离；
- 输出 `closing_mps / dynamic`；腿级聚类（宽 5–45cm、距 0.3–5m）单独列出 `person_legs`，
  供 HRI/跟随消费（V3 的"腿级人物"能力这次已经顺手拿到）。
- **主人不是障碍**：跟随的正常收敛由 follow 的距离保持负责（目标 1.2m / 实距 <0.7m 停），
  雷达的 stop 只在"制动距离不够"时兜底（例如主人急停、或路人在中途切入）。

### 4.5 迟滞（`_hysteresis`）

- 判定 `blocked` 需**持续 0.25s**（单帧噪声不推动整车）；解除需**持续 0.4s 且间隙回到 0.74m**；
- 例外：间隙 < 5cm（硬间隙）**首帧即否决**——迟滞不能拖住碰撞保护；
- 确认窗内速度上限不放松（否则"确认"期间还能全速冲）。

### 4.6 绕行提示（`escape`）——V2 麦轮的红利位

前方受阻时给出几何最优的脱离方向：`left/right`（带**符号化 vy**，正值向右）+ 可用速度，
全是 `hold` 则"四面受阻，原地等待"。**本设计不自动执行**：提示交给行为层（follow 的横向偏置、
HRI 的 YIELD），因为"往左让还是往右让"是社交决策，不是几何决策。
（V1 差速底盘只能观测；V2 麦轮横移时这条才是可执行的。）

### 4.7 健康：三种非 ok（`mode`）

| mode | 判据 | 为什么需要 |
|---|---|---|
| `ok` | 帧新鲜且有效点 ≥20 | 正常 |
| `stale` | 帧龄 > 0.6s | SDK 进程死了/线松了 |
| **`suspect`** | 有效点 <20（帧却是新鲜的） | **安静失效**：探头被挡、起雾、镜面脏——SDK 照常出版本、照常刷时间戳，但什么也没看见。这条防止"无事发生"被当作"前方畅通" |

## 5. 接口契约（四个，全部纯增量）

### 5.1 扫描帧（生产者 → daemon）`/dev/shm/lidar_scan.json`

```json
{"frame_id": 4211, "ts": 10892.597,
 "points": [[0.0, 2.34], [1.2, 2.31], ...]}      // [方位角°, 距离m]
```
兼容 `{"angles":[...], "ranges":[...]}`（标准雷达输出）。**原子替换写入**（tmp + rename）。

**`ts` 约定用 `time.monotonic()`**（与 guard 内部时钟同源）。2026-10-24 修订：本节旧示例
曾写 epoch 值——guard 按 `now(monotonic)-ts` 算帧龄，epoch 帧的 `scan_age` 恒为 None，
**stale 检测静默失效**（实测踩中，雷达拔线系统仍认为数据新鲜）。guard 现已双时钟兼容
（`lidar_guard.py` update()，T11c/T11d 断言），monotonic 为约定首选，实测记录见附 D。

### 5.2 安全包络（daemon → 命令路径）`/dev/shm/lidar_safety.json`

| 字段 | 含义 |
|---|---|
| `ok/mode/scan_age_s/n_points` | 健康（§4.7） |
| `limits` | `vx_max/vx_min/vy_max/vy_min/wz_max_dps`（SI：m/s、deg/s） |
| `blocked` | `{fwd,back,left,right,rot}` 布尔（已过迟滞） |
| `gap_m` / `rot_gap_m` / `gap_required_m` | 四方向间隙、转向净空、当前速度的需求间隙 |
| `nearest` | 最近障碍（方位/距离/间隙/类别/closing/dynamic） |
| `person_legs` | 腿级行人列表（方位/距离/closing） |
| `sectors_deg` + `sector_m[24]` + `sector_n[24]` | 扇区最小距离（供可视化/调试） |
| `mask_deg` | 生效的遮罩区间（自证配置正确） |
| `escape` | 绕行提示（§4.6） |

### 5.3 命令过滤语义（`apply_to_ascii`）

| 命令 | 语义 |
|---|---|
| `MOVE F/B <spd>` | 前进/后退：对应方向 blocked → `STOP`；否则按 `vx` 包络换算成 PWM 限速 |
| `MOVE L/R <spd>` | **V1 固件语义 = 原地旋转**（坦克转向）→ 受"转向净空/`wz` 包络"约束，**不受横向走廊约束**。V2 麦轮若把左右键改成"真横移"，置 `move_lr_is_rotation=false` 即切回走廊判定（两种语义都已测） |
| `DIFF Lx Ry` | 共模（前进）按 `vx` 包络压到上限；差模（转向）按 `wz` 包络压缩；前进方向 blocked → `STOP` |
| `MEC vx vy wz` | 逐轴钳位（线上单位 cm/s、rad/s ↔ SI 在过滤层换算） |
| `STOP/PAN/TLT/TEL/*` | 一律原样放行（云台与遥测不受避障影响） |

### 5.4 grid.json 的 `sensors.lidar`（§14.4 纯增量，消费方零改动）

```json
{"lidar": {"ok": true, "age_s": 0.08, "mode": "ok", "n_points": 412}}
```

## 6. 失效模式与对策（逐条交底）

| 失效 | 现象 | 对策 |
|---|---|---|
| 玻璃 / 镜面 | 前方空无一人，实际是玻璃门 | 原理性无解 → 相机 door_v3 兜底；`suspect` 只覆盖"几乎无回波"，穿透时反而有回波 |
| 矮物 / 负障碍 | 完全看不见 | 超声正前兜底；场景约束（不做下台阶）|
| 探头被挡 / 雾 | 帧新鲜但几乎无点 | `suspect` → 降级限速 + `ok=false` 上报 |
| 平面倾斜 | 远端切上层板 → 远点假障碍 | 装车验收（§2.3）+ `range_min_m`；诊断看 `sector_m` 是否出现固定半径环 |
| 飞点 / 多回波 | 单点跳变 | 同角去重 + 飞点中位差滤波 + 迟滞 |
| 人群（多点簇） | 一张"人墙" | 逐簇独立判定；窄簇=腿（可绕）、宽簇=墙（只能等）；绕行提示给出方向 |
| SDK 死 / 线松 | 帧不再更新 | `stale` → 限速（cap 模式），`ok=false` 上报，health 可查 |
| 参数填错（`v_at_spd_max`） | 限速比例不对 | 只影响保守/激进，不影响安全逻辑；§2.3 第 3 条标定 |
| 雷达与超声不一致 | 一个说停一个说走 | **取更保守**（两层独立生效，天然"或"逻辑） |
| 主人站在正前 | 车被"避障"卡住不跟 | follow 的距离保持先接管（1.2m/0.7m）；雷达间隙律在 0.59m 才介入 → 不冲突 |

判据（注入窗口 6–26s）：超声全程 CLEAR + 雷达 `blocked.rot` 触发 + 窗口内车几乎没转。

**✅ 2026-10-16 实跑结果（realtime，1 次）**：

## 9. 已知局限与明确不做

- **不做规划**：没有 A*、没有代价地图、不做"绕到目的地"（那是 V3 局部世界 + `sector_score` 的事）。
  本文只做"约束 + 提示"。
- **不做语义**：不判断"这是主人还是路人"（相机/BLE 的事）；只给 `person_legs` 与几何事实。
- **不做 SLAM/建图**：雷达原始帧用 `--record` 落盘供 PC 科研轨离线用，机器人在线**不依赖地图**。
- **单线平面原理性局限**：只切 13.5cm 一层，见 §2.2；这是"廉价方案换来的边界"，写进能力清单而不是藏起来。
- **仿真不能演示麦轮横移**：V1 仿真底盘是差速的，`escape` 只能观测；V2a 麦轮落地后补一个横移绕行场景。
