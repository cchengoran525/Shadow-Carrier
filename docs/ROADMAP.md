## 0. 当前基线（已就绪 ✅）

| 资产 | 状态 |
|---|---|
| YOLO 管线 v7.2 | 11.3 FPS，C++ daemon + /dev/shm + watchdog |
| 视觉跟随闭环 | 差速弧线 `DIFF L R`（v3，基本可用） |
| 云台硬件 | C3 直驱双轴（LEDC 50Hz），`PAN`/`TLT` 命令已部署 |
| 网页面板 | 遥控/跟随双模式 + `/move` 变速接口 + 云台拖拽 |
| 通讯链路 | USB CDC 全双工，uart_reader 持续排空 |
| 服务管理 | systemd ×3：ap-hotspot / rk-control / video-stream |

**已知约束**（影响排期的硬限制）：
1. **C3 固件烧录成本高**——拔板插 Windows（COM3，永远带 `CDCOnBoot=cdc`），所有固件改动必须攒批
2. **串口独占隐患**——`/dev/c3_controller` 目前 rk_control 与 gimbal_follow 各自打开；BLE 遥测上线后成为真实风险。MVP 先不管，坐标解码阶段前必须合并 owner
3. 板端无外网（ICS 共享未开），模型/依赖只能 PC 下载后 sftp 推
4. 板上目录不是 git 仓库，流程固定为：本地改 → git → sftp 推板

## 1. 四条线的定位

| # | 线 | Demo 角色 | 核心产出 |
|---|---|---|---|
| ① | 认主锁主 | 🔴 地基 | `owner_id.py` 三信号打分（BLE RSSI + HSV 直方图 + 体态比） |
| ② | HRI 智慧算法 | 🔴 主线叙事 | `hri_state.py` 行为状态机 FOLLOW / WAIT / HIDE / RECEIVE / YIELD |
| ③ | 世界模型 | 🔴 "躲门边"一环 | 几何快环 + 极坐标网格（有降级路径：手动安全点） |
| ④ | 云台坐标解码 | 🟡 增强（README 明确 demo 不需要） | FOV 粗标定 + bbox 底边/俯仰角 → 距离方位 |

### 依赖关系图

```
        ┌─────────── ④云台坐标解码（FOV标定→方位角）────────┐
        │                                                  ↓
  ①认主 ──→ "目标是谁" ──→ ②HRI状态机 ──→ 行为输出(MOVE/PAN)
   │  BLE/HSV信号              ↑    ↑
   │                      ③世界模型（网格 = "哪里能躲"）
   └── 串口遥测通道(BT <rssi> 上报) ←── 未来超声波TEL同一条路
```

**交叉点清单**：
1. **①→所有**：`owner_score()` 插在 `/api/detections` 与 follow_controller 之间，只换"跟谁"，控制律不动。唯一全局前置。
2. **②↔③ 共享行为接口**：HIDE 问网格"门在哪个扇区"；demo 版可用手动标定安全点降级，③不阻塞②。
3. **③⊂④**：都是"像素+内参→真实方位"。③的 Phase 2（FOV 粗标定→方位角）做完，④完成 80%。④不单独立项。
4. **①激活串口遥测**：C3 BLE 扫描开始吐 `BT <mac> <rssi>` 行——uart_reader 加解析分支存共享变量，为将来 `TEL:` 超声波遥测打样。
5. **C3 固件是公共瓶颈**：①的 BLE 扫描是唯一必做固件改动，与其他固件需求攒一批烧录。

### 稳定接口约定（开工前冻结，四线互不踩）

| 接口 | 生产者 → 消费者 | 说明 |
|---|---|---|
| `/api/detections` | video_stream → ①②③ | 已有，**格式不再变更** |
| `owner_score(person) -> float` | ①owner_id → ②follow_controller | 认主输出；v0 可先恒返回"最大bbox=1.0"占位 |
| `safe_point.yaml` / 后续 `grid.json` | ③world → ②hri_state | v0 就是手动标定的一个点；升级为网格不改消费方 |
| `BT <mac> <rssi>` | C3固件 → uart_reader 解析分支 | 遥测行协议，未来 `TEL:` 同风格 |

## 2. 分批执行计划

### 第 1 批 —— 并行侦察周（互不阻塞，可三线同时）

| 任务 | 线 | 场所 | 退出标准 |
|---|---|---|---|
| A1. AP6255 蓝牙侦察：`hcitool lescan` 10 分钟验证 | ① | 板上 | 能扫到手机 RSSI → 不用动固件；不能 → 固件批次加 NimBLE |
| A2. 点选锁主兜底：网页面板点击 bbox 锁定目标 | ① | 本地+板 | 无蓝牙也能锁定跟随对象 |
| B1. 离线门检测：拍 3-5 张门口场景照，Canny→Hough→垂直线配对调参 | ③ | PC 离线 | 门检出率稳定，阈值范围确定 |
| C1. 手持物检测置信度：果冻/水瓶对摄像头实测 | ② | PC/板上 | 置信度 ≥0.5 → RECEIVE 可行；否则换大目标物 |

### 第 2 批 —— 合流实现周

| 任务 | 线 | 说明 |
|---|---|---|
| F1. **固件一次性烧录** | ① | BLE 扫描上报（NimBLE 后台扫描）+ 任何攒下的固件改动，一次拔插全带上 |
| A3. `owner_id.py` v0 | ① | 先只做"RSSI 最近的人"，HSV/体态比逐个后加、单独可验 |
| S1. 安全点标定 | ③→② | 遥控开到门边一次，朝向+超声波距离存入 settings.yaml |
| H1. `hri_state.py` 四态骨架 | ② | 只订阅 `/api/detections` 打日志不接电机：FOLLOW/WAIT/HIDE/RECEIVE/YIELD 切换准确率观察 |
| W1. `geometry_daemon.py` + FOV 粗标定 | ③ | 低分辨率独立抓帧 30FPS 出几何 JSON；量 FOV 即可不棋盘格（此步顺带完成④的80%） |

### 第 3 批 —— 实车联调周

| 任务 | 线 | 说明 |
|---|---|---|
| L1. 状态机接 `/move` | ② | 完整场景首跑：跟人→主人静止>5s→HIDE(去安全点)→主人缓近+持物→RECEIVE(低速迎上,超声波20cm急停) |
| L2. YIELD 区分逻辑 | ② | 快近+空手=让路 vs 缓近+持物=迎接；核心特征是 bbox 面积变化率 |

### 第 4 批 —— 增强与打磨（demo 之后）

- ④完整版：bbox 底边 + 俯仰角 + 内参 → 米制距离（接物距离控制更稳）

- 修体验债：弯腰误判、低速死区走偏、C3 冷启动分电源、明文密码清理

## 3. 关键判断记录（为什么这么排）

1. **①最优先但最小化**：所有行为都建立在跟对人上，但 demo 版只需"RSSI 最近 + 画面最大"两个信号就能成立，MAC 随机化问题用 ¥10 iTag 信标绕开。
2. **③有降级路径所以敢并行后置**：HIDE 用手动安全点就能演示，完整网格是质量提升不是功能开关。
3. **④被③吸收**：同一套相机几何数学，Phase 2 做完自然长出来，不单独立项。
4. **固件改动唯一化**：整个 MVP→Demo 只有 F1 一个必做固件批次（BLE 扫描），把拔插成本压到一次。
5. **PC 离线工作前置**：B1/C1 零板上风险，且结论直接决定第 2 批要不要调整方向。

## 4. 风险登记

| 风险 | 概率 | 缓解 |
|---|---|---|
| AP6255 板载蓝牙不可用 | 中 | 直接走 C3 NimBLE（原 README 计划），调试期辛苦些 |
| 手持小物体 YOLO 检出率低 | 中 | C1 提前验证；不行就换香蕉/盒子等大目标，demo 叙事不变 |
| iTag 信标没到手 | 低 | 手机蓝牙改名 "SC-Owner" 方案 A 起步 |
| 多进程抢串口撞车 | 低(MVP)/高(后期) | 第 3 批 L3 强制收敛为单一 owner |
| 板子断电后 C3 不枚举 | 高（老毛病） | 每次 demo 前冷启动检查流程写进 RECOVERY.md |
