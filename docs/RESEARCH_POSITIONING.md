## 上层框架：Presence Management（在场管理）

**一句话**：陪伴体根据对情境的理解，决定**"何时在场、以何种方式在场、何时缺席、如何重逢"**；SC 的 FOLLOW/APPROACH/YIELD/HIDE/SEPARATE 是**五种在场决策**，不是五种跟随。

- 理论根：Calm Technology（Weiser/Case）、Implicit Interaction、Proxemics/礼貌（Goffman/Hall/Lakoff）、主动性/可打断性；
- 三层阶梯：`L0 感知世界 → L1 理解情境 → L2 决定在场 → L3 执行`；**L1 是硬骨头，L2/L3 多为拼装**；
- 调研地图、缺口（"何时退"这半张牌少人打）、ODD 边界、待精读清单 → 全部在 `docs/PRESENCE_MANAGEMENT_SURVEY.md`。

## 0. 一句话定位

SC 用**"主动分离"（proactive separation）这一负向策略**，把"动态人群中鲁棒跟随"（难、卷、容易输）**重述**为"伴随机器人的**分离事件管理**"（可做、少人做、能赢），以满足真实需求——**别把我弄丢，也别烦我**。

---

## 1. 核心洞察：以退为进的负向策略

跟随类产品的全部逻辑是"**尽量别分开**"。SC 反过来：**人群来了，主动让开、找个安全又找得到的地方等，等合适了再回来。**

| 正向难题（别人在卷、我们会输） | 负向绕法（我们的做法） | 为什么能成立 |
|---|---|---|
| 在人群里**穿过去**（连续社会导航） | **退到安全处 / 贴边让开** | "连续导航"降维成"一个静态等待点" |
| **在线预测 + 优化**等待点 | **查世界模型 / 记忆** | 优化题变成"查图/查记忆"题 |
| **重规划重逢轨迹** | **复用 认主锁主 + 跟随** | "回来"照跟即可，无需新能力 |

**结论：整个"主动分离" = 一堆已解决的旧零件 + 一个新零件。**
那个新零件只有一个：**决定"什么时候主动分开"**（迎面人群的触发/风险判断）。其余全是拼装。

## 1b. 主动分离时序（状态/复用图）

```text
                 ┌───────────────────────────────┐
                 │            FOLLOW             │
                 │  （认主锁主 + 跟随，已具备）    │
                 └───────────────┬───────────────┘
                                 │
              ┌──────────────────┴──────────────────┐
              │  Pre 预分离：人群逼近信号？           │
              │  人数↑ / 迎面运动 / 密度阈值          │  ← 唯一新零件
              └───────┬─────────────────────┬───────┘
                   否 │                     │ 是
                      ▼                     ▼
                  继续 FOLLOW     ┌────────────────────────┐
                                  │ During 选安全等待点       │
                                  │ 安全 + 找得到 + 不挡道    │
                                  │ → GOTO_SAFE             │
                                  │   （复用 HIDE / affinity）│
                                  └───────────┬────────────┘
                                              ▼
                                  停靠等待（wait_owner 语义）
                                              │
                          ┌───────────────────┴───────────────────┐
                          │  After 可回了？                        │
                          │  人群散 + 主人在场                     │
                          └───────┬─────────────────────┬─────────┘
                               否 │                     │ 是
                                  ▼                     ▼
                              继续等待      回到身边（复用 认主 + FOLLOW）
```

**复用映射**：Pre→新决策；During→`HIDE`/`sector_score`（换触发条件）；After→`wait_owner` + `follow_controller`。
**唯一新写**：`Pre` 的触发判据（起步可用"人数 + 迎面运动"，进阶再谈预测）。

## 2. 这在学术上是"问题重述"（problem reframing）

- **别人的题**：*"如何在全动态人群里鲁棒跟随？"* —— 难、拥挤、方法前沿在卷，我们大概率输。
- **我们的题**：*"伴随机器人如何管理分离事件？"* —— 可做、少人做、差异化。
- 这不是回避科学，而是**换一个能赢的提问方式**；很多好论文正是这么来的。
- 它直接落地了初心那句：**"不问怎么一直跟着，问分开了会发生什么。"**
- 呼应根 README 的 "Self-preserve, then return" 与 EXCHANGE 的 "失败模式 = 标准 S-W-R 分离剧情，`wait_owner` 天然接管"。

## 3. 三拍框架（Separation–Wait–Reunion）与"三个时机"

| 拍 | 问题 | 状态 | 备注 |
|---|---|---|---|
| **Pre** 预分离 | 何时该主动分？ | **唯一新零件** | 可先用"人数 + 迎面运动"土办法起步，再谈"预判" |
| **During** 等待 | 去哪等？ | 有半成品（`HIDE`/affinity） | 世界模型成熟后 = 查图选点（安全 + 找得到 + 不挡道） |
| **After** 重逢 | 何时、如何回？ | 可复用（认主 + 跟随） | 回来照跟，`wait_owner` 接管 |

**全部研究内容 = 三个"时机"问题**：何时分、何处等、何时回。一个不多，一个不少。

## 3d. 双轴视图（功能轴 × 学科轴）

> 本文出现的"两种大分类"（A/B/C/D 四簇 vs T1/T2/T3 三轨）**不是两套答案，而是同一对象被切了两刀**——来自两条**正交的坐标轴**。

| | **轴 1 · 功能轴**（它"做什么"） | **轴 2 · 学科轴**（"谁研究它"） |
|---|---|---|
| 切法 | 沿决策生命周期 **τ/π/ρ** | 沿**学科共同体** |
| 得到 | **A/B/C/D 四簇**（12 子题） | **T1 世界模型 / T2 自驾·边缘 / T3 HRI·设计哲学** |
| 回答 | "怎么拆活、怎么设计实验" | "讲给谁听、投给谁" |
| 用途 | **内部执行**（分工 / 验收） | **外部包装**（套磁 / 投稿 / 答辩） |
| 本质 | 工程 / 研究设计视角 | 受众 / 共同体视角 |

**关键：两轴正交** —— 每个子题同时有"功能坐标"和"学科坐标"；四簇与三轨只是**沿不同轴投影**的结果，没有谁更"真"，是同一对象的**两张视图**。

**两轴如何配合**：
```text
                功能轴（拆活）→ 用来干活 / 分工 / 验收
                      │
   学科轴（包装）─────┼─────→ 一个子题 = 一个 (功能, 学科) 坐标点
                      │
                交叉格子 = 整合价值（别人单线做不出的地方）
```
- **主脊 A1→B3→C1** 是这张矩阵里的一条**斜线**：每落一格就换一个学科，这就是"横跨三轨"的来源；
- **同一份仓库，两套账**：按功能轴拆给"四条开发线"，按学科轴讲给"三位老师"。

**结论**：**"在场管理"是母题（对象）；功能轴与学科轴是观察它的两个透镜。** 先有对象、再各切一刀——所以看起来"有两种大分类"，其实只是维度不同。

## 4. 先决条件：两根柱子

主动分离之所以"比想象的轻"，是因为它**站在两根柱子上**：

1. **世界模型**（提供"等/回"的参照系）——V2 雷达 + 现有 `grid.json` / `sector_score` affinity 正是干这个的；
2. **认主锁主 + 跟随**（负责"回来"）——已具备（机主原则 L0-L3 + follow_controller）。

**两根柱子在手时，剩下要新做的只有那个"分离触发/决策"。**

## 7. 四条可验收证据（证明"不只是车 + 篮子"）

至少拿到其中**两条**，才配得上"研究装置"：
1. **真·预判分离**：连续"分离风险值"，能在分开前 3-5 秒预警，**有数据支撑**；
2. **等待契约的用户研究**：证明"车选的等待点"符合人的直觉（别人没做）；
3. **主动重逢**：车主动走向你的手机位置，而非原地等；
4. **隐形的证明**：用户报告"我不需要想它在哪"（初心原句）。

**现状：四条一条未做——它们就是 SC 与 gita 的分界线。**

## 8b. 文献对标（"负向策略"的学术依据）

**定位差异一句话**：别人研究"如何跟 / 如何避"，SC 研究"**如何主动分、去哪里等、如何回**"。

| 方向 / 工作 | 它做什么 | 与 SC 的关系 |
|---|---|---|
| **Follow-Bench**（跟人基准） | 跟人任务的统一评测 | 我们的动作可在其框架下量化；SC 的关注点从"跟随本身"移到"分离事件" |
| **EscortE**（伴随在线动作检测） | 从行为信号在线识别意图 | `Pre 预分离` 可借鉴其在线信号思路 |
| **SDA**（社会动力学自适应跟随） | 优化"跟得自然" | **对照**：它优化跟，SC 在"何时离开" |
| **GUIDER**（运动证据 × 占据栅格 → 意图推理） | 从运动推断意图 | 借鉴：预分离 / 意图信号来源 |
| **Event-Driven Proactive Assistance** | 事件驱动的主动辅助 | **同源思想**：SC = 主动"分离" |
| **arxiv 1909.06087**（轮式 + 单目云台统一控制） | 跟随的统一控制器 | **基线架构**；SC 平台参照 |
| 社会导航 yield / 避让（Sisbot、Mead & Matarić、Rios-Martinez 综述） | 社会性避让 / 个人空间 | SC 的"让开" = 社会性 **yield** 的一个实例化 |
| **Legibility**（Dragan，可读的运动） | 用运动做隐式沟通 | SC"主动让开"是**可读的隐式信号**（"我懂事了"）——落到初心 Implicit Interaction |
| 安全退避 / graceful degradation | 遇险时退避 | SC 把"退避"从**失败处理**升级为**主动行为** |

> 结论：SC 的方法不新，但**"把退避/yield 从失败处理提升为一等公民行为，并用它替代'穿越人群'的难题"**这一**问题重述**，在文献里少见——这就是差异点。

## 9. 诚实自评（强在哪 / 弱在哪）

**强**：
- **问题重述**（负向策略）本身有价值，且少人做；
- **系统集成 + 全栈**（0.8TOPS 边缘部署到行为层的完整链）；
- **受控实验**（相机-雷达互补、低光失败数据集，见 V2 §0 / C7）。

**弱**：
- **方法内核不前沿**（MPC/卡尔曼/costmap/BLE 全是成熟工具，真正的边界前沿是学习式意图/人群预测、导航基础模型）；
- **Pre 触发 v0（busy 版）已上线**（WAIT→HIDE→GOTO_SAFE，真机触发过/仿真 3/3）；**人群/风险版未实现**（仍是设想 + 复用零件）；
- **用户研究未开始**（唯一的差异化点也最耗时间）；
- **"让用户忘记是机器人"**需要长期田野研究，实验室证不了。
