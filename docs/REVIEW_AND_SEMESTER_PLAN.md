# 第一部分：项目全量盘点

## 1.1 项目定位与愿景

**Shadow Carrier（影子搬运者）**：主动式购物陪伴机器人。不遥控、不跟路人——认得主、看得懂主人意图、知道周围哪里能走，在购物动线上主动提供"躲让—迎接—接物"服务。

**Demo 场景（一句话）**：跟主人到饮水机 → 主人打水（静止）→ 车躲到门边等候 → 主人去冰箱取物 → 持物缓近 → 车迎上接过果冻 → 跟主人回去。

**技术叙事三层**（对老师讲述的主线）：

| 层 | 内容 | 对应学术方向 |
|---|---|---|
| 感知 | NPU YOLO 快环 + OpenCV 几何环 + 极坐标世界快照（grid.json）+ YOLO-World 开放词汇慢环 | 世界模型 / 边缘感知 |
| 决策 | 认主锁主（模板+跟踪器+在场信号）+ HRI 行为状态机（持物/弯腰/靠近速度→意图） | 人机交互 / 主动服务 |
| 执行 | 差速弧线跟随 + 救援式凝视云台 + 超声波避障 | 机器人控制 / 无人驾驶全栈 |

诚实定位（答辩防线）：当前产物是**"世界理解快照"（perception snapshot）**，不是严格意义的"世界模型"（缺记忆与动力学）；通往真世界模型的第一步是路径记忆（拓扑图），已在路线图占位。

## 1.2 硬件与系统架构

```
┌─ KickPi RK3566 (4×A55, 0.8TOPS NPU, WiFi热点AP6255) ─────────────┐
│  video_stream_v7 (8080): YOLOv8n INT8 ~11-13fps + MJPEG推流      │
│  rk_control (80): 网页遥控/跟随/云台 + USB CDC → C3              │
│  [世界] geometry_daemon: OpenCV几何1-2Hz + YOLO-World 1Hz 慢环    │
│  [HRI] hri_state: 行为状态机 + 黑匣子jsonl                        │
└────────────────USB CDC (/dev/ttyACM0, 全双工)──────────────────┘
┌─ ESP32-C3 Super Mini (运动控制器) ──────────────────────────────┐
│  TB6612 双TT电机 (MOVE/DIFF) + 超声波 (OBS遥测)                  │
│  LEDC 50Hz 直驱双舵机云台 (PAN/TLT 命令, 指令角即真实角)          │
│  引脚账本: 13 GPIO 已用11, 空闲 GPIO10/21 (预留给 MPU6050 I2C)   │
└────────────────────────────────────────────────────────────────┘
```

关键标定资产（已冻结）：相机内参 fx=508.2/cx=292.7/cy=276.6/k1=-0.295/k2=0.085（三方互证，方位角误差 0.08°）；TILT_LEVEL_CMD=112、PAN_FORWARD_CMD=90.58；机位离地约 10cm。

# 第三部分：成果包装三轨（作品集 / 科研 / 专利产品）

> 设计原则：**一鱼三吃**。同一个代码库、同一批实测数据、同一套 demo 物料，三条轨道各自包装，边际成本递减。三轨不冲突，冲突时优先级 = 科研 > 专利 > 作品集（按升学/套磁收益排序）。

## 3.1 作品集轨道

**受众**：求职（嵌入式 / 机器人 / CV 算法 / AI infra）、保研复试、实习面试。
**核心卖点**：*"一个人 + AI agents，在 0.8TOPS 的边缘板上搭出感知—决策—执行全栈，并用 A/B 实验和量化数据说话。"* ——系统级能力 > 单点算法，这是作品集里最稀缺的叙事。

### 拆成 5 个可独立展示的"作品"（每个都是一个面试故事）

| # | 作品 | 技术点 | 故事钩子（踩坑→方案→数据） |
|---|---|---|---|
| A | NPU 边缘视觉管线 | v7.2：11fps、INT8、背压流水线、watchdog 自愈 | "从 0.8fps 调到 11fps 的 7 个版本" |
| B | 单目极坐标世界快照 | 标定链（三方互证 fx=508）+ PnP + 8扇区×3环 grid.json | "尺量光心高度差 9% 被我废掉了，改 PnP 误差降到 3.23%" |
| C | 救援式凝视控制 | 四态滞回状态机 + 底盘绞合弧线 | "云台自动追踪上线当天翻车，A/B 实验定位四条扰动通道，重构为救援式后稳定" |
| D | 认主系统 | 多信号融合 + α-β 跟踪器 + 机主原则 L0-L3 | "跟错桌子事故的完整搜查记录 → 三层防御设计" |
| E | HRI 行为状态机 + 黑匣子 | 五态机 + 自运动门控 + 施密特去抖 + jsonl 全程留痕 | "假数据自测→实机黑匣子→调参闭环" |

### 产出物清单

1. **GitHub 仓库门面化**：根 README 重写（中英双语）、架构总图、demo.gif、数据表；`.bak` 和历史遗留目录归档。
2. **技术博客 5-6 篇**（一作一坑）：每篇"现象→搜查→方案→量化收益"，发知乎/掘金/个人站——面试官最容易触达的入口。
3. **2-3 分钟中英字幕 demo 视频**（与 Phase B1 同一支，双用途）。
4. **面试兵器库**：每个作品一张 STAR 卡片（背景/任务/行动/量化结果），面试前 10 分钟刷一遍。

### 拓展方向（可扩性）

- **Web Dashboard**：实时 grid 俯视图 + 状态机时间轴 + 黑匣子回放（黑匣子 jsonl 已有，缺的只是前端）——顺便补前端技能面。
- **ROS2 移植对比版**：同一功能 ROS2 节点化 vs 裸机服务化对比，展示"什么时候不该用 ROS"的工程判断。
- **A/B 实验报告**：凝视翻车→救援式的完整对照实验单独成文，这类"负结果+归因+重构"内容在技术社区极受欢迎。

## 3.2 科研轨道

**受众**：世界模型 / 无人驾驶 / HRI 方向老师（10 月底套磁对象），未来导师。

### 已在手却被低估的研究素材

- **完整 A/B 对照实验**（凝视持续追踪 vs 救援式，四条扰动通道归因）——现成的 empirical study 素材。
- **黑匣子 jsonl**：HRI 状态转移全程结构化数据，持续积累就是小数据集。
- **系统度量三件**：距离误差中位 3.23%、方位角 0.08°、门检测回归 3/3 零误报。
- **论文对标已建**：Follow-Bench / SDA / EscortE / arxiv 1909.06087（同款架构先行者）。

### 三个研究切口（由小到大，按老师反馈选）

| 切口 | 量级 | 题目方向 | 依赖 |
|---|---|---|---|
| 一（快，workshop 级） | 2-4 周 | "0.8TOPS 边缘端快慢环语义感知架构"：YOLO 快环 + YOLO-World 慢环 + 几何环的调度/延迟预算/网格质量 | 已有素材 90%，补延迟实测表 |
| 二（中，会议级） | 1-2 月 | "基于单目社交信号的主动式服务行为推断"：持物/弯腰/靠近速度 → 五态行为，收 N 人×M 轮黑匣子数据做小数据集+基线，对标 SDA/EscortE | A1 联调后持续采集 |
| 三（大，长线） | 学期+ | "从感知快照到拓扑世界模型的伴随机器人导航"：路径记忆+重访先验（与 Phase C3 同一件事的研究包装版） | 套磁反馈确认方向 |

### 路径与竞赛通道

- 路径：10 月底带 demo 套磁 → 11 月按反馈定切口 → 12 月-1 月技术报告/论文初稿。
- **竞赛顺路投一个**（大创 / 挑战杯 / 互联网+）：项目现成，主要是写本子；收益=经费+背书+答辩演练。建议 11-12 月报下一批大创或挑战杯校赛。
- 拓展：与实验室合作后可借深度相机/S3 平台做传感器升级对照；Follow-Bench 框架下做完整 benchmark。

## 3.3 专利产品轨道

**先易后难三步走**，软著兜底、发明占坑、产品试探。

### 第一步：软著（1-2 个月下证，几乎零成本，立刻可做）

按模块申请 2-3 件，代码已有，主要工作是文档（说明书+源码前后 30 页）：

1. "购物陪伴机器人控制系统软件 V1.0"（rk_control + C3 固件）
2. "基于视觉的用户识别与跟随控制软件"（owner_id + follow_controller）
3. "机器人环境理解与行为决策软件"（hri_state + geometry_daemon/grid）

### 第二步：发明专利（方法类，1-3 年周期，尽早占坑）

两个交底书候选（实测教训和 A/B 数据就是权利要求的现成论据）：

1. **"一种基于多信号融合的移动机器人用户锁定与跟随方法"**——模板打分+跟踪器门控+在场心跳+机主原则层级（L0-L3 本身就是权利要求层级结构）。
2. **"一种云台-底盘级联的移动机器人视野保持方法"**——救援式：冻结+边缘保持+定向扩展搜索+底盘绞合弧线（A/B 实验证明其必要性=创造性论证）。
3. （可选第三件）"一种单目云台极坐标环境快照生成方法"。

流程：11 月写交底书 → 走学校知识产权中心（费用通常可减免）→ 12 月前递交。

### 第三步：产品化探索（可选投入，不设硬指标）

- **硬件升级线**：C3→ESP32-S3（编码器+里程计，引脚账本已论证）+ UWB 标签 → "防丢跟随模块"概念（购物车/行李箱/宠物）。
- **场景泛化**：校园快递代取 / 实验室巡检 / 导盲伴随——同一套"认主+世界+HRI"三件套换场景。
- **最小商业验证**：demo 视频发 B 站/小红书，看自然流量与评论需求（零成本需求调研）。

### 拓展方向

- 专利族：认主 / 凝视 / 快照三方法各配"方法+装置"独立权利要求，随产品迭代持续分案。
- 产品与科研互喂：切口二的数据集 → 产品体验报告；产品场景 → 科研 problem set。
