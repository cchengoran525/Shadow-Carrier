## 0. 一句话定位

**雷达能覆写"跟踪"，覆写不了"身份"。** 覆写后架构变成一句话：
**雷达（360°、匿名、不怕黑）负责"指向"，相机（±32°、有身份、怕黑）负责"认人"** ——
即"低置信的传感器可以**指向**高保真传感器，但不能**声明**"（sensor cueing 的既有实践准则，
见 §5.2）。所以雷达拿到**转向权威**，相机的**身份证据**才放行平移。

## 2. 覆写阶梯（现状机制 → 雷达版）

| 现状（转向通道 v5） | 雷达上线后 | 为什么 / 注意 |
|---|---|---|
| **E1 预测式 TTE**（相机角速度预测出画） | **保留** | 它服务的是"保住**身份**"（相机快看不见→提前转）；雷达解决不了"相机只有 ±32°" |
| **BLIND 有界盲转**（按 θ̇ 外推 60°） | **换掉 → LED**：以关联腿簇的 bearing 为误差闭环 | 盲推是"没有量测时的无奈"；雷达给 360° bearing + range |
| **SEARCH 90°×2 + 停顿** | **降为最后手段**（雷达也没有腿簇时）；方向由 `sector_m`/`escape` 选 | 现方案"朝人消失侧扫"可能朝墙扫；雷达知道哪边空 |
| **weak_cue**（低置信框 + 下装 HSV 腿带） | **换掉 → 雷达腿簇**；HSV 降为"雷达掉线"兜底 | 13.5cm 平面看腿，衣物无关、暗光可用；顺带解掉"必须穿鲜艳下装"约束 |
| `dist_fn`（真实距离） | 接**关联腿簇的 `range_m`** | 注入口现成；替掉框高测距兜底，"保持 2.5m"变可测 |
| 夜景幻影（历史 95/98 帧） | 雷达做**几何否决**：该 bearing/range 无腿簇 → 丢该相机框 | 双向一致性门；对应 `phantom_adoption_risk` 日志 |
| HIDE 选点可见性/占用 | `sector_m` 占用 + 净空（§13 已规划） | `hide_occupied` 场景的实机版 |
| 原地转时的侧后盲区（超声只看正前） | 已覆盖 ✓ | `rotation_gap` 就是干这个的 |

**关联规则（粘滞 ID）**：以相机最近一次确认的 bearing 为锚 → 距离门 + 簇运动连续性 → 得到"主人簇"；
相机盲区内靠雷达自身航迹延续；**一有机会（相机看见）立刻复核**并把模板在线刷新（RA-L 2024 的在线持续学习：
固定特征 20–82% vs 在线 93.5–97%）。

## 3. 必须先定的仲裁：人和障碍是**同一个簇信号**

`lidar_guard` 今天把所有腿簇当障碍，`rotation_gap` 取 **360° 最近点**。于是：

| 工况 | 实测/推断 | 结论 |
|---|---|---|
| 主人 1.0m 擦身（正常 passby） | 仿真实测：**0 次命令改写**，`wz` 包络全程 90°/s，`blocked` 空 | **常态不冲突**（贴着 §6 那行"主人站在正前"的距离分离设计成立） |
| 主人贴到 **<0.5m** | 由 `wz_from_gap` 推断：0.4m 时净空 0.17m → 限速 ~72°/s；~0.28m 以下 → 判 `rot blocked`，**转向被自己的避障否决** | **近距冲突是真的**，而"主人贴着车走过去"正是 demo 会拍的镜头 |

**提议的仲裁规则（identity-aware）**：

1. **被关联的主人是"可转不可撞"**：不否决转向，但按**切向速度**限速 ——
   `wz_max = min(wz_max, v_tangential_max / max(r, body_radius))`，建议
   `v_tangential_max ≈ 0.3–0.4 m/s`（等价于"扫过他的体表速度不超过人的手臂动作速度"）。
   例：人在 0.4m，限到 ≈45–55°/s；人在 1.0m，可到 90°/s。
2. **未被关联的簇**（路人/椅子腿/箱体）→ 维持现有硬否决。
3. **两侧都挤**时：`sector_m` 选空的一侧转向（顺带把 SEARCH 的方向从"朝消失侧"升级为"朝消失侧 ∩ 净空"）。
4. 兜底不变：真进了 `HARD_GAP_M` 就停，人在 0.3m 内也不该继续拧。

**这条仲裁今天会失败**：把 `lidar_sweep_block`（路人版）扩成"主人版"（`person_legs` 里**被关联**的簇不该否决转向），
就是一个今天红、改完绿的断言 —— 建议作为装车第一步的验收。

## 4. 相机盲区与"信任"：文献给了什么、没给什么

### 4.1 直接回答："T 秒规则"确实没有人发表过

检索结论（含被引与反例）：**没有任何论文/标准/条令给出"身份证据陈旧后还能行动多久"的时间阈值。**

- 跟踪文献把"信任"建在**存在概率 / 航迹分**上，而不是**身份年龄**上：
  IPDA/JIPDA 的 `P(存在)` 是显式贝叶斯状态、无测量时继续传播并按阈值确认/删除
  （Musicki et al., IEEE TAC 1994, https://doi.org/10.1109/9.293185 ；FUSION 2002, https://doi.org/10.1109/icif.2002.1020938 ）；
  MHT 的 m-of-n 滑窗确认（Blackman, IEEE AES Mag 2004, https://doi.org/10.1109/maes.2004.1263228 ；Noyes 2004）。
- 跟人机器人的再识别是**事件触发**（人重新出现时），不是**陈旧时钟触发**：
  RPF-ReID（RA-L 2024, https://doi.org/10.1109/LRA.2024.3438042 ）；TPT-Bench（arXiv:2505.07446, https://medlartea.github.io/tpt-bench/）。
- 最近的一篇"匿名跟踪 + 人脸识别"系统（= 我们这套架构）用的是**带阈值的最近邻仲裁**，同样**没有时间窗**：
  Chan et al., "Autonomous Person-Specific Following Robot", arXiv:2010.08017 。

### 4.2 但四样东西可以直接用（这才是"没有规则"的正确解法）

1. **形式化**：JDL 数据融合模型把"**身份估计**"与运动学状态并列为 Level-1 的两个状态空间
   （Steinberg/Bowman/White, SPIE 1999, https://doi.org/10.1117/12.341367 ）；Dempster–Shafer 身份融合里给
   `{主人, 非主人, 未知}` 分配质量 —— "航迹在、身份未定"有现成表示（Blasch et al. SPIE 2013, https://doi.org/10.1117/12.2016326 ）。
2. **"多久"的正确形式是阈值而不是时长**：ATR 传统里，识别在置信度越过**声明阈值**时产出"声明"，
   工作点由 ROC 分析确定、以**误声明率**为受控量（Sherman SPIE 1991, https://doi.org/10.1117/12.2283656 ；
   Scherreik & Rigling SPIE 2017, https://doi.org/10.1117/12.2262666 ；Schachter, SPIE Press 章 4）。
   → 信任窗不该是"3 秒"，而应是"**在 P(身份) 跌破声明阈值之前**"，3 秒只是那个阈值在本场景下的**等效时长**（实测出来的）。
3. **"只准转不准走"有已发表的实践依据**：sensor cueing 的惯例是**低置信线索可以指向、不能声明**；
   且有实验量化"指向误差如何影响后续识别"（Park et al., J. KNST 2026, https://doi.org/10.31818/jknst.2026.6.9.2.369 ）。
4. **实现机制**：他们的 `uart_send` 收口就是 **Simplex 架构 / safety filter** 的形状
   （Sha, IEEE Software 2001, https://doi.org/10.1109/ms.2001.936213 ；Mehmood et al. NASA FM 2022, arXiv:2102.12981 ；
   CBF 滤器 Ames et al., IEEE TAC 2017, https://doi.org/10.1109/tac.2016.2638961 ）；
   而"**按感知置信度**门控动作"这一支已有先例：measurement-robust CBF（arXiv:2010.16001）、
   conformal prediction 门控（arXiv:2304.00194）、conformal/POMDP shielding（arXiv:2506.17275 / 2604.20728）、
   综述术语 **"runtime action authorization"**（arXiv:2606.00090）。
   → **"身份置信门 + 安全 shield"的组合目前没人做过** —— 这是干净的novelty，也是你们实测数据的论文出口。

### 4.3 三个选项（现状基线 / 推荐 / 激进）

| 选项 | 规则 | demo 影响 | 风险 |
|---|---|---|---|
| (a) 保守 = 现状 | 相机盲区**只准原地转** | 每次擦身停下转头，等人回锥内再走 | 最低；但"擦身"观感偏顿 |
| **(b) 信任窗（推荐）** | `P(身份)` 未跌破声明阈值（≈实测 2–3s）且雷达关联链未断 → 盲区内允许继续跟走 | 擦身变成"平滑转头继续走" | 双人交叉时段可能跟错 → 需粘滞关联 + 一有机会就复核 + 超窗立即降级 |
| (c) 雷达主跟 | 相机只做周期性复核（夜间也能跟） | 最流畅 | ID 交换风险最高，"锁人只跟主人"叙事被削弱 |

**为什么 (b) 的窗长锚在 2–3s**：真人走路跟随时相机被遮挡的实测分布是
**均值 1.2–1.4s、最长 3.4–3.7s**（Isobe et al., ROBOMECH J. 2018, https://doi.org/10.1186/s40648-018-0101-2 ，12.8Hz）；
而要覆盖我们的"擦身 6s"，**主要解法是转头而不是加长信任窗** —— 别用信任窗去顶"该转的场合"。

### 4.4 实测协议（把"体验"变成可复现的数）

**设计**：走廊固定动线，软件门上"临时抑制相机身份通道"（只压制身份，雷达腿航迹继续），
在预标位点开始计时。因素与水平建议：

- **盲区时长 T** ∈ {0, 2, 4, 8, 15}s（锚在 Isobe 的 1–4s 与擦身的 6s；上界用于找拐点）
- **路人编排** ∈ {无, 一次垂直穿越, 两次穿越, 并行后分开}（TPT-Bench 的现实分布：目标每次离线平均 65.3s、
  每序列 45.4 次消失、**大多数空隙 0–6s**、离线期间平均 9.6 个干扰者）
- **是否公告**（"我暂时看不到你了"）∈ {不公告, 公告} —— 人因侧依据：失败沟通被列为欠研究
  （Honig & Oron-Gilad, Front. Psychol. 2018, https://doi.org/10.3389/fpsyg.2018.00861 ）
- **每格 ≥10 次独立跑**（无事件率的置信上界用 rule of three：N 次 0 事件 → 95% 上界 ≈ 3/N）

**指标（含一个必须避开的坑）**：

1. **主指标 = "盲区结束时是否仍锁住主人"** → Kaplan–Meier 生存曲线，报中位拐点 T50 与置信区间；
2. **错锁率**（锁到非主人簇的时间占比）—— 用 TPT-Bench 的 **AMR（100% 精度下的最大召回）** 思路，
   因为"一次误报就足以让车跟错人"（该基准上 SOTA 也只有 **66.06 F-score / 16.26 AMR**，说明这问题真的难）；
3. **目标级切换次数**（不用 MOTA 的 IDSW：MOT20 明确定义"目标离开视野再出现会被当作新目标"，
   即**漂移遮蔽不被惩罚**；要按"目标级"数，见 Dendorfer et al. 2020, arXiv:2003.09003 ；关联质量另用 HOTA，
   Luiten et al. IJCV 2020, https://arxiv.org/abs/2009.07736 ）；
4. **重捕获时延与成功率**；5. Gockley 式的"每次失败的间距/时间"（HRI 2007,
   https://doi.org/10.1145/1228716.1228720 —— 注意：他们实验里是**禁止遮挡**的，所以我们的场景在他们的数据之外）；
6. 主观问卷（跟随距离/自然度/被打断感，1–7 量表，沿用 Gockley 的题面结构）。

**文献里挖不到的**（诚实交底，别在论文里假装有）：DJI ActiveTrack 的"8s coast / 10s 超时"在可达资料里**未证实**（原手册副本取不到，此前引用作废）；
TPT-Bench 未公布 IDF1/IDSW 数字；**没有任何 HRI 研究做过"车跟错人"的被试实验**；也没有"被盲跟多久会不适"的近距/时间容忍度研究。

## 6. 装车前就该做的三件事（不动主链路）

1. **`--record` 真实走廊**（主人擦身 + 路人交叉 + 椅子腿），`--replay` 离线调"腿簇→人"的分类与关联阈值。
   标注用**相机框做伪标签**（把雷达点投到相机框下半部自动标注：真机 TPR 91.6% / TNR 99.4%，
   Jia et al. arXiv:2012.08890 ）→ 零人工成本 bootstrap。
2. **把仲裁写成断言**：被关联簇**不得**否决转向（改为切向速度限速）、未关联簇**必须**否决。
   即把 `lidar_sweep_block` 扩出"主人版"，作为装车第一步验收。
3. **方位角约定并入 `test_bearing_convention.py`**，并定 `SENSOR_YAW_DEG` 的装车实测流程
   （装车验收 3 条沿用 `V2_LIDAR_AVOIDANCE.md` §2.3，那里再加一条"雷达 bearing 与相机 bearing 同向"）。

## 7. 与既有分期（`V2_LIDAR_AVOIDANCE.md` §7）的衔接

他们的四步走是**安全**线（观察 → 限速 → 停车 → 绕行）。本设计插入两档**感知**线，互不阻塞：

| 新步 | 做什么 | 验收 | 回退 |
|---|---|---|---|
| **2.5 人-簇关联（只读）** | 消费 `person_legs`，做"主人簇"关联与日志，**不下发任何动作**；与相机框离线对照出 TPR/TNR | 关联正确率 vs 相机框 ≥ 目标值（先测基线再定） | 只删日志 |
| **3.5 转向用腿（LED）** | BLIND/SEARCH 改为以关联腿簇 bearing 闭环；近距按切向速度限速（§3） | `passby` 场景 + 主人贴 0.4m 的台架：转向既不被否决也不超速 | 置回 `TURN_ENABLED` 的 v5 行为 |
| **4 距离/幻影/暗光** | `dist_fn` 接 `range_m`；幻影几何否决；夜间雷达主跟（相机做周期复核） | 各自独立开关 | 各自关掉 |

## 8. 度量纪律（这次踩过的坑，写进规矩）

1. **passby 这个场景抖动很大**：同一配置重复 3 次，最长不可见 = **0.62 / 2.40 / 2.79 s**
   （可见率 0.89 / 0.58 / 0.55）→ **单跑不能当门禁**。今后 A/B 一律 **N≥5 取中位数 + 报分布**；
   单跑结论只在"差异远大于抖动"时才采信。由此也推翻了早前"加雷达让擦身变差"的猜想
   （lidar-on 那次 2.17s 落在噪声区间内；且那次 `lidar_filter` **0 条**、`wz` 包络全 90°/s、`blocked` 空）。
2. **抖动源与修法**：仿真的 HRI/控制拍用的是**墙钟**（`time.monotonic()`）而剧本走**仿真钟** → 负载一变就错相。
   建议把仿真侧的 HRI/follow 拍改成 `robot.getTime()`，并给场景加固定"就位段"，再谈门禁。
3. **别用 MOTA 的 IDSW 衡量"擦身跟丢"**（它的定义把"离开视野再出现"当作新目标 → 漂移遮蔽零惩罚）。
4. **任何"雷达有用"的结论都要带对照组**（关雷达同配置同 N），否则和负载/时序差异分不开。

---

## 9. 明确不接管（边界重申）

- **身份**（"谁是主人"）：仍只由相机 + 模板声明；雷达永不放行"跟陌生人"；
- **玻璃/镜面/矮物/下台阶**：相机 + 超声 + 场景约束；
- **平移放行的最终解释权**：在 §4.3 让你拍板之前，仍按现状（(a) 选项：盲区只准转）。
