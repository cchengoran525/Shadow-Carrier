# Shadow Carrier — V1(demo) → V2 → V3 开发路线

> 写于 2026-10-11。**这是"开发计划"，与包装计划（`docs/PACKAGING_PLAN.md`）分开**。
> 三个版本节点：**V1 demo（10 月底）→ V2（1 月寒招，全硬件 + 单人 + release）→ V3（大三前，纯固件：世界 + 多人）**。

---

## 0. 版本定义

| | **V1（demo）** | **V2** | **V3** |
|---|---|---|---|
| 内容 | 场景跑通 + 套磁 | **全硬件配齐** + 稳健单人 | **纯固件升级**（不碰硬件） |
| 硬件 | 现车 | 底盘/编码器/电源/相机/**雷达**/云台 **一次到位** | 不变 |
| 软件 | 五态状态机 + HIDE/RECEIVE | 跟随距离保持 + 单人交互 + 雷达局部几何 | 局部世界 + 多人判断与反应 |
| 产出 | demo 视频 + 一页纸 | **GitHub release `v2.0`**（硬件+固件+软件+文档+视频） | V3 固件（可再发 release） |
| 硬节点 | 10 月底 | **1 月寒招** | **大三前原型** |

---

## 1. 三条总原则

1. **V2 一次把硬件做对**：V3 纯固件，所以 **V2 的硬件规格要为 V3 预埋**（雷达、编码器、云台自由度、接口一次冻结）。
2. **机器人轨：局部情境、无云、无 SLAM**：
   - 机器人侧只做**局部情境世界理解**（周围 free / 谁在动 / 可见性 + 短时记忆）；
   - **不建全局地图、不 SLAM、不重定位、不连云**；
   - **SLAM 归 PC 科研轨**（离线，吃车上日志，无死线）。
3. **每版只跑一条主脊**：V2 保"单人 S-W-R 工程实现"，V3 保"局部世界 + 多人 + 在场管理"，其余封存（见 `docs/DEFERRED_WORK.md`）。

## 2. V2 开发排期（11 月 → 1 月，按月按周）

### V2a 底盘 bring-up（11月 W1–W3）
| 任务 | 交付/验收 |
|---|---|
| S3 固件：DIFF 兼容 + `MEC` + 4 轮 PID + 航向环 + 4 路编码器（PCNT） | 编译烧录通过，遥控能跑 |
| 装底盘：麦轮 + JGB37-520 电机 + A4950 + 三路隔离电源 | 供电稳定、无"落电断连" |
| 台架验收 | 直线 5m 偏差 <0.3m；横移/原地转正常；DIFF 一键回退可用 |

### V2b 传感器全装 + 重标定（11月 W4 – 12月 W2）
| 任务 | 交付/验收 |
|---|---|
| 低照度广角相机装回 + 重标定（fx/tilt/PnP） | 夜景幻影显著下降；测距复标 ≤2% |
| **雷达** 装 + YDLidar-SDK aarch64 编译 + **L1 daemon**（局部几何，出 `/api/scan` 或 grid.json 第四源 `lidar`） | 雷达稳定出图；360° 净空可见 |
| 云台 STS3215（预算允许）或继续冻结 | 单线菊花链 + 真实角回传 |
| 跟随加**距离保持**（编码器里程 + `dist_m`）；认主加固（画廊/多帧投票） | 单人跟随不丢、不顶人；双人只跟主人 |
| **记录原始数据**：雷达扫描 + 编码器/IMU 里程 + ts 落盘 | 供 PC 科研轨回放做 SLAM（机器人零负担） |

### V2c 单人交互 + 寒招（12月 W3 – 1月 W2）
| 任务 | 交付/验收 |
|---|---|
| 单人交互：RECEIVE / WAIT-HIDE / **停等型分离** / BESIDE 基础 | 主动上前接物 + 主动让开 |
| 续航分级模式（柜台/跟随/关机） | 寒招一天够用（快换电池兜底） |
| 寒招脚本 + 彩排 | **连演 3 次**不救场 |
| **V2.0 release** | 见 §3 |

## 4. V3 开发排期（2 月 → 8 月，**纯固件**）

> 不新增硬件；接口不动；只改实现。**全程无 SLAM、无云。**

### V3a 局部世界（2–4 月）
| 任务 | 交付/验收 |
|---|---|
| 雷达**局部几何**：free/障碍/**腿级人物**/可见性（不建图） | 周围净空与可见性可量化 |
| **短时记忆**：滚动地图（TTL 级，已有 `geometry_map`）+ 语义网格（YOLO-World+几何） | 情境快照稳定；等待点"找得到"可测 |
| 明确**不做** | ❌ 全局地图 ❌ 扫描匹配建图 ❌ 重定位 |

### V3b 多人（4–6 月）
| 任务 | 交付/验收 |
|---|---|
| 多目标跟踪 + ReID（≥2 人才触发，低频足矣） | 人群中不丢主人、不误锁路人 |
| 人群/群组理解；**分离两型**：停等 + **绕行**（麦轮横移） | 主动分离（停等/绕行）成功 |
| 主动出场/退场；社会让行 / BESIDE 硬化 | 多人场景得体应对 |

### V3c 整合 + 稳健（6–8 月）
| 任务 | 交付/验收 |
|---|---|
| 局部世界 + 多人 + **在场管理**整合 | 公共空间连续运行 |
| 主脊 **A1→B3→C1** 落地实验（触发/等待契约/信念重逢） | 分离/重逢/出场闭环 + 量化证据 |
| **V3 原型**（大三前） + V3 固件 release | — |

## 7. 风险

| 风险 | 缓解 |
|---|---|
| **V2 硬件长尾**（集成期故障淹没） | 分相 + 每相独立验收 + 事故记录 |
| V2 拍错硬件（算力/传感器）→ V3 卡死 | 设计时把 V3 需求摆上桌；接口一次冻结；留余量 |
| sim→real 缺口（每次换硬件重开） | 先仿真定逻辑，再真机定参数；新能力先小场景冒烟 |
| 多人 + 边缘算力 | 低频足矣；ReID 仅 ≥2 人触发；砍 SLAM 已省大半 |
| 单人带宽 / 课业 | 永远只有一条主脊在跑；敢砍；保护 GPA |
| 伪需求（在场管理没人要） | 小样本先证伪（10–20 人），再投入 |
