# V2 摄像头选型调研

> 生成于 2026-10-14。用途：给 V2 桅杆云台换相机做选型决策与验收方案。
> 说明：市场价为**大致行情**（本 session 无联网核价条件，下单前请以在售价为准）；物理与集成结论来自计算与现有代码约束，可直接采信。

## 1. 需求是从哪推出来的（不是拍脑袋）

| 约束 | 来源 | 量化要求 |
|---|---|---|
| **低照度** | 宿舍夜景幻影 person 率 95/98 帧（真实失败数据） | **第一优先级**：同场景幻影率要显著下降 |
| **垂直 FOV** | §9.3/§14.6 几何：65cm 机位下要"全身(1.7m 人 @≥1.5m) + 近地(≥1.4m)" | **vFOV ≥55°** |
| **UVC + MJPG** | `video_stream_v7.py` 全链路按 UVC/MJPG/640×480 写死，且有 watchdog/重连/禁用 autosuspend 兜底 | **硬约束**，换 CSI 等于重写感知链 |
| 分辨率/帧率 | YOLO 输入 640×480，11 FPS 瓶颈在 NPU 不在相机 | 1080p30 足够；60fps 无收益 |
| 物理 | 云台顶端负载（STS3215 舵机 + 打印支架） | ≤50g、≤Ø30×40mm |
| 预算 | ¥555 档全套 | ≤¥120 |

## 2. 指标排序与物理依据

**① 低照度 = 像素尺寸 × 传感器工艺（决定夜景幻影率）**

- **像素尺寸是主因**：同为 1/2.8" 传感器，2MP（1920×1080）单像素 **2.9µm**，4K（3840×2160）只有 **1.45µm**——面积差 4 倍 → 4K 夜景噪声高约 2 档（6dB）。**"分辨率越高夜景越差"是本次选型的核心结论**。
- 工艺：索尼 **STARVIS 背照式**（IMX307/IMX291/IMX462）是低照度标杆；国产（SC3336 等）次之但便宜一档。
- 这条直接否掉 4K 方案：我们缺的是信噪比，不是分辨率（YOLO 输入本来就是 640）。

**② FOV = 镜头焦距 + 传感器靶面**

1/2.8"（5.6×3.15mm，16:9）配 M12 镜头：

| 焦距 | 水平 FOV | 垂直 FOV | 对角 | 判定 |
|---|---|---|---|---|
| 2.1mm（鱼眼） | ~150° | ~110° | ~170° | ❌ 畸变太大，毁 PnP 测距（现基线 ≤2%） |
| **2.5mm** | ~96° | ~66° | ~105° | ✅ 余量最足，畸变可接受（推荐备选） |
| **2.8mm** | ~90° | **~59°** | ~98° | ✅ 刚好压 55° 线（首选，需实测确认） |
| 3.6mm | ~76° | ~48° | ~82° | ❌ 垂直 FOV 不够，全身入画距离被推远 |

**③ 畸变**：必须买"**低畸变**"版。整条几何链（`auto_calib_pose.py`、`calib_prod.json` 的 ≤2% 距离精度）建立在近似针孔模型上。
**④ IR-CUT**：必须有（否则白天偏色、夜里缺红外增益）。
**⑤ 快门**：全局快门平替（OV9281 1MP）低照度与分辨率双输，且手部动作 30fps 卷帘可接受 → 不选。
**⑥ 接口**：UVC（硬约束，见 §1）。

## 4. 验收协议（四项，全部复用现有工具）

1. **夜景幻影 A/B（核心指标）**：同一宿舍夜景场景，沿用现成 30s 采样法统计"含 person 帧数"（当前基线 **95/98 帧**）；新模组目标：**<30%** 且幻影 conf 分布明显下移。
2. **FOV / 畸变**：黑底画直网格 → 量四角直线残差；再跑 `auto_calib_pose.py` 标定链看距离精度是否仍 ≤2%（超标则换 2.5mm 或校正畸变）。
3. **模式与帧率**：`v4l2-ctl --list-formats-ext` 列全部模式；**逐模式实测 FOV**——UVC 模组的经典坑是 640×480 由**裁剪**得到（视场会变小），必须确认 MJPG 640×480 与 1080p 的视场一致；测实际 FPS。
4. **USB 稳定性**：跑 10 分钟，看 `/api/detections` 的 `cam_reopens / cam_read_fail`（现成统计）；`dmesg | grep -i usb` 看有无重新枚举。

**换模组必须同步改两处 VID:PID**：`configs/99-shadowcarrier-camera.rules`（`/dev/camera0` 别名 + autosuspend 规则）与 `deploy/camera-usb-fix/` 轮询兜底脚本。

## 5. 数据链路衔接

- `video_stream_v7.py` 的 `WIDTH/HEIGHT=640,480` + `MJPG` 不用改；只增加新 VID:PID 的 udev 规则；
- 换机后重跑：§14.4 激光点试验（云台震动）→ `auto_calib_pose.py` 标定 → 幻影率 A/B → 跟随实测；
- 备件：短粗 USB 线（≤30cm，20–22AWG，见 §19.6 的 IR 压降结论）+ 磁环。

## 6. 专项调查：SC3336（2026-10-14）

> **先自我修正**：§3 把 SC3336 当"UVC 候选"列出是 oversimplify——它在零售市场主要是 **MIPI 排线形态**，能不能用取决于形态与主机支持，见下。

### 6.1 器件本身

思特威（SmartSens）3MP CMOS，**1/2.8"、2304×1296、约 2.0µm 像素、BSI、MIPI 2-lane**，大量用于 IPC/消费摄像头。低照度定位：**中上**，但明显弱于索尼 STARVIS 的 IMX307（2.9µm + STARVIS 工艺）——**"全彩夜视"是营销词，不是 STARVIS 级**。

### 6.2 三种在售形态与识别方法（下单前必看接口）

| 形态 | 接口 | 是否免驱 | 判定 |
|---|---|---|---|
| **裸 MIPI 模组**（用户看到的"条带"） | FPC 排线（15/22pin）+ 座 | ❌ 需主机 CSI + 传感器驱动 + ISP 调优 | ⚠️ 见 §6.3 |
| **自家 MCU/SoC 模组**（IPC/开发套件形态） | 网口/USB 输出压缩流 | ❌ 需厂商 SDK | ❌ 拒绝：管道被厂商吃走，延迟 +100–300ms，拿不到原始帧 |
| **USB UVC 版**（若该版本存在） | USB-A/Type-C，**免驱** | ✅ | ✅ 可用，等价普通 UVC 相机（但低照度仍不如 IMX307） |

**识别三问**：① 接口是 USB 插头还是 FPC 排线座？② 详情页是否写"免驱/UVC"？③ 是否要求"配套某板/某 SDK"？——三个都是 USB/UVC 才是 UVC 版。

### 6.3 若走裸 MIPI 在 RK3566 上的真实成本

| 项 | 内容 | 工作量 |
|---|---|---|
| 传感器驱动 | rkisp/v4l2 subdev 驱动（Rockchip BSP 里**可能有**，先查） | 有则 1 天，无则按周计 |
| **ISP IQ 调优文件** | 每个 sensor 一套 XML（3A/降噪/色彩） | 有则 0，无则基本做不完 |
| DTB 配置 | CSI 端口 + I2C + clock/reset GPIO | 半天（易砖，谨慎） |
| 流水线改造 | 现在是 `cv2.VideoCapture` + **MJPG**；CSI 出 YUYV/NV12 → 每帧转换吃 CPU（RK3566 余量本就紧），**MJPG 硬解优势消失** | 1–2 天 |
| 加分项 | NV12 可考虑直通 RKNN，省一步转换 | — |

**决定性第一步**：向 KickPi 板厂/查 BSP 确认 **是否存在 SC3336 的驱动 + ISP IQ 文件**（`dts` 里有没有 `sc3336` 节点）。有 → 成本骤降，可做；无 → 这是驱动移植项目，不属于 V2 工期。

### 6.4 云台安装的真实问题（用户的直觉正确）

- **FPC 排线在平转云台上反复弯折 = 疲劳断裂**（0.5mm 间距的连接器座本身也脆）；必须走服务环 + 双点固定，且**弯折点不能落在插座根部**；
- 传感器板很小很轻（≈10–20g）——这点**对云台反而是优点**（比带外壳的 USB 模组轻）；
- USB UVC 模组的粗线虽丑但便宜可换（¥60 一换）；MIPI 模组一断就是重新焊 FPC 或整换。

### 6.5 判定

1. **若只买得到 MIPI/自家 MCU 形态**：不做 V2 主相机；可**单列为研究支线**（"CSI 低延迟通路 + NV12 直通 NPU"），且**前置条件是 §6.3 的 BSP 支持确认**；
2. **若能买到 UVC 版 SC3336（¥45–80）**：可用，但它省下的是 ¥20–40，代价是夜景幻影这个核心 KPI——**若夜景区分度是 demo/论文指标，不值得省钱**；若只是白天演示，可接受；
3. **同价位的低风险替代**：OV2710/OV2735 2MP UVC（老牌免驱、120° 广角版常见，¥40–70）——低照度一般但链路零风险；
4. **首选仍是 IMX307**（§3）：¥60–100 换 STARVIS 级低照度，是这一项预算里性价比最高的 ¥20。

## 7. 为什么"IMX 看起来像汽车件"：输出形态识别 + 更多候选（2026-10-14）

**原因**：IMX307/291 这类 STARVIS 传感器是**行车记录仪/安防**的功勋件，所以零售盘围绕这两个行业铺货；UVC 免驱版只是其中一支。**同一颗传感器可以有三种完全不同的输出形态，能不能用取决于形态，而不是传感器**：

| 形态 | 线索关键词（商品页） | 能否直插 RK | 说明 |
|---|---|---|---|
| **模拟同轴**（车载/倒车/安防） | AHD / TVI / CVI / CVBS / 同轴 / 航空头 / 4pin / 宝马头 / 车载 | ❌ 需 AHD→USB 采集卡 | 见 §7.2 野路子 |
| **IPC 网络** | 网络 / IP / RTSP / ONVIF / RJ45 / WiFi / PoE / 需 SDK | ❌ | 延迟 +100–300ms，拿不到原始帧 |
| **USB UVC 免驱** ✅ | **免驱 / UVC / USB2.0 摄像头 / 支持 MJPG+YUYV / 格式表 / 分辨率×帧率表** | ✅ | 要的就是它 |
| MIPI 裸模组 | MIPI / CSI / FPC / 22pin / 15pin / 需驱动 / 需配套板 | ⚠️ | 见 §6.3 |

**识别三问（顺序问卖家）**：① 是 USB 免驱吗？② 支持 MJPG 吗？③ 镜头是 M12 螺纹可换吗？——三问全 yes 才是我们要的东西。

### 7.2 野路子：车载 AHD 摄像头 + USB 采集卡（¥70–130 全包）

- 组成：**AHD 车载摄像头**（IMX307/291 常见，带金属外壳+广角镜头，¥35–70）+ **AHD→USB 采集卡**（¥30–60）→ 系统看到的就是一个 UVC 设备，`cv2.VideoCapture` 直接用；
- 优点：便宜、**外壳/防水/线束现成**、广角版本多、传感器真材实料（STARVIS）；
- 缺点（关键）：**延迟 +50–150ms**（采集卡缓冲）、分辨率上限常为 720p/1080p@25–30、**曝光/白平衡由摄像头固件自动，不可编程**（YOLO 前处理的参数控制权丢失）、供电多为 5–12V 车载、接头是 4pin 航空头需转接；
- 判定：**跟踪类任务不推荐**（延迟+不可控曝光都会伤害 follow/pose）；若只做"看得到人"的演示可接受。做一个低成本对照臂倒是可以。

### 7.4 OV2710 vs OV2735 + 品牌溢价买的是什么（2026-10-14）

**传感器本身**：

| | OV2710 | OV2735 |
|---|---|---|
| 年份/定位 | 老方案（2011 年代），当年记录仪主力 | **2710 的换代**，新 UVC 模组/记录仪多用 |
| 靶面/像素 | 1/2.7"，2MP 1080p，**3.0µm** | 1/2.7"–1/2.9" 量级，2MP，~2.8–3.0µm |
| 低照度 | 同代里能打，但读出噪声/工艺老 | **读出噪声更低、SNR 更好** |

**结论：传感器的账上 2735 ≥ 2710。** 若 2710 卖得比 2735 贵，原因只能是**模组形态**（镜头/IR-CUT/外壳/库存/渠道），不是"2710 低照度更好"。→ **在两者间选 2735**，除非那个 2710 模组明确带了你要的镜头/IR-CUT。

**品牌溢价（微雪 ¥100+ vs 无名 ¥60）买的是四样"可预测性"**：
1. **规格可信**：真实 FOV / 镜头焦距 / 是否有 IR-CUT / 完整格式表 —— 正是 §1 需求的判据；
2. **批次一致**：同传感器同镜头（无名件可能换料）；
3. **UVC 合规**：MJPG 与**曝光/增益控制真的可用**（关系到"锁增益治幻影"那个 ¥0 实验能否做）；
4. **镜头可调焦/可换**（M12 螺纹 vs 胶死塑料镜）——畸变与 FOV 是几何标定链的命门。

**三档买法**：
- **稳妥**：微雪 OV2735（¥80）——比同品牌 2710（¥100+）更划算；
- **省钱**：¥60 无名 2710 可以买，但把 §4 **验收四项当退货筛子**（`--list-formats-ext` 查 1080p MJPG@30 与各模式 FOV 是否一致；`--list-ctrls` 查曝光/增益可编程；棋盘格量畸变；夜景 A/B）——任一项崩就七天无理由退，无牌件即变低风险；
- **要夜景**：仍优先找 IMX307 免驱 UVC（¥100–150 档）——相对 2710/2735 是 4–9 倍像素面积 + STARVIS。

**换模组两处必改**：`configs/99-shadowcarrier-camera.rules` 与 `deploy/camera-usb-fix/` 的 VID:PID。**新相机到手先跑 `v4l2-ctl --list-ctrls`**，把输出贴回项目，确认能否做"锁曝光/增益"的 ¥0 幻影实验。

| IR-CUT | 不确定/质量未知 | 通常明确标注 | 白天偏色问题可控 |
| 曝光/增益 | 有控制项但常被固件忽略 | **UVC 控制可用** | "锁增益治幻影"的 ¥0 实验能做 |
| USB | Sonix bridge，autosuspend 会 re-enumerate | 标准 UVC bridge，通常无此毛病 | 少一类偶发故障 |

**可量化的预期**：夜景幻影帧率从 **95/98（97%）** 出发，靠 1–1.5 档 SNR 增益预计降到 **40–70%**；**再叠加锁曝光/增益**有机会压到 **<30%**（真实数字以 §4 的 A/B 实测为准）。

**不会变的**：仍非 STARVIS 级（幻影不会清零）、仍卷帘快门、分辨率与 YOLO 输入不变（还是 640×480）、**换镜头/换靶面后必须重跑 `auto_calib_pose.py`**（否则 ≤2% 测距精度退化）——不要跳过标定。

**可选加分项**：市面有"带 IR LED 夜视"版本——**主动补光是硬件层面最直接的幻影解法**（把信噪比抬起来），代价是可见红点、+1–2W 功耗，以及"像偷拍摄像头"的社会观感（本项目在意形象，需权衡）。

### 7.6 结论修订：**不推荐 OV2735**（"感觉没升级"是对的）（2026-10-14）

用户反馈"怎么好像没啥升级"——**这个判断正确，§7.4 的"选 2735"应降级为"别买"**：

- OV2710 / OV2735 / 现役 0c45:6366 **同属中低档 2MP**，像素尺寸 2.8–3.0µm 档位相当，谁都不比谁"亮"一档；
- 2735 相对现役多出来的只有：镜头可换、IR-CUT 明确、曝光/增益可编程、USB bridge 更规矩——**是"确定性"升级，不是"画质"升级**；
- 真正能"感觉到"的分界是**暗噪声工艺**：STARVIS 级（IMX307）把噪声底显著压低，这才是夜景幻影率会明显下降的档位。

**相机这一项的正确花法（三选一，别再纠结 2710/2735）**：

| 方案 | 内容 | 成本 | 预期 |
|---|---|---|---|
| **A（先做）** | ①现役相机**锁死曝光/增益**（自动增益拉满=噪声被判成 person）；②修 `_pick_owner` 回退通道（person 权重 + 位置连续性，仿真已证） | ¥0 | 幻影率最可能的实际降幅来源 |
| **B（要换就一步到位）** | **IMX307 免驱 UVC + 低畸变 M12 镜头**，换后重跑标定 | ~¥150 | 唯一"能感觉到"的相机升级 |
| **C（不动相机）** | 钱与工时给 S3+编码器 / STS3215 云台 / 雷达 | — | **项目真正的大件升级在这里**：gimbal README 自己写了"长期方案=里程计让位置连续性成为最强过滤"——幻影的根治是里程计，不是相机 |

**另一个被忽略的"升级"**：现役传感器**型号都查不出来**（批次不一）→ 无法推理、无法复现、无法调参、标定不可复现。换成有文档的模组，**工程可预测性本身就是升级**——但只有买到 IMX307 这一档才顺带拿到画质，OV2735 只买到确定性。

### 7.7 "IMX307 是不是都是 MIPI？"——形态现实与 USB+真低照度的可行档位（2026-10-14）

**用户观察基本正确**。IMX307 原生输出就是 **MIPI CSI-2**；要做成 USB 免驱，模组厂必须再挂一颗 UVC bridge + ISP。因此零售盘里 IMX307 的形态分布是：

| 形态 | 占比 | 备注 |
|---|---|---|
| **MIPI 裸模组** | 高 | 给嵌入式板用（RK/RV1106 等，需厂商驱动 + IQ） |
| **AHD/CVBS 模拟**（车载/安防） | 高 | 需采集卡（§7.2） |
| **IPC 网络** | 中 | 需 SDK，延迟大 |
| **USB UVC（bridge+ISP）** | **低** | 存在但少，¥100–200，需用"识别三问"筛 |

**所以想要"USB 免驱 + 真低照度"的三条现实路径**：

1. **继续找 IMX307 USB 免驱版**（¥100–200）：搜"IMX307 免驱 UVC 1080P 模组"，用 §7 三问 + §4 四项验收；
2. **工业 USB 相机档**（¥200–400）：IMX290/291/307/385 的**原生 UVC 工业相机**（迈德威视/海康机器人等），曝光/增益可编程、参数稳定、文档齐全——这是"低照度 + USB + 可控"最省心的组合，贵但一步到位；
3. **退档 + 补光**：OV2735 档模组（¥80）+ 加**大光圈镜头/IR 补光**，用光学和照明补传感器的账——便宜，代价是观感（红点）与功耗。

**MIPI 唯一的正面理由**：传感器板小又轻（10–20g），云台负载更友好——但排线疲劳（§6.4）与驱动移植（§6.3）两个问题照旧。**若没有 BSP 支持，MIPI 路线一律不碰。**
