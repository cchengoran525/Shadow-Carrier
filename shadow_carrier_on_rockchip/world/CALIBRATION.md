## 1. 触发条件 → 必做动作（四层）

### Tier 1 — 换场地/落地（每次车贴地运行前）｜~2 分钟
**触发**：从桌面搬到地面；换房间；地面不平时。
**做**：
1. 车放平，云台归到工作角（跟随态为 112）
2. **首选：已知距离经验标定（本页 §1b，测距最准）**；辅以 `python3 auto_calib_pose.py sweep <档位...>`（PnP 扫掠拟合 H(tilt)/俯角）
3. 核对：`tilt_true(命令)` 的零点是否与 TILT_LEVEL_CMD 一致；H 值与预期相符
**验收**：经验标定残差 ≤5%（3 点）；PnP 拟合残差 ≤0.5°；零点与 [云台] 声称值差 ≤1 cmd

### Tier 1b — 已知距离经验标定（生产测距精度）｜~5 分钟
**背景**：11cm 机位 + 112 水平视角下棋盘**无法直采**（掠射压缩，`findChessboardCorners` 失败）；PnP 对 H 的外推在 112 上有 ~4cm 偏差（实测 h 148mm vs 外推 110mm，机构摆动非线性）。因此生产角的**测距**用实物距离标定。
**做**：
1. 用**平底实物**（纸箱最佳，bbox 底边=落地点；圆底物如玩偶有接触点歧义）摆 3 个已知距离：**0.6 / 1.0 / 1.4 m**（卷尺量镜头到物底）
2. 各档 `geometry_daemon.py once` 读检测 bbox 底边像素 → `theta = atan((y2-CY)/FY)`
3. 联立解 `(h, tilt)`：使 `atan(h/d_i) - theta_i` 尽量一致 → 写入 `world_lab/fusion/calib_prod.json`
**验收**：回代三点误差 ≤5%（当前实测 ≤2%）
**已知值（10-03 地板）**：h=148mm，tilt(112)=+0.43°，残差 ≤0.12°

### Tier 2 — 机械变动（云台拆装/舵机更换/相机位置移动/换新车）｜~30 分钟
**触发**：动过云台结构、换底盘、改变相机安装点。
**做**：
1. `pan_sweep.py`（[云台]）重定 PAN_FORWARD_CMD
2. `auto_calib_pose.py`（[世界]）重出 H(tilt) 与 tilt_true(cmd)
3. 等距标记法复测 TILT_LEVEL_CMD，与 PnP 零点互证
4. 改 `state/calib/params.py` + 在 EXCHANGE 声明新值
**验收**：桌面校验 `validate_desk.py` 成对距离误差中位 ≤5%

### Tier 3 — 换相机/换镜头/改分辨率｜~1 小时
**触发**：相机模组更换、分辨率/裁剪改变。
**做**：
1. 棋盘重标内参（[云台] 三方互证法：棋盘 + pan_sweep + 真值点）
2. Tier 2 全流程（安装变化几乎必然）
3. **光流桥重录重评**：`of_bridge.py record 25` + `eval`（相机变了，阈值/ROI 全作废）
4. 检查各服务分辨率假设一致（yolo_daemon/video_stream/几何环同为 640×480）
5. 认主线：HSV 模板与体态阈值可能需重采（@认主 评估）
**验收**：PnP RMS ≤3px；光流 drift 归一化 ≤5%；门检测回归 `regression.py` 通过

### Tier 4 — 跨源一致性抽检（demo 前/大改动后）｜~10 分钟
**做**：
1. 已知距离实物（1m/2m）三点验证：PnP 距离 vs [云台] tracker `dist_m` vs 超声波
2. `regression.py` 门检测基准 8 张
3. 极坐标网格 sanity：正前方 1m 的物体应落在 sector0/ring1
**验收**：三源距离差 ≤15%（近环）；基准全绿

## 5. 姿态(pose) offering 判据标定记录（10-04，[世界]）

- **服务**：`fusion/pose_server.cc` v2（`auto` 帧源 = `yolo_frame_a/b.jpg` 取最新；输出派生量 + 诊断特征 `arms[{side,elbow_deg,ext_ratio,wrist_up,valid}]`）
- **判据（现行）**：任一有效臂满足 **2/3** → offering=1：`肘角<125°`｜`前伸量<0.21`｜`腕高>-0.25`（后两者按 bbox 高归一）
- **数据**（仓库 `world/fusion/pose_pn_train.jsonl` / `pose_pn.jsonl` / `pose_pn_bad.jsonl`）：
  | 集合 | 条件 | TPR | FPR |
  |---|---|---|---|
  | 训练轮 111 行 | 正对镜头 | 78% | **0%** |
  | 留出轮 75 行 | 正对镜头 | 43% | **0%** |
  | 合并清洁集 (A=91,B=82) | 排除背对帧 | **67%** | **0%** |
  | 宽松工作点（1/3 union） | 排除背对帧 | 78% | 2% |
- **结论**：**可作为 RECEIVE 的 OR 辅助通道**（零误报 + 1.5s latch 下 2~3 帧 => 有效触发 ~89%），**不适合作唯一触发**；召回随手势幅度波动
- **旧规则已被证伪**：`腕高于肩+15%身高` → TPR **0%**（前伸时透视缩短、腕停在胸口，HRI 10-04 定论）
- 消费/接入由 [HRI] 决定（他们持 fuse 逻辑）；当前默认不接入

### 5b. 为什么 pose offering **验证不过**（根因，Phase C 立项说明｜10-04）

严格说：**"零误报"通过（0/91），"稳定召回"不通过**（训练 78% → 留出 43%）。根因按重要性：

1. **单目 2D 关键点无深度** → "前伸递物"与"屈肘在体侧/抱胸"在投影上同形（透视把手腕压到胸前）→ 单帧几何阈值分不干净，**非调参可解**
2. **视角/遮挡极敏感**：facing 变侧/背时有效关键点从 2.0/帧 掉到 0.58/帧，特征全废（一次实测 facing=back 30/38 帧 → 数据作废）
3. **跨次泛化差**：同一判据两次采集肘角中位 114.8° vs 150° → 召回 78%→43%（拟合到单次动作风格）
4. **无时序建模**：只有单帧几何 + 1.5s latch；真正可分的信号是**腕部轨迹**（前伸位移/胸前停留/收回）
5. **小样本单受试者**：111/75 行、一人一距离一光照；FPR 0/91 的 95% 置信上界 ≈3%
6. **标签无客观真值**："递物"为人为协议，B 段混入"抬手臂非递物"帧，噪声进指标

**要让它可验证需要**（超 demo 预算）：固定机位与距离的统一协议 + 多人多轮采集 + **腕部轨迹时序特征**（或双目/深度）。→ 留 Phase C，本轮不投

## 4. 原则（从踩坑提炼）

- **禁止尺量光心高度**——一律 PnP 反解（08-29 教训：尺量 110 vs 真值 100.3）
- **禁止单姿势大面标定**（08-27 教训：fx=757 退化解）
- **评测基准片必须"人完整入画且持续可见"**（10-03 教训：坏测片让光流结论反转）
- **参数冻结 + 回归验收**：改 `params.py` 必须重跑 `regression.py`
- **喂姿态模型必须用干净原帧（10-04 教训）**：`yolo_frame_a/b.jpg`（video_stream 的 ping-pong 缓冲，无画框）；喂 `yolo_out.jpg`（带检测框）会让关键点被框边缘污染 → 判据**恒真**（实测 16/16 假阳性）。同理任何"从标注帧再推理"的用法都要先剥离标注
- **P/N 对照必须有明确负样本与统一协议（10-04 教训）**：姿态类判据的评测要"正/负各一段、全程正对镜头、距离固定"；一次背对镜头的采集（facing=back 30/38 帧）会让数据失效
- **标定量只能有一个来源（10-03 教训）**：映射函数曾自己在内部用旧常数(112/1.0°)重算俯角，忽略已标定的 tilt，导致 h/tilt 混用 → 距离偏 10%。**规则：映射函数只接受显式标定量（h、tilt_deg），不得内部重算**
- **掠射角下距离精度受限**：生产位（112 水平）视线对地面仅 5~8°，bbox 底边抖 1px ≈ 距离抖 2~3%；单帧距离不可尽信，消费方宜做短时平均（HRI 已按 age/latch 处理）
- **时间戳禁止凭记忆/板钟**（板钟不准），写 EXCHANGE 前跑本地 `date`
